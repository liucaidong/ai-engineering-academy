# M01–M20 学习者视角质量验证协议

> 状态：Pilot protocol / 待真实学习者试测。此文件定义方法，不声称真实试测已完成。

## 1. 唯一目标与范围

验证课程是否能被目标学习者真正学会、实践、完成和评估。验证五项：入门可达性、学习时间真实性、实验难度递进、作业可完成性、Capstone 能力证明。

保留 M01–M20 结构和先修关系；不扩张平台功能，不以代码可运行代替学习成果，不把模拟实验说成真实生产验证。

## 2. 目标学习者与试测样本

沿用课程定位：具备基本计算机使用能力、希望从模型原理走向 AI 应用与系统工程交付的开发者、软件工程师、技术产品人员和跨职能工程团队。课程同时支持独立学习与教师授课。

首轮建议 6–8 人，覆盖：
- A 组：有一般计算机使用能力，但没有系统 AI/ML 工程经验；
- B 组：有软件开发经验，做过 API、数据库或测试，但 LLM/Agent 实战有限；
- C 组：做过 LLM 应用、RAG 或 Agent 项目，尚未系统承担生产工程责任。

这是形成性试测样本，不具统计代表性。缺少某层参与者时，必须明确报告覆盖缺口，不外推结论。

## 3. 入门可达性

使用配套《学习者入门诊断题与补救路径》，建议 45–60 分钟。诊断不是淘汰考试。每个知识领域独立判定：正确率 ≥80% 绿色（直接进入）；50%–79% 黄色（完成桥接练习后进入）；低于 50% 红色（先完成桥接并复测）。阈值是首轮试测假设，需按错因校准。

硬原则：
- M01 无硬性编程先修。
- M02 的线性代数、矩阵乘法、Softmax 和基本概率必须有学习者可见的复习/桥接路径。
- M03 的向量、矩阵、存储单位和消息/API 概念必须有自测与补救路径。
- M04–M20 的专门先修不能只藏在教师指南中。
- 先修不足应导向有边界的补救任务，不得默认要求学习者自行搜索整门外部课程。

### 必须采集的时间类别

## 5. 实验难度与可完成性

对 M01–M20 每份实验工作簿按学习者说明执行，不使用教师参考答案作为操作步骤。记录环境准备、命令、预期/实际输出、失败与恢复方法，并检查是否依赖未声明的 API Key、GPU、付费账户或外部服务。

每项实验标注执行模式：browser-local、simulation、mock、local real service、target environment；同时按 L0 概念验证、L1 局部实现、L2 工程组件、L3 系统设计、L4 综合交付标记。等级由实际任务和证据决定，不按模块编号自动递增。

## 6. 正式作业可完成性

每项抽样作业逐条判定 PASS / PARTIAL / FAIL：
1. 情境、目标和约束清楚；
2. 输入数据、参数、样例或获取方式完整；
3. 术语、版本、单位和假设明确；
4. 交付物格式和最小范围明确；
5. 学习者可获得的环境可完成；
6. 无未声明付费服务、凭证或专用硬件；
7. Rubric 能映射到可观察证据；
8. 评分点总分正确且无矛盾；
9. 合理替代方案可按证据评分；
10. 设计、模拟、本地测试和真实环境边界明确。

FAIL 必须给出 assessment ID、失败证据、学习者影响、修复责任和复测结果，不能只写“太难/太简单”。

## 7. Capstone 验证

至少一位 B 组和一位 C 组参与者完成 M20 Gate 0–4 演练；A 组可在桥接后参与 Gate 0/1。记录立项耗时、ADR 完成情况、垂直切片复现情况、正常/失败/安全拒绝轨迹，以及 Eval、统计分母、威胁模型、SLO、成本、回滚和证据矩阵的可完成性。

沿用现有门槛：总分 ≥75/100、Gate 0–4 全通过、无未关闭 P0、无关键安全硬门槛失败、至少一条端到端路径达到 E3 Local-tested、关键需求有证据且披露未验证项。此为课程建议门槛，不是行业认证。

## 8. 预注册试测阈值

- 可达性：每个关键先修领域至少 80% 参与者能通过直接学习或桥接路径达到进入标准。
- 说明清晰度：至少 80% 参与者无需教师口头补充即可开始实验。
- 实验可复现：核心实验任务成功率 ≥90%；环境阻塞单独统计。
- 作业可完成性：抽样项至少 85% 无 FAIL；关键作业缺少输入或不可执行列 P1。
- 时间偏差：实际 P75 超出估计 50% 以上，或单模块反复超出计划周投入，列 workload P1。
- Capstone：关键 Gate 不得因课程未教过的隐含先修失败；安全硬门槛不可平均补偿。

优先级：P0 会导致错误学习、安全错误或证据造假；P1 阻断核心任务；P2 显著摩擦/重复/评分不一致；P3 低影响措辞和导航问题。

## 9. 执行步骤

具体招募文案、筛选问题和样本分层见 [学习者试测招募工具包](./LEARNER_PILOT_RECRUITMENT_KIT.md)；匿名参与者登记使用 [参与者登记表模板](./LEARNER_PILOT_PARTICIPANT_REGISTER_TEMPLATE.csv)；观察员操作、抽样安排和退出条件见 [学习者试测执行手册](./LEARNER_PILOT_RUNBOOK.md)；逐项 Lesson/Assessment 分配见 [试测任务矩阵](./LEARNER_PILOT_TASK_MATRIX.md)。参与前使用 [知情同意模板](./LEARNER_PILOT_CONSENT.md)，由组织者补齐数据处理主体、联系人和保存期限。

1. 招募并记录 6–8 位参与者的经验画像与知情同意。
2. 完成入门诊断，记录答题时间、求助和误解。
3. 每位参与者完成 M01、M02、M03 的核心学习任务；每个模块至少观察一个代表性讲次和一项正式作业，并明确记录未覆盖内容。
4. 按 [学习者试测执行手册](./LEARNER_PILOT_RUNBOOK.md) 分层抽样 M04–M19；首轮未覆盖模块必须标记为未测，不得外推。
5. 至少两位参与者完成 M20 Gate 0–4 演练。
6. 每次任务后填写时间日志和摩擦记录；提示必须记录。
7. 对问题做证据复核、分级和最小整改；由未参与修复的学习者复测。
8. 发布试测报告，分别报告样本量、经验分层、任务覆盖、完成率、时间分布、求助次数、阻塞原因和局限。

## 10. 伦理与数据治理

参与者知情同意后才收集记录，使用匿名 ID；不收集无关个人信息、真实客户数据、秘密、API Key 或商业机密。参与者可退出。首轮试测分数不用于就业或资格认证。原始记录应设置访问权限和保留期限；公开报告只发布聚合数据和经授权的匿名引述。

## 11. 完成定义

本协议、诊断题、时间日志和作业审查模板完成，不等于真实学习者试测完成。取得参与者数据前，状态仍是“内部候选冻结，等待外部学习者验证”。
