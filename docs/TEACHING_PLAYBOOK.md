# AI Engineering Academy 教师教学实施手册

> 课程内容版本：0.26.0。适用范围：M01–M20 旗舰课程。本手册定义教学组织建议，不改变课程 Schema、正式作业或 Rubric。

## 1. 课程结构与工作量

课程按六个层级组织，共 20 个模块、100 讲、100 项正式评分作业和 8 个教学实验。课程源文件中各讲 estimatedMinutes 合计为 **7,650 分钟，即 127.5 小时**；这是讲授/学习内容估计时间，不包含作业研究、报告撰写、答疑和 Capstone 独立开发时间。

| 层级 | 模块 | 能力目标 |
|---|---|---|
| L1 基础认知 | M01 | AI 系统概念、学习机制、能力边界与系统设计 |
| L2 模型原理 | M02–M05 | Transformer、Token/Context、训练、推理和部署 |
| L3 应用工程 | M06–M09 | Prompt、结构化输出、工具、RAG 和多模态应用 |
| L4 Agent 工程 | M10–M16 | Runtime、Planning/Memory、MCP、Skills、多 Agent、安全与 Workflow |
| L5 平台工程 | M17–M19 | 评测观测、AI 平台、产品工程化和交付 |
| L6 综合实践 | M20 | 端到端系统方案、实现切片、验收证据和技术答辩 |

## 2. 推荐 24 周教学节奏

| 周次 | 模块 | 阶段交付 |
|---|---|---|
| 1–3 | M01–M03 | 概念地图、Attention 推导、Token/Context 审计 |
| 4–19 | M04–M19 | 每周一个模块；完成五讲学习和五项正式作业 |
| 20 | M20 立项与需求 | 项目章程、范围、非目标、验收指标 |
| 21 | M20 架构与决策 | 架构图、数据流、威胁模型、ADR |
| 22 | M20 垂直切片 | 一条端到端用户旅程和可复核轨迹 |
| 23 | M20 验收与部署 | Benchmark、安全测试、SLO、成本与回滚方案 |
| 24 | M20 答辩与复盘 | 可复现演示、技术答辩、未验证事项和复盘 |

每个普通模块建议按五次学习单元组织：每次完成一讲、课堂练习和课后复盘；模块末集中检查五项正式作业。对先修依赖较强的 M02、M03、M04、M05、M08、M10、M15 和 M17 可延长，不应为赶进度跳过推导和安全边界。

**重要：24 周是教学排程建议，不是已经由学习者试测验证的工时承诺。** 课程源文件的 7,650 分钟（127.5 小时）只统计 100 讲 estimatedMinutes，不含 100 项正式作业的独立完成时间、实验调试、复习和 Capstone 额外开发。正式开课前应使用 [学习者质量验证协议](./LEARNER_VALIDATION_PROTOCOL.md) 和 [学习时间记录模板](./LEARNER_TIME_LOG_TEMPLATE.csv) 采集主动学习与阻塞时间；根据实际 P50/P75/P90、逾期率和求助频率校准每周负荷，不得把估算写成承诺。

## 3. 单讲教学模板

按课程估计时长弹性调整，建议保留以下闭环：

1. **问题引入（约 10%）**：真实工程问题、失败案例或可观察现象。
2. **概念与术语（约 20%）**：定义、边界、输入输出和关键假设。
3. **机制推导（约 25%）**：手算公式、张量形状、状态转移、协议消息或成本预算。
4. **工程实践（约 25%）**：使用已有 Lab、案例或设计任务复现机制。
5. **评测与反思（约 20%）**：分析失败、替代方案、风险、可观测信号和验收条件。

每讲至少留下一个可复核学习产物：计算记录、架构图、状态图、数据流、威胁清单、实验表或决策记录。仅有课堂讨论或术语记忆不视为完整学习证据。

## 4. 八个实验的教学定位

| Lab | 对应模块 | 执行模式 | 可验证内容 | 不代表什么 |
|---|---|---|---|---|
| Tokenizer Lab | M03 | browser-local | 玩具 BPE 合并过程 | 不代表厂商真实 tokenizer 或 API token 计量 |
| Transformer Attention Lab | M02 | browser-local | 固定矩阵、Mask、权重和输出 | 不代表真实模型权重、GPU 内核或性能 |
| RAG Pipeline Lab | M08 | simulation | 内置语料、教学向量、Top-K 与重排 | 不代表生产 embedding、真实向量库或线上召回 |
| Tool Calling Lab | M07 | simulation | Schema、参数校验、Runtime 策略与只读工具 | 不代表真实外部工具调用 |
| Agent Runtime Lab | M10 | simulation | 状态机、审批、执行轨迹与终止条件 | 不代表真实 LLM Agent 或隔离沙箱 |
| MCP Protocol Lab | M12 | simulation | 本地能力目录和协议角色概念 | 不建立网络 JSON-RPC 连接或真实 MCP Server |
| Multi-Agent Lab | M14 | simulation | 确定性角色分工与综合 | 不代表并发模型调用或多模型协作质量 |
| Evaluation Lab | M17 | simulation | 固定数据集 Exact Match 和失败案例 | 不代表 LLM Judge 或真实模型质量 |

教师必须在实验前说明执行模式，实验后要求学生写明“本实验验证了什么/没有验证什么”。

## 5. 正式作业与评分政策

- 每个模块有 5 项正式作业，每项 Rubric 总分 10 分；全课程共 100 项作业、1,000 个 Rubric 分值。
- 模块成绩可按 5 项作业原始分合计（满分 50）呈现。课程未在代码中规定统一及格线或证书标准，授课机构不得将建议阈值描述为产品内置规则。
- 按原始 Rubric 逐项评分。教师可接受等价解法，但不得悄悄更改正式评分项和权重。
- 数值题检查公式、代入、单位、舍入和数量级；设计题检查需求、责任边界、风险、失败路径和验证证据。
- 高风险工程设计必须将模型建议和服务端授权/业务执行分开；让模型自行批准支付、退款、越权读取或删除数据属于关键设计缺陷。
- 反馈包含达到的标准、缺失证据、错误原因和下一步可执行修改。

## 6. 学习成果与能力门槛

- **L1**：准确解释 AI/ML/DL/LLM，区分参数知识、上下文和外部证据，绘制 AI 系统边界图。
- **L2**：推导 Attention、Tokenizer/Embedding、训练目标和 KV Cache，完成容量/计算预算。
- **L3**：设计 Prompt 契约、结构化输出校验、工具调用、RAG 证据链和多模态评测。
- **L4**：设计受控 Agent Runtime、状态恢复、MCP/Skill 契约、多 Agent 协调、最小权限和 Workflow。
- **L5**：建立评测数据集、Trace/Metric、质量 SLO、模型路由、配额、成本和产品发布治理。
- **L6**：把需求映射到架构、实现、测试和运维证据，并解释残余风险。

## 7. Capstone 评审框架

Capstone 使用课程内五项正式作业和对应 Rubric。建议证据包包括：项目章程；Context/Container/Component 架构图、数据流和 ADR；代码版本与模型/Prompt/索引/工具契约版本；正常、失败、无证据、注入、越权、超时、重复请求和租户隔离测试；SLO、告警、回滚、数据删除和责任人；固定版本/输入的可复现演示及技术答辩。

必须区分 implemented、reviewed、simulated、tested、not tested 和 blocked。Mock 测试不能写成真实 provider 集成通过；静态审阅不能写成运行验收通过。

## 8. 学术诚信与 AI 辅助工具

建议采用透明披露：允许 AI 辅助解释、备选方案、代码审阅和表达，但学习者必须能解释最终提交内容；AI 生成的代码、数据、引用和技术结论须自行验证；报告披露使用工具/模型、用途、人工修改和验证方式；不得上传未获授权的个人数据、商业机密或凭证；不得伪造测试日志、引用或实验结果。
