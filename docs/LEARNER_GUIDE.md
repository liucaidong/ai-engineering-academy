# AI Engineering Academy 学习者手册

## 1. 这门课程如何学习

AI Engineering Academy 是从模型原理到工程系统交付的学习路径。建议按 M01→M20 顺序学习，因为先修关系反映概念和工程能力依赖。

课程共 20 个模块、100 讲、100 项正式作业。课程原始讲次估计时间合计约 127.5 小时；作业、实验、项目和复习需要额外时间。建议按 24 周节奏学习，M20 留出五周完成综合项目。

## 2. 学习路线

| 阶段 | 模块 | 你应获得的能力 |
|---|---|---|
| 基础认知 | M01 | 理解 AI 系统、机器学习、LLM 和能力边界 |
| 模型原理 | M02–M05 | 理解 Attention、Token/Context、训练、推理和部署 |
| 应用工程 | M06–M09 | 构建 Prompt、结构化输出、Tool Calling、RAG、多模态流程 |
| Agent 工程 | M10–M16 | 设计 Agent Runtime、Planning/Memory、MCP、Skills、多 Agent、安全和 Workflow |
| 平台与产品 | M17–M19 | 评测、观测、平台架构、产品交付和持续运营 |
| 综合项目 | M20 | 交付可评审、可复现且明确验证边界的 AI 工程项目 |

## 3. 每讲的学习闭环

1. **预习**：阅读学习目标、摘要和术语，写下不理解的问题。
2. **理解**：阅读章节内容，标记定义、假设、公式和边界。
3. **复现**：手算公式、画数据流/状态图，或运行对应教学 Lab。
4. **迁移**：将概念应用到不同案例，至少构造一个失败场景。
5. **提交**：完成本讲正式作业，按 Rubric 自查证据。
6. **复盘**：记录错误、修正和仍未验证的假设。

只看完页面不等于掌握。能从空白文档重建关键机制，并解释失败路径，才是可迁移能力。

## 4. 正式作业怎么做

每个模块有五项正式评分作业，每项满分 10 分。提交前检查：是否回答原题全部要求；是否提供公式、输入、假设、单位和中间计算；架构图是否标出信任边界、权限、数据来源和失败处理；评测是否定义样本、分母、指标、阈值和版本；是否区分设计、模拟、真实测试和生产验证；是否说明替代方案、成本、限制和未验证项。

教师指南提供参考解答和评分说明。它们是学习对照，不是可以复制后当作个人实验结果的模板。

## 5. 教学实验能做什么

课程提供八个教学实验：Tokenizer、Transformer、RAG、Tool Calling、Agent Runtime、MCP、Multi-Agent 和 Evaluation。执行模式由课程 Lab Registry 定义：browser-local 在浏览器内进行确定性计算；simulation 使用固定数据和教学逻辑模拟系统行为。

这些实验不代表真实模型推理、生产向量数据库、真实 MCP Server、并发 Agent 服务、LLM Judge 或 GPU 性能基准。实验报告必须写明实际执行模式和验证边界。

## 6. 如何使用参考资料

优先阅读原始论文、标准、官方 API 文档和项目维护者文档。记录标题、作者/发布机构、版本或发布日期、访问日期和支持的具体论点；区分论文研究结论、官方实现行为和个人推断；不把搜索摘要或模型生成文献条目当作已核验来源；遇到失效链接或版本迁移，记录问题并寻找官方替代来源。

## 7. M20 Capstone 应如何准备

不要等到 M20 才开始积累项目证据。从 M01 起保留设计图、计算表、测试记录和失败案例。Capstone 最终需要把需求映射到架构、实现、测试和运维证据。

建议项目至少包含：明确用户任务、一条端到端垂直切片、可信身份/权限边界、可复现测试集、正常与失败轨迹、成本和延迟预算、审计记录、回滚方案以及未验证事项清单。

## 8. 常见学习误区

- 模型回答得很好，不等于系统可靠；语言质量不能替代事实、权限和业务状态验证。
- RAG 接入不等于答案有依据；必须检查召回、ACL、来源、版本、引用支持和过期内容。
- Tool Call 出现在输出里，不等于操作已经执行；模型提出请求，宿主校验授权后才可能执行。
- Agent 越自主不一定越好；自主性必须受预算、权限、终止条件和人工接管约束。
- 测试通过不代表生产可用；测试范围、环境、版本和外部依赖决定证据强度。
- 上下文窗口越大不等于记忆越好；可输入长度不等于有效利用能力或长期记忆。
