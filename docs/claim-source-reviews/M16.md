# M16 Claim-to-Source Review — Durable Workflows, Events and Reliability

> Review date: 2026-11-10  
> Scope: 21 lesson-level source occurrences, 19 unique URLs, five lessons.  
> Result: 21/21 source occurrences matched to the claims they support; CloudEvents, Temporal versioning, retry and OpenTelemetry maturity details were reconciled.

## Key findings and qualifications

1. **Workflow vs Agent:** LangGraph and Anthropic patterns distinguish deterministic orchestration from dynamic agent decisions. Workflow engines coordinate state, retries, timers and recovery; the Agent proposes or performs bounded work but does not replace the control plane.
2. **Temporal determinism:** Workflow code must be replay-safe; nondeterministic APIs and external I/O belong in Activities. Temporal replays recorded Event History and completed Activity results, but Activities can retry and external side effects may execute more than once. Use idempotency keys and query/reconciliation for unknown outcomes.
3. **Temporal deployment versioning:** Temporal Worker Versioning provides Pinned and Auto-Upgrade behavior using Worker Deployment Versions; patching is another compatibility mechanism. Exact APIs and semantics depend on SDK/deployment mode. Auto-Upgrade does not remove the need for replay-safe code.
4. **Azure Durable Task:** Orchestrators replay from history and require deterministic code; use orchestration context for time/random APIs and Activities for I/O. Do not assume Azure and Temporal version/retry APIs are interchangeable.
5. **Saga:** A Saga is a sequence of local transactions with compensating business actions. Compensation is not an ACID rollback and can fail; design semantic locks, retry, idempotency and observability.
6. **Transactional Outbox:** Business state and outbox row must be committed in the same database transaction; relay delivery is typically at least once, so consumers need durable Inbox/unique-key deduplication. The example uses a process-local lock only to demonstrate the atomic boundary, not a database transaction.
7. **CloudEvents:** The pinned spec document is v1.0.2, but the event context attribute `specversion` remains the string `"1.0"`. Required context attributes are `specversion`, `id`, `source`, `type`; aggregate ID/version and schema version are application fields. CloudEvents does not itself guarantee broker delivery or transactional publication.
8. **Retry:** Full Jitter is modeled as `Uniform(0, min(cap, base × factor^attempt))`. Step Functions has AWS-specific Retry/Catch parameters including JitterStrategy FULL. Always bound attempts by a global deadline and retry budget; retry only safe/idempotent operations.
9. **Circuit breaker:** Resilience4j supports sliding windows, minimum call counts, half-open permitted calls and multiple decorators. The teaching code is only a consecutive-failure threshold with a single half-open probe; it is not a Resilience4j implementation.
10. **Approval durability:** Approval event is HMAC-signed by a trusted demo signer and binds request/event ID, authenticated approver, action digest, policy version, expiry, trace and nonce. The nonce store is process-local; production requires a durable shared uniqueness constraint, trusted identity service, KMS/secret rotation, trusted time and cross-language canonicalization (e.g. RFC 8785).
11. **OpenTelemetry:** General tracing/context propagation docs are stable concepts, but Messaging spans semantic conventions are currently Development. Pin the convention/instrumentation version and plan migration.
12. **NIST controls:** SP 800-53 Release 5.2.0 was announced 2025-08-27; selected controls/discussion were updated but SP 800-53B control baselines were not changed. The release announcement is not the control catalog itself; CPRT is the catalog.
13. **Teaching code limits:** Agent proposals and workflow state are in-memory; Outbox/Inbox is process-local; Full Jitter uses a seeded RNG for reproducible tests; the breaker is simplified; approval HMAC assumes authenticated signer; replay checks compare simplified command strings, not real Temporal/Azure SDK histories.
