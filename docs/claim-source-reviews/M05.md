## 1. Prefill, Decode and KV cache

| Source | Claim supported | Qualification |
|---|---|---|
| [Efficiently Scaling Transformer Inference](https://arxiv.org/abs/2211.05102) | Analyzes latency/long-context inference and MQA's reduction of KV memory/bandwidth in large-scale TPU inference. | Performance figures are specific to the reported model, hardware and partitioning. |
| [Fast Transformer Decoding](https://arxiv.org/abs/1911.02150) | MQA shares one K/V head across query heads to reduce memory bandwidth during incremental decoding. | The paper reports minor quality degradation in its experiments. |
| [GQA](https://arxiv.org/abs/2305.13245) | GQA uses an intermediate number of KV heads between MQA and MHA and can approach MHA quality with MQA-like speed in evaluated settings. | Quality and uptraining results are model/training dependent. |
| [PagedAttention](https://arxiv.org/abs/2309.06180) | Block-based KV management reduces fragmentation and redundant duplication and enables cache sharing; vLLM is built on it. | Near-zero waste and 2–4× throughput are paper-specific evaluation results, not universal guarantees. |

**Formula check:** (M_{KV}=2LBT H_{KV}d_h b) is dimensionally correct. The 32-layer / 32-KV-head / 8192-token / BF16 example equals 4 GiB; the 32-layer / 8-KV-head / 16384-token example equals 2 GiB. Batch-4 unshared capacity is 8 GiB. The lesson correctly distinguishes query heads from KV heads and excludes alignment, metadata, activations and fragmentation from the theoretical payload.

## 3. Continuous batching, chunked prefill and scheduling

| Source | Claim supported | Qualification |
|---|---|---|

The publisher landing page is crawler-restricted, but the official indexed abstract and PDF corroborate the source. |

**Queueing check:** the illustrative M/M/1 expressions (W=1/(\mu-\lambda)) and (W_q=\lambda/[\mu(\mu-\lambda)]) are correct for λ < μ. The numerical examples (20/15 req/s and 20/19 req/s) are correct. The lesson explicitly says real LLM serving is not an M/M/1 system, which is the required qualification.

## 4. Speculative decoding and quantization

| Source | Claim supported | Qualification |
|---|---|---|
| [Speculative Decoding](https://arxiv.org/abs/2211.17192) | Draft-and-verify decoding can accelerate autoregressive generation without changing the target distribution through a correction sampling method. | 2–3× T5-XXL result is setup-specific; speed depends on draft acceptance and hardware. |
| [GPTQ](https://arxiv.org/abs/2210.17323) | One-shot post-training weight quantization using approximate second-order information, including 3/4-bit cases. | Quality/speed depends on bit width, kernels, model and hardware. |
| [SmoothQuant](https://arxiv.org/abs/2211.10438) | Equivalent transformation migrates activation outlier difficulty into weights to enable W8A8 quantization. | Reported speed/memory gains are evaluation-specific. |
| [AWQ](https://arxiv.org/abs/2306.00978) | Activation-aware weight-only quantization uses activation statistics to identify salient channels and reduce quantization error. | Kernel and hardware support determine real performance. |

**Storage arithmetic check:** 13B parameters at 16/8/4 nominal bits correspond to 26/13/6.5 decimal GB of raw weight payload. This excludes scales, zero-points, group metadata, alignment, runtime buffers and KV cache; the workbook/lesson labels this as theoretical payload, not deployment memory.
