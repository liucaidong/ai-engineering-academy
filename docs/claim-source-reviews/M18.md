## Key findings and qualifications

1. **Control plane and data plane:** Control-plane desired state, versioned policy/config snapshots and data-plane enforcement should have separate failure domains. The example now HMAC-signs the full snapshot, binds key ID/schema/version/expiry and rejects stale or expired state. HMAC is symmetric and Python JSON serialization is not cross-language JCS; production should use KMS/HSM-backed signing, key rotation, schema validation, canary, atomic rollout and rollback.
2. **Model gateway:** LiteLLM routing/reliability is an implementation reference, not a guarantee that all providers share the same capabilities. Fallback must check tenant provider allowlist, model capability, region/data policy, health, context limit, output schema, budget and quality. Provider adapters should preserve raw provider usage/errors and normalize only a versioned internal contract.
3. **Provider usage differences:** OpenAI Responses and Anthropic Messages expose provider-native request/response and usage fields. Cache tokens, tool calls, refusal and multimodal payloads are not interchangeable. Do not collapse provider-native usage into one assumed field mapping or price estimate.
4. **Rate limiting:** Envoy Gateway distinguishes local proxy-instance limits from global limits coordinated through an external Rate Limit Service. Local limits are not fleet-wide quotas. Stripe publishes API-specific global, endpoint and concurrency limits; do not generalize them as one universal token-bucket setting.
5. **Metering:** OpenMeter usage events use CloudEvents-compatible source/id identity and subject-based aggregation. The code validates tenant/request/provider/model/usage/price-version/currency/time fields and detects same-key/different-payload conflicts. Its currency field validation only checks a three-letter uppercase token; it does not implement the ISO 4217 registry. Currency minor-unit exponent must be supplied from a versioned registry at settlement time. The ledger is process-local; production requires durable unique `(source,id)` constraints, transaction/outbox integration, correction events and provider invoice reconciliation.
6. **Billing precision:** Costs use Decimal and versioned price cards; float inputs are rejected. The example quantizes using a caller-supplied currency minor-unit exponent and explicit ROUND_HALF_UP policy. Production must bind provider/model/region/currency/price version/effective time and obtain the exponent from a versioned ISO 4217 registry (e.g. not all currencies use two decimal places). Estimated token usage must remain distinct from provider-reported usage and invoices.
7. **Tenant isolation:** Tenant context must come from verified identity claims, not client headers. Same-tenant membership is not blanket object authorization; enforce owner/authorized-principal/action ACLs. Private cache keys include tenant, principal, resource version and policy version; each component is percent-encoded to prevent delimiter collisions. Tenant-shared cache scope is allowed only for explicitly tenant-visible resources.
8. **Kubernetes isolation:** Kubernetes namespaces provide useful tenancy and policy boundaries but are not, by themselves, strong security isolation. Combine RBAC, NetworkPolicy, Pod Security, admission controls and quotas; use separate clusters/control planes or dedicated data services for higher-risk tenants. Silo/Pool/Bridge are deployment patterns, not an automatic security ranking.
9. **Key management:** NIST SP 800-57 Part 1 Rev.5 remains the published final baseline. Rev.6 was an Initial Public Draft in December 2025 with comments due February 2026; as of 2026-11-10 no final Rev.6 publication was located. Do not cite the IPD as an effective final standard.
10. **Zero Trust and policy:** NIST SP 800-207 describes PE/PA/PEP logical components. OPA/Rego provides policy-as-code evaluation but is not an identity provider; verified principal/resource context and enforcement at PEPs remain necessary.
11. **Reliability and capacity:** Google SRE overload guidance supports bounded queues, admission control, load shedding and bounded retries. The code’s weighted round-robin is a small scheduler, not WFQ/DRR; N+1 capacity must be calculated after losing one node/failure domain and preserving reserve.
12. **Teaching code limits:** Provider routes are static; no real gateway or distributed rate limiter is invoked. HMAC keyring, usage ledger, tenant claims and scheduler are in-memory examples. The code does not validate JWTs, perform KMS signing, execute database RLS, reconcile provider invoices or replace load/fault testing.
