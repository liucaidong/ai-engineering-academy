| Source | Claim supported | Qualification |
|---|---|---|

| [OpenTelemetry documentation](https://opentelemetry.io/docs/) | Provides traces, metrics, logs and instrumentation concepts for correlating runtime events. | Metrics should use low-cardinality dimensions; redact secrets and user content from traces/logs. |
| [τ-bench](https://arxiv.org/abs/2406.12045) | Pass^k measures the probability of all k repeated trials succeeding and highlights consistency failures that a single-run success rate hides. | The simple (p^k) expression assumes independent, identically distributed trials with constant success probability; real agent runs may be correlated. |

## 6. Formula and implementation checks

- **Pass^k:** if a single run succeeds with probability p and trials are independent with identical p, the probability all k runs succeed is (p^k). The lesson states the IID assumption and warns that real runs may be correlated.
- **Execution lifecycle:** the lesson correctly separates `replay` from `retry`. Workflow replay rebuilds state from history; Activity retries can repeat external I/O, so Activities should be idempotent or reconciled before retry.
- **Persistence scopes:** LangGraph checkpointer is thread-scoped graph state; store is cross-thread application data. They must not share an implicit authorization/retention policy.
- **Observability maturity:** OpenTelemetry GenAI conventions remain Development. Core semantic-conventions v1.42.0 deprecated and moved the former `gen_ai.*` definitions; the lesson warns against treating them as a stable schema contract.
- **Agent completion:** outcome must be validated from environment state/postconditions, not from model text. The stop conditions include success, clarification, permission denial, budget exhaustion, unrecoverable failure and human takeover.

## 7. Review conclusion

All 20 M10 source occurrences match their scoped claims. Corrections are maturity/version qualifications rather than architectural reversals: AgentBench v3 metadata, Temporal deterministic replay vs Activity retries, LangGraph checkpointer vs store, and OpenTelemetry GenAI conventions at Development maturity. The module's autonomy envelope, action authorization, postcondition verification, retry reconciliation and budget-based stop rules are consistent with the cited research and runtime documentation.
