## 1. Planning methods and formal planning

| Source | Claim supported | Qualification |
|---|---|---|
| [Tree of Thoughts](https://arxiv.org/abs/2305.10601) | Explores multiple coherent intermediate paths, self-evaluates candidates, looks ahead and backtracks; tested on Game of 24, creative writing and mini crosswords. | Current arXiv v2 (2023-12-03); gains are specific to three tasks, not a guarantee for arbitrary planning problems. |
| [LLMCompiler](https://arxiv.org/abs/2312.04511) | Converts tool calls into a dependency-aware DAG and parallelizes independent tasks using planner, task fetching and executor components. | Performance gains are specific to paper benchmarks/baselines; the same source is also used in M07/M10. |
| [Plan-and-Solve Prompting](https://arxiv.org/abs/2305.04091) | Two-stage zero-shot prompting: devise a plan that decomposes a task into subtasks, then solve according to the plan; PS+ adds more detailed instructions. | Current arXiv v3 (2023-05-26); a prompting method, not a formal optimal planner. |
| [LLM+P](https://arxiv.org/abs/2304.11477) | Translates natural-language planning problems to PDDL, invokes a classical planner and translates the resulting plan back to natural language. | Planner correctness/optimality assumes the translated PDDL model is accurate; language-to-PDDL errors invalidate the world model. |

## 2. Memory architecture and lifecycle

| Source | Claim supported | Qualification |
|---|---|---|
| [Generative Agents](https://arxiv.org/abs/2304.03442) | Combines a memory stream, reflection synthesis and retrieval-based planning for persistent simulated agents. | Demonstrated in a controlled sandbox with 25 agents; simulation believability is not factual or production-grade memory. |
| [MemGPT](https://arxiv.org/abs/2310.08560) | Proposes virtual context management with tiered memory and data movement between model context and external memory for long documents and multi-session chat. | Current arXiv v2 (2024-02-12); context paging is not infinite or lossless memory. |
| [Mem0](https://arxiv.org/abs/2504.19413) | Proposes dynamic extraction, consolidation and retrieval of salient conversation facts, with an optional graph-memory variant; evaluates on LoCoMo. | The paper is authored by the Mem0 team. The reported 26% judge improvement, 91% p95 latency reduction and >90% token savings are author-reported benchmark results, not independent third-party replication. |
| [Lost in the Middle](https://arxiv.org/abs/2307.03172) | Shows that evidence position within long contexts affects how reliably models use it, with middle-position degradation in evaluated settings. | Position effects depend on model/task/context; measure them rather than assume a universal constant. |
| [Ragas](https://arxiv.org/abs/2309.15217) | Provides automated RAG evaluation dimensions such as retrieval relevance, faithfulness to retrieved context and answer quality. | Not a dedicated long-term memory benchmark; automated judge scores need human/domain calibration. |

| Source | Claim supported | Qualification |
|---|---|---|
| [AgentBench](https://arxiv.org/abs/2308.03688) | Evaluates LLM agents across eight interactive environments and studies reasoning, decision-making and instruction-following failures. | Current arXiv v3 revised 2025-10-04; results are environment/model-specific. |

## 5. Cross-claim correctness checks

- **Prompting vs planning:** Plan-and-Solve is a prompting strategy; Tree of Thoughts is search over candidate reasoning paths; LLM+P is the cited approach that translates to PDDL and invokes a classical planner. They are not interchangeable.
- **Formal planner boundary:** a classical planner can return a valid/optimal plan only relative to its supplied action schemas, initial state, goal and constraints. An LLM translation error can produce a formally valid plan for the wrong world model.
- **Memory taxonomy:** the lesson's context/state/memory/knowledge-base separation and proposed memory object fields are course design guidance, not a claim that one cited paper defines a universal schema.
- **Evidence levels:** user-stated facts, tool-verified facts and model inferences remain distinct. Repeated summaries of the same source event are not independent evidence.
- **Temporal validity:** `valid_from/valid_until` describe when a fact applies; `recorded_at` describes when the system learned it. Expiration, supersession and deletion must propagate to summaries, embeddings, caches and derived memories.
- **NIST status:** AI RMF 1.0 is the published framework. The NIST page says it is under revision; the April 2026 critical-infrastructure profile is a concept note, not a replacement final framework.
- **Benchmark comparability:** LongMemEval and LoCoMo test different memory capabilities/distributions; AgentBench and τ-bench evaluate broader agent/tool behaviors. Scores should not be merged into one undifferentiated “memory quality” metric.
- **Mem0 evidence:** its paper's relative accuracy/latency/token results are author-reported; replicate with the same task distribution, baseline, model, judge, retrieval configuration and cost accounting before drawing production conclusions.

## 6. Review conclusion

All 20 M11 source occurrences match the scoped claims in the traceability register. The main corrections are version/evidence qualifications: NIST AI RMF 1.0 is being revised; LongMemEval v2 and LoCoMo dataset properties are explicit; Mem0 vendor-reported performance claims are not treated as independent evidence; and prompting methods are separated from formal PDDL planning. The module's approval binding, memory provenance, temporal validity, deletion propagation and recovery rules are consistent with the cited material and are presented as engineering controls rather than paper-specific guarantees.
