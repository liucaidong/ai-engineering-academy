## 6. Cross-claim correctness checks

- **Identifier separation:** provider `call_id`, host `request_id`, MCP/JSON-RPC request `id`, and business `idempotency_key` are different identifiers with different scopes. JSON-RPC `id` must not be reused as a business deduplication key.
- **MCP metadata:** 2026-07-28 MCP requests include required `_meta` metadata. Abbreviated spec examples must not be copied as complete production requests.
- **Strict schema:** schema validity is not semantic validity, resource ownership, authorization or user approval. Server-side checks remain mandatory.
- **Idempotency:** the lesson's same-key/same-parameters and same-key/different-parameters behavior is a recommended application design; Stripe v1/v2 show why provider retention/replay details must be checked per version.
- **Outbox/Saga:** outbox relay is at-least-once in practice and consumers must be idempotent; saga compensation is a business action, not time reversal or automatic ACID rollback.
- **ToolBench metadata:** arXiv:2307.16789 is currently titled ToolLLM; ToolBench is the dataset and ToolEval is the evaluator. The source title was corrected.

## 7. Review conclusion

All 20 M07 source occurrences match their scoped lesson notes. Corrections in this tranche were documentation canonicalization, ToolLLM citation metadata, and precision around MCP `_meta`, JSON-RPC correlation IDs, Stripe API version semantics and duplicate outbox delivery. No claim that a model-generated tool call is already executed, that schema validity implies authorization, or that a timeout proves failure is made.
