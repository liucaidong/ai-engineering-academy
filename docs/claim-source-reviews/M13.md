# M13 Claim-to-Source Review — Agent Skills and Reusable Capabilities

> Review date: 2026-11-10  
> Scope: 20 lesson-level source occurrences, 14 unique URLs, five lessons.  
> Result: 20/20 source occurrences matched to the specific claims they are used to support. This is a scoped claim/source review, not a certification of third-party software or target Runtime behavior.

## Key technical findings and qualifications

1. **Format vs Runtime:** Agent Skills is an open package format built around a directory containing `SKILL.md`; optional `scripts/`, `references/` and `assets/` are conventions. The format does not standardize every Host’s invocation, tool integration, sandbox, permission or scheduling semantics.
2. **Frontmatter:** `name` and `description` are required; `license`, `compatibility` and string-to-string `metadata` are optional. `allowed-tools` is experimental. `version`, `tags`, `skill_id`, `input_schema` and `required_scopes` are not standard top-level fields; enterprise registries may define their own schema.
3. **Name/description constraints:** name is 1–64 characters, lowercase alphanumeric plus hyphens, no leading/trailing/consecutive hyphens, and must match the parent directory. description is 1–1024 characters and should state what the Skill does and when to use it. compatibility is 1–500 characters.
4. **Progressive disclosure:** discovery loads name/description; activation loads SKILL.md; resources are loaded as needed. The specification recommends keeping SKILL.md under 500 lines and the instructions under roughly 5,000 tokens; these are recommendations, not hard format limits.
5. **Runtime-specific extensions:** Claude Code has product-specific frontmatter such as `disable-model-invocation`, `user-invocable`, `context` and `argument-hint`. Its `allowed-tools` is a per-invocation pre-approval that does not remove other tools or replace baseline permission policy. Do not generalize this behavior to all Skill Hosts.
6. **skills-ref scope:** the official README explicitly says the reference library is for demonstration only and not for production. It exposes `validate`, `read-properties` and `to-prompt`; it is not a production security scanner or a task-effectiveness test.
7. **Composition/versioning:** LangGraph documents workflow/agent orchestration concepts; Agent Skills itself does not define a cross-Skill DAG or dependency manifest. SemVer is an optional organizational versioning policy, not a required Skill field.
8. **Tool/runtime comparison:** OpenAI Agents SDK documents Agent/Runner, tools, guardrails, handoffs, sessions, tracing and MCP integration; Anthropic advanced tool use documents Tool Search, Programmatic Tool Calling and Tool Use Examples. These are complementary runtime/tool mechanisms, not Agent Skills package-format features.
9. **Supply-chain controls:** SLSA v1.2 is the current Approved specification; v1.0 is Retired. Build/Source provenance improves traceability of artifacts and source, but does not prove a Skill’s instructions are benign, its code is vulnerability-free or its runtime permissions are safe.
10. **Security frameworks:** OWASP GenAI LLM Top 10 2026 and Agentic Applications Top 10 2026 are risk taxonomies/frameworks, not Agent Skills format specifications or product certifications. NIST SP 800-218 v1.1 and SP 800-218A are final SSDF guidance/profile documents; SP 800-218 Rev. 1 (v1.2) was published as a draft on 2025-12-17 and is not final. Applying these documents does not certify a Skill package.
11. **Evaluation metrics:** binary trigger FPR = FP/(FP+TN); false-trigger share = FP/all cases. Multi-Skill wrong-skill rate, activation miss rate and false-activation rate require a labeled routing dataset and distinct denominators. Task success is separate from trigger correctness.
12. **Teaching code limitations:** the metadata example accepts a Python dictionary and does not parse YAML; token estimation is bytes/4 rather than a tokenizer; DAG validation does not check schema compatibility; file hashing is not SBOM/signature/provenance; the path demo is not race-safe under concurrent filesystem mutation; the evaluation data is synthetic.
