# 产品需求与学习目标

## 1. 产品愿景
建设面向 AI 工程学习者的系统化学习平台，将概念讲解、可操作实验、工程任务和能力评估串成闭环。核心产物不是课程页面数量，而是学习者能够解释系统行为、实现关键组件、识别风险并完成可运行工程项目。

## 2. 目标用户
- 入门学习者：建立 AI、机器学习和大模型的正确心智模型。
- 应用开发者：掌握 Prompt、结构化输出、RAG、工具调用和多模态集成。
- Agent 工程师：理解 Agent Runtime、状态、规划、工具、安全和评估。
- 平台工程师：理解模型网关、推理服务、可观测性、成本、可靠性和治理。
- 教师/导师：组织课程、实验、测验和项目验收。

## 3. 学习成果
完成课程后，学习者应能够：
1. 解释 Tokenization、Embedding、Attention、Transformer、上下文窗口和推理过程。
2. 设计模型调用、结构化输出、工具调用和 RAG 应用。
3. 构建具备状态管理、工具边界、失败恢复和可观测性的 Agent。
4. 理解 MCP、Skills、Workflow 与 Multi-Agent 的职责边界。
5. 设计权限控制、人工审批、输入输出校验和安全评估。
6. 对 AI 应用进行测试、评估、部署、监控和成本治理。
7. 交付有文档、测试、威胁模型和运行说明的综合项目。

## 4. 核心用户体验
每个课程单元遵循统一学习循环：

**目标与先修知识 → 概念模型 → 可视化解释 → 交互实验 → 工程任务 → 自动/人工评估 → 复盘与拓展。**

实验应提供可编辑输入与参数、明确的执行步骤和中间状态、预期结果及边界条件、可复现配置、错误案例和诊断提示，以及“模拟 / 浏览器本地 / 真实后端”执行标识。

## 5. 功能范围

### MVP
- 课程目录、模块、章节与学习目标；
- Markdown/MDX 内容渲染；
- 交互式前端实验组件；
- 课程搜索、层级标签和先修关系；
- 本地学习进度（初期不依赖账号体系）；
- 章节测验与实验验收说明；
- 桌面和移动端响应式布局。

### 后续能力
- 用户账户与跨设备进度同步；
- AI Tutor、上下文问答和个性化学习路径；
- 真实模型 API 与模型路由；
- RAG、Tool Calling、Agent、MCP 实验后端；
- 隔离代码执行环境；
- 课程评测、遥测和教师管理。

## 6. 非目标（初期）
- 不把课程平台做成通用 IDE 或模型托管平台；
- 不在浏览器中执行不受约束的任意代码；
- 不把静态模拟描述成真实模型推理或真实工具调用；
- 不承诺所有模型供应商、协议和框架在 MVP 同时接入；
- 不以复杂微服务架构替代尚未验证的产品需求。

## 7. 验收原则
功能只有在用户价值、行为契约、失败状态、权限边界、测试方式、可访问性、运行成本和文档均明确时才可标记完成。课程知识必须注明适用范围、关键假设和参考来源。
