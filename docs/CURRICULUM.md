| L2 模型原理 | M03 | Token、Embedding、Context | 分析 token 与上下文限制 |
| L2 模型原理 | M04 | 预训练、微调与对齐 | 区分训练范式和数据需求 |
| L2 模型原理 | M05 | 推理、解码与部署 | 解释采样、KV Cache 和服务指标 |

| L3 应用工程 | M08 | RAG | 实现检索、重排、引用和评估 |

## 旗舰课程：M01《人工智能与 AI 系统工程基础》

M01 是 Academy 的第一门完整课程，不再以一篇概念导读作为入门。它采用五讲递进式结构，目标是让学习者从“知道几个 AI 名词”走向“能够拆解并设计一个 AI 系统”。

| 讲次 | 主题 | 核心学习产物 |
|---|---|---|
| 01 | 人工智能是什么：概念地图与系统边界 | 一张 AI 产品分层图，区分任务、方法、模型、应用与系统 |
| 02 | 机器如何从数据中学习：规则、模型与泛化 | 一份训练数据说明，解释样本、特征、标签、损失和数据切分 |
| 03 | 从神经网络到大语言模型：能力从哪里来 | 一张自回归语言模型训练与生成流程图 |
| 04 | 大模型能做什么、不能做什么：能力边界与失败模式 | 一份可靠性审查，区分生成、知识访问、推断、执行和验证 |
| 05 | 从模型到工程系统：完成第一个 AI 系统设计 | 一份可评审的系统设计包，覆盖需求、架构、信任边界、指标、评测和运维 |

### 教学组织原则

- **先建立概念，再解释机制，最后进入工程设计。** 不要求初学者一开始就记忆大量模型术语。
- **使用贯穿案例。** 垃圾邮件分类、地图导航、企业知识助手和退款流程用于连接抽象概念与真实工程场景。
- **明确事实、简化和假设。** 教学模型用于建立直觉时，必须说明它省略了什么；无法确认的产品内部实现必须标为假设。
- **把安全与可靠性放进入门课程。** 权限、证据、验证、人工介入和可观测性不是高级课程才需要考虑的附加项。
- **以可评审产物收尾。** 学习者最终提交系统设计，而不只是完成术语记忆题。

## 旗舰课程：M02《Transformer 与 Attention》

M02 承接 M01 的 AI 系统基础，进入现代大语言模型的核心架构。课程不把 Attention 当作孤立公式，而是从输入表示出发，逐步推导张量、注意力权重、多头机制、位置机制、Transformer Block 和推理阶段的计算成本。

| 讲次 | 主题 | 核心学习产物 |
|---|---|---|
| 01 | 从序列到注意力：为什么需要 Attention | 一份 Q/K/V 数据流图与单头注意力手算记录 |
| 02 | Multi-Head Attention 与 Mask：并行的信息交互 | 多头维度推导、Causal/ Padding Mask 对照表 |
| 03 | 位置机制：模型如何表示顺序 | 绝对位置编码、相对位置与 RoPE 的比较说明 |
| 04 | Transformer Block：把注意力组装成网络 | Encoder/Decoder、残差、归一化和 FFN 架构图 |
| 05 | 从理论到推理：复杂度、KV Cache 与优化 | Attention 复杂度分析和一次完整实验报告 |

### 教学组织原则

- 从一个可手算的小矩阵开始，先理解每一步运算，再扩展到批量、多头和真实模型张量。
- 明确区分数学定义、架构设计选择和特定模型的实现差异。
- 对 Q/K/V 的解释采用“检索接口”的教学类比，但不把它们说成固定的人类语义标签。
- 分清 Causal Mask 与 Padding Mask 的目的，避免把所有 mask 混为一谈。
- 将标准 Attention 的二次复杂度与 FlashAttention 的 IO 优化区分开：后者不改变标准注意力的数学结果定义。
- 通过浏览器本地固定矩阵实验验证数值流程；实验不加载真实模型权重，也不代表 GPU 性能基准。

## 旗舰课程：M03《Token、Embedding 与 Context》

M03 将模型输入表示拆成三个相互关联但不能混淆的层次：文本如何被 tokenizer 离散化、离散 token ID 如何通过 embedding 变成向量，以及系统如何把有限上下文预算分配给指令、历史、检索证据和输出。课程同时强调模型接口契约：Tokenizer、词表、特殊 token 和 Chat Template 必须与目标模型匹配。

| 讲次 | 主题 | 核心学习产物 |
|---|---|---|
| 01 | 从文本到 Token ID：离散化过程 | Tokenizer 算法比较与多语言输入切分审计 |
| 02 | 从 Token ID 到 Embedding：向量表示 | Embedding 参数量计算、数据流图与 weight tying 说明 |
| 03 | Context Window 与 Token Budget：上下文容量规划 | 一份可复算的请求预算表与超限压缩方案 |
| 04 | Context Engineering：消息、模板与证据组织 | 企业知识助手 Context Assembly Pipeline 设计 |
| 05 | 综合实操：Token 计量、Embedding 估算与上下文审计 | Tokenizer 实验记录和端到端 Token/Context 审计报告 |

### 教学组织原则

- 严格区分 Unicode 码点、UTF-8 字节、token、token ID 和 embedding vector；**Token ID 是离散索引，不是语义向量**。
- 比较 BPE、WordPiece、Unigram 和 byte-level 设计时，说明训练目标、预处理与编码规则差异，不把它们混为同一算法。
- 通过可复算的词表规模 × embedding 维度示例建立参数量和存储量直觉，并明确训练额外状态未计入。
- 将 context window 视为一次请求的序列容量约束；预算必须纳入消息模板、工具、检索内容、输出预留和安全余量。
- 区分标称上下文窗口与模型对长上下文的有效利用质量；摘要、滑动窗口和 RAG 都需要任务级验证。
- Tokenizer Lab 仅使用浏览器本地玩具 BPE 词表，不等同于任何厂商的生产 tokenizer，不验证真实 token ID 或 API 计量结果。
- 对模型专用 Chat Template、特殊 token 和消息结束语义，以目标模型/服务的官方文档为准。


## 旗舰课程：M04《预训练、微调与对齐》

M04 从自回归预训练目标出发，连接数据治理、模型架构、监督微调、参数高效适配、偏好优化和发布评测。课程将训练 FLOPs、LoRA 参数量、PPO clipping 等内容转化为可复算案例，并明确奖励模型只是偏好代理。

| 讲次 | 主题 | 核心学习产物 |
|---|---|---|
| 01 | 预训练目标与数据工程 | 训练预算计算与数据治理审查单 |
| 02 | 模型架构家族与稀疏专家 | Encoder/Decoder 对比与 MoE 参数分析 |
| 03 | SFT 与参数高效微调 | 指令数据契约、loss mask 与 LoRA 计算 |
| 04 | 偏好对齐、RLHF、PPO 与 DPO | 偏好优化流程图与奖励风险分析 |
| 05 | 训练评测、模型卡与发布治理 | 模型发布评测档案 |

教学重点：区分总参数与激活参数、训练目标与偏好代理、离线分数与真实泛化；对数据许可、污染、PII 和模型发布边界进行工程审查。

## 旗舰课程：M05《推理、解码与部署》

M05 从自回归生成的数据路径出发，深入 KV Cache、采样分布、连续批处理、推测解码、量化和多 GPU 推理服务。容量估算明确区分权重、KV、激活、工作区与运行时开销。

| 讲次 | 主题 | 核心学习产物 |
|---|---|---|
| 01 | Prefill、Decode 与 KV Cache | KV Cache 容量计算与缓存生命周期设计 |
| 02 | 解码策略与生成分布 | Temperature/Top-k/Top-p 手算记录 |
| 03 | Batching 与请求调度 | Continuous Batching 调度策略 |
| 04 | Speculative Decoding 与量化 | 模型量化存储估算与评测计划 |
| 05 | 推理服务架构与容量工程 | 多 GPU 推理服务架构与 SLO 设计 |

教学重点：区分 TTFT、TPOT、请求吞吐和 token 吞吐；区分理论内存估算与实测峰值；所有优化必须以目标硬件、真实请求分布和质量回归为依据。

## 旗舰课程：M06《Prompt Engineering》

M06 将提示词视为可测试、可版本化的任务接口，而不是依靠措辞技巧保证模型正确。课程覆盖消息职责、Few-shot 示例选择、结构化输出、Prompt Injection 和回归发布。

| 讲次 | 主题 | 核心学习产物 |
|---|---|---|
| 01 | 指令结构与任务规格 | 可审查的任务 Prompt 契约 |
| 02 | Few-shot、示例选择与上下文组织 | 示例选择策略与 token 预算 |
| 03 | 结构化输出与可验证生成 | JSON Schema 与业务校验流程 |
| 04 | Prompt Injection 与提示词安全 | 威胁模型和非 Prompt-only 控制 |
| 05 | Prompt 评测、版本管理与回归 | Prompt 发布流水线与回滚门槛 |

教学重点：结构化输出必须经过程序校验；外部文档和检索内容不能因文本标记而自动成为可信指令；模型拒绝语句不能代替工具执行审计。

## M04–M06 教材深化：可复现工程练习

本轮为 M04–M06 的 15 讲各增加一个实践章节。新增章节不要求新增平台能力，重点是让学习者能独立复算、绘制流程、检查假设并提交可审阅证据。

| 模块 | 新增实践重点 | 必须提交的证据 |
|---|---|---|
| M04 预训练、微调与对齐 | 训练 FLOPs 逐步估算；MoE 总参数/激活参数账本；SFT token-level loss mask；PPO 与 DPO 同样本比较；模型发布追溯链 | 公式和单位、参数账本、脱敏样本、流程图、发布档案及未验证项 |
| M05 推理、解码与部署 | KV Cache 容量复算；temperature/top-k/top-p 手算；continuous batching 时间线；量化公平对照；多 GPU 容量评审 | 可复算表格、候选概率表、调度时间线、质量/性能对照、容量与 SLO 设计 |
| M06 Prompt Engineering | 采购审查 Prompt 契约；few-shot 覆盖和顺序实验；退款 JSON 分层校验；网页间接注入攻击链；Prompt 回归发布门禁 | 契约与失败样例、token 预算、Schema/错误分类、威胁模型、评测和回滚记录 |

### 教学与评审要求

- 每项数值练习必须写明输入、公式、单位、舍入方式和未计入成本；理论估算不得写成实测性能。
- 每项架构练习必须同时呈现收益、代价、适用条件和失败模式。
- 每项安全练习必须标出信任边界与真正执行控制的组件；Prompt 文本本身不构成授权边界。
- 评测作业必须区分设计方案、静态审阅、真实执行和未验证状态，不得将计划或模拟结果写成生产证据。
- 新增内容复用现有 Schema 和模块实验室，不新增运行时、API、数据库或 CI 工作流。

本轮为 M07–M09 的 15 讲各增加一个实践章节，延续“计算可复核、状态可追踪、失败可归因、证据可审阅”的教材标准。

| 模块 | 新增实践重点 | 必须提交的证据 |
|---|---|---|
| M07 Tool Calling | 工具调用超时状态追踪；退款 Schema 负向测试；工具路由混淆矩阵；并发幂等故障注入；分层验收指标 | 状态机、测试矩阵、混淆矩阵、并发时序图、Mock/真实服务验收边界 |
| M08 RAG | 可引用请求追踪；Chunk Overlap 规模计算；Exact/ANN 召回诊断；RRF 排名手算；ACL/删除/缓存回归 | 数据血缘、chunk 计算、检索对照、融合排名、权限与删除传播记录 |

### 教学与评审要求

- 多模态练习必须标注采样、时间同步和模态缺失假设；理论 token/带宽估算不得冒充真实模型性能。
- 所有实验报告记录输入、版本、执行模式、结果和未验证项；Mock 或浏览器模拟不得描述为真实服务集成。
- 本轮仅增加教材内容，不新增 Lab runtime、API、数据库或 CI 工作流。


## M10–M12 教材深化：Agent Runtime、Planning/Memory 与 MCP 实践

本轮为 M10–M12 的 15 讲各增加一个实践章节，将概念学习转化为可检查的运行轨迹、状态模型、权限边界和验收证据。

| 模块 | 新增实践重点 | 必须提交的证据 |
|---|---|---|
| M10 Agent Runtime | Agent 目标契约；Plan/Act/Observe 轨迹与循环检测；DAG 状态机和 checkpoint；多租户上下文/runtime 隔离；故障注入验收 | 状态/动作表、执行轨迹、DAG、checkpoint schema、隔离矩阵、故障与恢复记录 |
| M11 Planning & Memory | 供应商尽调 DAG；记忆类型与写入策略；检索摘要和冲突处理；Human Approval 状态恢复；规划/记忆独立评测 | 节点契约、记忆数据结构、来源追溯、审批状态机、指标与故障注入 |
| M12 MCP | JSON-RPC 消息追踪；Tools/Resources/Prompts 能力目录；Transport 生命周期；第三方 Server 威胁模型；互操作与升级验收 | 消息样例、能力版本矩阵、连接状态机、威胁模型、兼容/回滚清单 |

### 教学与评审要求

- Agent 的目标完成必须由外部可观察条件证明；模型输出“完成”不是状态事实。
- Checkpoint 恢复前重新验证身份、权限、工具版本和外部副作用状态，不得盲目重放写操作。
- 长期记忆必须具有来源、时效、所有者和删除策略；一次性纠正不得自动固化为长期偏好。
- MCP 协议互操作与 Server 信任是两个不同问题；协议兼容不代表 Server 安全可信。
- Mock/Simulation 只证明其覆盖范围内的模拟行为，不能描述为真实服务部署或生产验收。


## M13–M15 教材深化：Skills、Multi-Agent 与 AI 安全实践

本轮为 M13–M15 的 15 讲各增加一个实践章节，重点是能力契约、协作一致性和安全治理的工程证据。

| 模块 | 新增实践重点 | 必须提交的证据 |
|---|---|---|
| M13 Skills | Skill 输入输出契约；包结构与路径安全；Skill DAG 组合；第三方供应链审计；Registry 准入/回滚 | 契约表、目录树、依赖锁定、威胁模型、版本和撤销记录 |
| M14 Multi-Agent | 单 Agent baseline；Task/Result 协议；共享状态并发冲突；claim ledger 证据仲裁；单位成功成本对照 | 拓扑矩阵、消息 Schema、并发时序、证据账本、成本/质量对照 |
| M15 AI Security | STRIDE 威胁登记；间接注入数据外传路径；RBAC/ABAC 与审批绑定；高影响人工监督；红队与事件响应 | 数据流图、攻击树、授权策略、审核 SOP、红队报告和事件时间线 |

### 教学与评审要求

- Skill 的能力声明必须对应输入输出契约和可执行边界；工具权限仍由 Host/runtime 强制实施。
- Multi-Agent 必须与单 Agent baseline 对照，计入协调、重试和重复工作成本；意见一致不等于独立证据。
- 共享状态需要版本冲突检测、写入所有权和可审计仲裁，不默认采用 last-write-wins。
- AI 安全作业必须将威胁映射到实际控制组件和测试证据；高影响输出需明确人工责任和申诉路径。
- 安全控制未执行验证时标记 not tested，不得把设计方案写成已通过的安全验收。
