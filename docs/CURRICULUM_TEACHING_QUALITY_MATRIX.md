# M01–M20 教学质量评价矩阵

## 1. 评分口径

每项按 1–5 分评价：1=缺失/严重不足；2=部分覆盖但证据薄弱；3=达到工程课程基本要求；4=内容完整且有可检查实践；5=跨模块衔接清晰、评价可复现并有高质量工程证据。

八个维度：技术准确性（TA）、教学完整性（TC）、工程真实性（ER）、实践深度（PD）、评价有效性（AE）、知识衔接（KA）、资料质量（SQ）、综合能力（IC）。总分为 40 分。评分依据是当前课程内容和资产结构的桌面审阅，不等同外部专家评分。严重技术错误或缺少关键安全门槛不能被平均分抵消；存在 P0/P1 时，即使总分高也不得标记为通过。

## 3. 维度分布与解释

- 技术准确性：各模块均有核心来源审查记录；分数 4 表示仍需版本化复核，不代表所有技术主张获得外部认证。
- 教学完整性：课程源文件、教师指南、学习目标、实践任务和评分 Rubric 基本齐备。
- 工程真实性：M05、M07、M08、M10、M12、M15–M20 强调实际工程约束，但多数例程为合成/本地教学模型，不能标记生产验证。
- 实践深度：M01–M03 原有资源形态不均衡；新增工作簿后，实践步骤、提交物和自检标准补齐；M09 仍定位为系统工程覆盖。
- 评价有效性：每讲有正式作业和 Rubric；跨课程评价统一证据等级、负向测试和统计分母。
- 知识衔接：显式 prerequisite 图完整；M04 新增 M03 先修边。
- 资料质量：课程包含论文、正式规范和官方产品文档，需持续区分证据类型、版本和适用范围。
- 综合能力：M19/M20 将产品价值和系统工程交付结合；最终能力仍需通过学习者 Capstone 真实证据证明。

## 4. 质量门禁

1. 任一 P0 技术错误未关闭：模块不通过。
2. 任一 P1 先修、关键实验或安全验收缺陷未关闭：模块不得标记旗舰完成。
3. 课程目标不能映射到实际内容、作业或 Rubric：必须整改。
4. 设计题至少要求图/表/状态/指标/替代方案之一；实现题必须要求可执行结果或明确说明模拟边界。
5. 评分 Rubric 分值必须闭合到 10 分；通过条件必须能由第三方按提交物复核。
6. 来源 HTTP 可访问不等于主张支持；协议文档、标准、论文和厂商文档的证据级别必须标注。
7. 平均分不抵消安全硬门槛、错误结论、越权风险或伪造验证证据。

## 5. 结论

当前矩阵为基于工作区材料的基线评分，不应包装为外部认证。M01–M20 的总体教学体系成熟度较高；主要整改集中在 M01–M03 实验资源、M04 先修关系，以及 M20 的真实交付证据边界。
