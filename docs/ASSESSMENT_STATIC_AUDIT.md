# M01–M20 正式作业静态审查报告（Phase 02）

> 状态：100 项结构审计与语义初筛完成；逐项人工可完成性判定和真实学习者验证尚未完成。
> 范围：M01–M20 的 100 项正式作业及其 Rubric、学习者作业界面和 M04–M20 模块先修可见性。
> 不在范围：新增平台功能、真实课堂试测、外部认证或生产环境验收。

## 1. 审查方法

本轮通过 TypeScript AST/运行时模块导入读取 20 个旗舰课程数据文件，逐项检查 assessment ID、type、prompt、rubric criterion/description/points；另检查课程目录、学习者手册、模块页面和 AssessmentWorkspace。对文本提示的“交付物/格式/环境/证据”进行关键词覆盖统计，仅用于定位复核对象，不将关键词缺失自动判为缺陷。

静态审查判定边界：
- 数据完整性：字段、数量、评分结构是否完整且一致。
- 任务可理解性：是否能识别要完成的动作与评价目标。
- 交付可执行性：输入、交付物、格式、环境和证据是否足以支持独立完成。
- 类型一致性：type 是否与任务本质一致；同时检查该字段是否实际影响学习者界面。
- 先修可见性：目录依赖是否存在、学习者是否能看到，以及是否能理解具体要复习的能力。
- 本轮不把静态检查视为真实学习者的可完成性或学习成效证据。**审查深度说明**：100 项均已读取并核对 ID、类型、prompt、Rubric 维度和分值；另完成类型分布、交付/格式/环境/证据关键词扫描及高风险样例复核。本报告不是 100 项逐项 PASS/FAIL 的人工评分表，不能据此宣称每项作业均已完成语义验收。下一轮应结合试测任务覆盖表，对实际抽样任务做逐项可完成性判定。

## 3. 主要发现

### A-01 — 作业类型标签与任务交付形式存在语义不一致（P2，元数据治理）

21 项标记为 `code-task` 的任务中，有相当一部分实际交付是计算、设计、Schema、评测计划或目录结构，而不是可执行代码。例如：
- M02 `m02-01-attention-by-hand`：手算 Attention 矩阵；
- M03 `m03-02-embedding-calculation`：参数/存储计算与数据流图；
- M04 `m04-03-lora-plan`：SFT/LoRA 方案与参数推导；
- M05 `m05-01-kv-capacity`：KV 容量计算；
- M06 `m06-02-fewshot-design`、`m06-03-schema-contract`：选择器设计与 Schema 契约；
- M08 `m08-02-chunking-design`、`m08-04-hybrid-search`：切分/RRF 计算和检索设计；
- M09 `m09-02-vit-calc`、`m09-04-audio-engineering`：数学计算和系统设计；
- M17 `m17-02-benchmark-design`：Benchmark 数据结构和统计计算；
- M18 `m18-03-quota-cost`、M19 `m19-03-unit-economics`：配额/成本计算。

这些任务并非低质量任务；问题在于 `code-task` 容易让人误以为必须编写和运行代码。相反，部分 `knowledge-check` 也要求流程图或架构图，例如 M01 `m01-03-llm-mechanism`、M04 `m04-04-alignment-compare`、M12 `m12-01-mcp-architecture`。

**影响与处理**：当前 `AssessmentWorkspace` 不读取或显示 `assessment.type`，也没有按 type 分流提交 UI；因此这是元数据语义问题，不是已确认的学习者界面阻断。本轮不批量重分类，以免仅凭关键词破坏既有分类意图。建议后续在课程类型治理中把定义改成可操作的任务分类（例如 knowledge-check = 概念解释/短答；code-task = 必须提交可执行代码或测试；design-review = 设计工件/分析包），再逐项确认并迁移。

### A-02 — 学习者作业工作区是通用文本草稿，不是完整制品提交环境（P1，能力边界需明确）

`src/components/AssessmentWorkspace.tsx` 当前提供：
- Prompt 展示；
- 单个文本回答框（最多 10,000 字符）；
- Rubric 自评勾选；
- 浏览器本地草稿保存说明。

它不展示 assessment type，不提供文件/代码附件、执行环境、测试运行、外部制品链接或教师评分提交工作流。对于 M20 `m20-03-implementation-review` 等要求代码审查包、测试证据和 mock/真实服务边界的任务，单一文本框不能承载完整交付物本身。

**影响与处理**：当前 UI 文字定位为“回答/设计说明”和“草稿”，并明确自评分数不是教师评分，因此不能称为实现缺陷或误导性自动评分。但学习者必须知道：该区域用于记录摘要和自评，正式代码、图表、测试日志及其他工件应按课程/教师约定另行提交。本轮保持平台范围不变，建议在学习者手册和作业说明中明确“草稿区不等于正式提交入口”，真实试测时观察学习者是否误认为已完成正式提交。

### A-03 — 多数作业有明确动作，但交付格式、环境与证据强度并不总是显式（P1/P2，需任务级复核）

100 项 prompt 的关键词扫描显示：96 项包含可识别动作/产出词；38 项显式出现表格、JSON、图、报告、代码等格式词；28 项显式出现环境词；43 项显式出现证据、复现、日志、测试、版本等词。

这些数字是定位信号而非质量评分。例如纯概念推导不必要求 Python 环境；架构设计也不必指定 IDE。但对于要求“实现、评测、运行、集成、benchmark”的任务，应明确：
1. 最小交付物（文件/图/代码/表格/报告）；
2. 允许的执行模式（手算、浏览器实验、mock、本地服务、真实 provider）；
3. 输入数据、参数、版本或获取方式；
4. 验收证据与复现步骤；
5. 未提供凭证、GPU、付费账户时的替代路径。

首轮高优先级复核对象：M10 `m10-02-agent-loop`（伪代码/状态与终止条件）、M13 `m13-02-skill-package`（目录树/元数据/脚本边界）、M16 `m16-03-resilience-policy`（参数选择及依据）、M20 `m20-03-implementation-review`（代码与测试工件）。这些是任务级复核对象，不代表已经确认无法完成。

### A-04 — M08 RRF 作业的检索候选预算与讲义练习不一致（P2，已修复）

`m08-04-hybrid-search` 的作业原先要求 top-50 召回后直接 rerank top-5；同一讲次的复现练习则规定 top-50 初召回、rerank top-10、最终上下文 top-5。教师指南原参考答案也写 top-5 rerank，导致课程正文、作业和答案之间出现不一致。

**核实结果**：RRF 的输入排名并非缺失。讲次正文已给出 A 在 BM25/dense 排名 1/5、B 排名 3/2；参考答案此前没有把这组输入展开计算，降低了学习者自检能力。

**最小修复**：统一为 top-50 初召回 → rerank top-10 → 最终上下文 top-5；教师参考答案补入 A≈0.031778、B≈0.032002，明确 B 排名更高，并将评测要求对应到 Recall@50、nDCG@5、MRR 和延迟。未更改作业 ID、Rubric 分值或模块结构。

### A-05 — M13 Skill 版本元数据的规范边界需要进入评分标准（P2，已修复）

M13 第二讲正文与教师指南均说明 Agent Skills 规范没有定义顶层 `version` 字段，组织版本信息应放入自定义 `metadata.version`。原作业 Rubric 只写“名称、版本、适用范围和兼容信息完整”，没有说明版本字段的规范位置，可能诱导学习者把组织扩展误认为开放规范字段。

**最小修复**：将 Rubric 描述改为明确区分规范字段与组织扩展，并规定如记录版本应放入组织约定的 `metadata.version`，不误写为规范顶层字段。分值和作业结构不变。

### A-06 — M19 单任务直接成本的范围边界不够明确（P2，已修复）

`m19-03-unit-economics` 原题要求计算“单任务直接成本”，而讲次同时展示模型+人工合计 0.24，以及再计入工具/存储 0.03 后的 0.27。Rubric 以至少 0.24 为基准，但题面没有明确本题必须先计算哪两项，容易把示例扩展成本误认为本题固定输入。

**最小修复**：明确先计算模型与人工两项，列出工具/存储等未计入成本，再讨论毛利和配额；Rubric 明确 0.24 是两项合计的基准，其他成本单独列示。分值不变。

### A-07 — M18/M19 成本计算练习缺少明确币种和价格有效性声明（P2，已修复）

M18/M19 的计算题和教师答案使用美元金额，但题面原先只写“2/百万、8/百万”，没有明确币种；学习者可能将教学假设误认为某个供应商的当前报价。

**最小修复**：两题统一标记为课程假设价目（USD），并明确仅用于练习、不代表当前供应商报价；M18 Rubric 与 M19 题面同步标注 USD。价格版本仍作为成本治理练习的必填信息。分值不变。

### A-08 — M02 Transformer 结构图作业的 Rubric 超出题目范围（P2，已修复）

`m02-04-transformer-block-review` 要求绘制 Encoder Layer 与 Decoder-only Block；原 Rubric 却要求列出 Encoder、Decoder 和 Decoder-only 的主要子层，额外引入题目未要求的 Encoder–Decoder Decoder 结构，可能造成扣分标准与交付要求不一致。

**最小修复**：将课程数据与教师指南中的 Rubric 统一为检查 Encoder Layer、Decoder-only Block 的主要子层及注意力差异。分值不变。

### A-09 — M03 综合 Context 审计的教师答案未沿用讲次预算案例（P2，已修复）

`m03-05-integrated-context-audit` 要求提交 24,000-token 请求预算与超限调整。讲次练习给出 22,000-token 分项预算、2,000 动态余量和 26,500-token 超限情景；教师指南原答案另用一组 27,000-token 案例，虽然计算本身可成立，但不利于学习者按同一组数据核对课程练习。

**最小修复**：教师参考答案改为复用讲次的 22,000 + 2,000 动态余量，以及 26,500 超限场景；给出减少 2,500 tokens 的示例策略，并强调不得丢弃权限、否定约束和关键证据。Rubric 分值不变。

### A-10 — M16 重试策略作业缺少可复算的参数基线（P2，已修复）

`m16-03-resilience-policy` 要求设计 timeout/retry/backoff/circuit breaker/bulkhead 参数，但原题没有给定重试基线；讲次练习已有 base=0.5s、factor=2、cap=5s、n=0..3、overall deadline=8s。学习者可能各自假设不同输入，教师难以比较重试预算计算是否正确。

**最小修复**：作业题面和教师指南统一使用讲次参数，要求列出 Full Jitter 窗口，并将排队、请求执行和退避纳入 8 秒总 deadline。熔断和 bulkhead 参数仍允许自行选择，但必须声明负载假设和依据；参考答案补入四个窗口及支付超时状态未知时的处理边界。分值不变。

### A-11 — M20 核心垂直切片作业缺少最小工件和无付费环境路径（P1，已修复）

`m20-03-implementation-review` 原题列出模型请求、RAG 引用、工具 schema、授权、幂等和错误路径，但未明确代码/commit、复现命令、测试日志等必须交付的最小证据，也未明确无付费 API 凭证时的执行路径。教师指南说明 mock 与真实 provider 必须分开，但题面本身没有把默认 mock 路径和证据要求说清。

**最小修复**：明确本地隔离仓库、代码/commit、README/复现命令、依赖版本、正常/失败/安全拒绝测试和日志；确定性 mock 是默认可接受路径，不要求购买 API。接入真实服务时单独记录 provider、版本、凭证前提和实际证据；未运行项必须标记，不得把 mock 冒充真实集成。教师指南同步题面。Rubric 分值不变。

### P-01 — M04–M20 先修模块依赖存在且在应用页面可见，但学习者能力清单不够具体（P1，文档已补充）

课程目录 `src/data/courseCatalog.ts` 为 M04–M20 定义了模块依赖；`src/App.tsx` 的模块侧栏会显示“先修模块”并提供跳转。因此，先修模块 ID 并非仅存在于教师指南。

不足在于：学习者手册只建议按 M01→M20 学习，没有把“先修模块”转换为“开始本模块前应会什么”的能力检查。单独看到 M02/M03 或 M10/M15，不能让学习者知道具体复习哪些概念。

**处理**：新增 `docs/LEARNER_PREREQUISITE_MAP.md`，按 M04–M20 列出上游模块、进入前能力和快速自测；同时从学习者手册增加入口链接。此项是基于课程目录和上游学习目标的文档化，不代表真实学习者已证明这些先修关系合理。
