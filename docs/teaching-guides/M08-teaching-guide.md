# M08 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** RAG 是离线摄取与在线检索/生成的双流水线；证据、版本、ACL、引用定位和无答案策略必须成为一等契约。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** 概率/向量基础、文档解析、数据库索引、访问控制与评测指标
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** 检索增强生成 RAG 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：RAG 系统边界与端到端数据流

### 课前准备

- 复习：概率/向量基础、文档解析、数据库索引、访问控制与评测指标
- 预读主题：为什么需要 RAG、离线与在线两条流水线、证据与引用契约、无答案与权限边界、复现练习：追踪一次可引用 RAG 请求。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 为什么需要 RAG、离线与在线两条流水线、证据与引用契约，先定义对象、边界和数据流。
2. **工程深化：** 以 无答案与权限边界 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：追踪一次可引用 RAG 请求。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「为什么需要 RAG」与「离线与在线两条流水线」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「证据与引用契约」与「无答案与权限边界」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：追踪一次可引用 RAG 请求」和「RAG、Long Context 与 Fine-tuning 的边界」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为企业知识助手画出离线/在线 RAG 数据流，定义 chunk 元数据、引用定位、ACL 过滤和无答案策略。

**参考解答与推理：** 离线链路：source registry→权限/许可检查→解析规范化→chunk+metadata→embedding→稀疏/向量索引→版本快照。在线链路：身份认证→查询改写→ACL 过滤→多路召回→融合/重排→上下文预算→生成→引用验证。chunk 保留 document/version/page/offset/ACL；无证据或无权访问时 abstain。

**原始 Rubric 对照（满分 10 分）：**

- **流水线（3 分）：** 离线摄取与在线检索阶段完整。要求提交物中有直接证据支持该项结论。

- **证据追溯（3 分）：** chunk 和 citation 可回到原文版本。要求提交物中有直接证据支持该项结论。

- **安全边界（4 分）：** 检索前/查询时执行 ACL 并定义无答案。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 只看向量相似度；忽略 ACL 和版本；把召回率与答案正确率混为一谈；引用无法定位原文；缓存跨租户复用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 对 10,000 token 文档比较 chunk=500/overlap=50 与无 overlap 的 chunk 数，并设计保留标题、表格、ACL 和来源定位的解析策略。

**参考解答与推理：** 10,000 token、chunk=500、overlap=50，步长450；按覆盖长度估算 chunk 数约 ceil((10000-50)/(500-50))=23。无 overlap 时约20。切分按标题/段落/表格结构优先；metadata 保留来源、版本、权限、页码/offset、时间与解析器版本。

**原始 Rubric 对照（满分 10 分）：**

- **计算（3 分）：** 正确得到约 23 与 20 个 chunk 的估算。要求提交物中有直接证据支持该项结论。

- **切分取舍（3 分）：** 说明粒度、语义完整和冗余成本。要求提交物中有直接证据支持该项结论。

- **元数据（4 分）：** 保留版本、权限、来源和结构定位。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 只看向量相似度；忽略 ACL 和版本；把召回率与答案正确率混为一谈；引用无法定位原文；缓存跨租户复用。

### 正式作业参考解答

**原始作业：** 给定 u=(1,0)、v=(0.8,0.6)、2v=(1.6,1.2)，计算 cosine 和 dot product，并比较 HNSW 与 IVF 的主要调参变量。

**参考解答与推理：** cosine(u,v)=0.8/(1×1)=0.8；dot(u,v)=0.8。对2v，cosine仍为0.8，dot=1.6，说明点积受向量范数影响。HNSW 通过多层近邻图导航，调 M、efConstruction、efSearch；IVF 先聚类分桶，调 nlist/nprobe。用 exact search 对照 ANN Recall@k 和延迟。

- **相似度计算（3 分）：** 正确算出 cosine=0.8 且 dot 随缩放变化。要求提交物中有直接证据支持该项结论。

- **索引机制（4 分）：** 说明 HNSW 图导航与 IVF 分桶。要求提交物中有直接证据支持该项结论。

- **评测（3 分）：** 提出 Recall@k、延迟和过滤安全验证。要求提交物中有直接证据支持该项结论。

### 正式作业参考解答

**原始 Rubric 对照（满分 10 分）：**

- **分层评测（3 分）：** 检索、生成和端到端指标区分清楚。要求提交物中有直接证据支持该项结论。

- **数据治理（3 分）：** 覆盖版本、删除、ACL 和缓存失效。要求提交物中有直接证据支持该项结论。

- **可靠性（4 分）：** 定义监控、成本和有证据的降级。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 只看向量相似度；忽略 ACL 和版本；把召回率与答案正确率混为一谈；引用无法定位原文；缓存跨租户复用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 进阶概念辨析与课堂扩展

### 1. RAG、Long Context 与 Fine-tuning 的决策边界

RAG 适合可更新、可追溯、需要 ACL 的外部知识；Long Context 适合一次性提供完整材料和跨段推理，但要评估上下文成本与位置偏差；Fine-tuning 适合稳定的行为/格式/任务适配，不应替代动态事实库或资源授权。让学生按更新频率、引用要求、权限粒度、数据规模和评测目标做方案选择。

### 2. Parent-Child 与 Hierarchical Retrieval

小 child chunk 有利于精确定位，parent section 有利于恢复完整语义；层级检索可以先找章节/摘要，再下钻段落、表格行或代码块。父级上下文必须继承 ACL，且删除、版本更新和权限撤销要传播到父子索引关系。表格必须保留列头、单位和脚注，代码必须保留路径和符号上下文。

### 3. 多索引一致性与安全过滤

BM25、vector、metadata 和 ACL 索引要绑定相同 document_version/content_hash。Pre-filter 与 post-filter 对 ANN 召回和侧信道的影响不同，必须在真实索引引擎上测试。不要将“检索后隐藏文本”视为安全过滤。对 BM25-only、dense-only、hybrid、reranker 做 ablation，并报告 Recall@k、nDCG、延迟、索引内存和 ACL violation rate。

### 4. Corrective RAG 与 Self-RAG 的限制

Corrective RAG 可在证据不足时触发查询改写、补充检索或拒答；Self-RAG 探索模型反思检索触发、证据相关性和生成支持。两者增加调用和延迟，模型自评不是真值。冲突证据应呈现来源权威、更新时间和适用范围，不能只按相似度或时间戳选一条。

### 5. 指标分母和人工校准

Recall@k、MRR、nDCG 的分母和排序语义不同；faithfulness 应按可核验声明统计；citation precision 需要检查引用是否真正支持声明；abstention accuracy 要单独评测。RAGAS/ARES 等自动框架是诊断工具，必须用领域人工标注集校准，并按语言、租户、文档类型、权限和长尾主题分层报告。

### 6. 实验工作簿与代码

学生实验统一见 [M08 实验工作簿](./M08-lab-workbook.md)，可运行计算器见仓库的 `examples/m08/README.md`。示例代码展示 chunk 数估算、混合排名、引用校验和分层指标，不实现完整向量数据库或模型推理。

## 评分与教学一致性要求

- 评分项和分值逐条取自课程模块正式 Rubric；不改变原题、分值或课程内评分标准。
- 数学题写明单位、假设和舍入规则；架构题展示替代方案与故障边界；安全题将控制映射到执行组件和测试证据。
- 外部服务使用 mock/sandbox 时明确标注范围，不得将模拟通过描述为真实 provider 或生产验收。
- 允许其他等价方案，只要满足原始 Rubric 且证据充分。


### Chunk 单位与 RRF 计算核验（2026-11-10）

- 10,000/500/50 与 10,000/500/100/200 的切分示例均假设 D、C、O 使用同一 token 计量单位。LangChain `RecursiveCharacterTextSplitter` 默认 `length_function=len` 计字符，不计 token；token budget 必须显式配置 tokenizer-aware length function 或 token splitter。Unstructured `chunk_by_character`/`max_characters` 也是字符单位。
- RRF 示例取 k=60：A=1/61+1/65≈0.031778；B=1/63+1/62≈0.032002，因此 B 排名更高。
- Cross-encoder reranking 应引用 Nogueira & Cho 的 *Passage Re-ranking with BERT*，而不是只引用 BERT 预训练论文；教材来源已更正。
