# M07 教师教学指南与作业参考解答

> 版本：0.20.0 · 适用模块：M07 结构化输出与 Tool Calling  
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 工具调用是模型提出意图、宿主校验授权并执行、再回传结果的受控协议。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** HTTP、JSON、类型系统、事务与权限模型
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** 结构化输出与 Tool Calling 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Tool Calling 协议与控制流

### 课前准备

- 复习：HTTP、JSON、类型系统、事务与权限模型
- 预读主题：工具调用不是模型直接执行代码、工具调用状态机、结果回传与多轮交互、错误与取消语义、复现练习：追踪一次带超时的工具调用。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 工具调用不是模型直接执行代码、工具调用状态机、结果回传与多轮交互，先定义对象、边界和数据流。
2. **工程深化：** 以 错误与取消语义 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：追踪一次带超时的工具调用。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **对象与边界：** 能否说明参与方、状态、数据和责任归属？若把模型建议写成已执行状态，要求重画控制流。
- **机制与权衡：** 能否解释核心算法/协议及其成本？要求给出至少一个替代方案。
- **验证与失败：** 是否定义异常、权限拒绝、超时、恢复或人工接管？没有负向测试的设计不完整。

### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为订单查询和退款工具画出完整状态机，标记模型、宿主、授权服务和外部 API 的责任边界。

**参考解答与推理：** 状态机包含 proposed、schema_validated、authorized、awaiting_confirmation、executing、succeeded、failed、cancelled、unknown。模型只提出 tool name/arguments；宿主分配 call_id，校验 schema 和业务约束，再调用授权服务。超时后若无法确认外部结果，应进入 unknown 并按 request_id 查询，不得盲目重放退款。

**原始 Rubric 对照（满分 10 分）：**

- **控制流（4 分）：** 完整描述提出、验证、授权、执行和回传。要求提交物中有直接证据支持该项结论。

- **状态模型（3 分）：** 状态和 call_id/request_id 设计明确。要求提交物中有直接证据支持该项结论。

- **失败语义（3 分）：** 覆盖超时、取消、重复执行和错误分类。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 tool call 当作已执行；把 schema valid 当成授权；超时后盲目重试写操作；将模型选择当作权限控制。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

**参考解答与推理：** Schema 定义类型、required、enum、范围、格式及 additionalProperties 策略；随后执行对象级授权、订单归属、可退款余额、币种/精度、订单状态和幂等键校验。金额用整数最小货币单位或定点数，拒绝负数、超额和未知字段。schema_valid 不等于业务合法或有权执行。

## 第三讲：工具发现、选择与路由

- 复习：HTTP、JSON、类型系统、事务与权限模型

### 正式作业参考解答

**原始作业：** 为 30 个企业工具设计分层注册表和路由策略，给出只读/写入分组、风险等级、选择评测指标和服务端拒绝规则。

**参考解答与推理：** 注册表按只读查询、低风险写入、高风险资金/外部动作分组。每项含稳定 tool_id、版本、JSON Schema、scope、风险级别、超时、幂等语义、owner 和审计策略。评测混淆矩阵、参数完整率、误调用成本；宿主 allowlist、对象授权、速率限制和高风险确认必须独立于模型路由。

**原始 Rubric 对照（满分 10 分）：**

- **注册表（3 分）：** 包含 ID、版本、schema、scope 和风险元数据。要求提交物中有直接证据支持该项结论。

### 正式作业参考解答

**原始作业：** 设计一个会创建退款并调用支付网关的工具，说明幂等键、事务边界、超时查询、Saga 补偿和审批绑定。

**参考解答与推理：** 幂等键由租户、业务动作和稳定请求意图构成，服务端保存 key、规范化参数摘要、状态与结果；相同 key/相同摘要返回原结果，相同 key/不同摘要拒绝。数据库事务只覆盖本地状态，outbox 可靠投递支付请求；跨服务失败用 Saga 补偿。审批绑定订单、金额、收款方和参数 hash。

**原始 Rubric 对照（满分 10 分）：**

- **幂等机制（3 分）：** 定义 key、参数摘要、重复请求语义。要求提交物中有直接证据支持该项结论。

- **事务设计（4 分）：** 区分本地事务、outbox 和跨服务补偿。要求提交物中有直接证据支持该项结论。

- **审计审批（3 分）：** 审批绑定参数并保留可追溯记录。要求提交物中有直接证据支持该项结论。
