# M09 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 跨模态系统必须分别处理编码、对齐、时间同步、模态缺失、模态级评测、隐私与资源成本。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** 线性代数、图像 patch、概率噪声过程、音频采样与时间戳
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** 多模态 AI 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：多模态架构与表示对齐

### 课前准备

- 复习：线性代数、图像 patch、概率噪声过程、音频采样与时间戳
- 预读主题：多模态系统的基本结构、Early Fusion、Late Fusion 与 Cross-Attention、表示对齐与训练数据、模态缺失与鲁棒性、复现练习：设计会议助手的跨模态时间线。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 多模态系统的基本结构、Early Fusion、Late Fusion 与 Cross-Attention、表示对齐与训练数据，先定义对象、边界和数据流。
2. **工程深化：** 以 模态缺失与鲁棒性 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：设计会议助手的跨模态时间线。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「多模态系统的基本结构」与「Early Fusion、Late Fusion 与 Cross-Attention」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「表示对齐与训练数据」与「模态缺失与鲁棒性」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：设计会议助手的跨模态时间线」和「跨模态对齐目标：Contrastive、Sigmoid 与生成式监督」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为会议助手设计音频、视频帧和文本融合架构，比较 early fusion、late fusion 与 cross-attention，并说明模态缺失策略。

**参考解答与推理：** 会议助手可采用音频 ASR、视频抽帧、说话人/时间戳与文本编码后做 late fusion；细粒度跨模态交互可在投影后用 cross-attention。Early fusion 交互强但同步和算力成本高；late fusion 模块化、缺模态容错较好。所有片段用统一会议时钟和时间区间对齐。

**原始 Rubric 对照（满分 10 分）：**

- **数据流（4 分）：** 说明各模态编码、投影和融合路径。要求提交物中有直接证据支持该项结论。

- **架构比较（3 分）：** 比较交互能力、计算和时序成本。要求提交物中有直接证据支持该项结论。

- **鲁棒性（3 分）：** 覆盖模态缺失、噪声和时间同步。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把模态拼接等同于对齐；忽略时间戳；把 patch 数线性误当注意力成本；不报告 WER/隐私；将理论带宽当实测。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 计算 384×384 输入在 patch=16 和 patch=8 时的 patch 数、含 CLS 的序列长度，并比较标准注意力矩阵规模比。

**参考解答与推理：** 384/16=24，每边24个 patch，合计576；加 CLS 为577。384/8=48，每边48个，合计2304；加 CLS 为2305。序列长度约4倍，标准全注意力矩阵约16倍。Patch 变小保留细节，但显存、延迟和数据需求上升。

**原始 Rubric 对照（满分 10 分）：**

- **Patch 计算（3 分）：** 分别得到 576 与 2304 patch。要求提交物中有直接证据支持该项结论。

- **复杂度（4 分）：** 正确计算序列长度扩大 4 倍、注意力矩阵约 16 倍。要求提交物中有直接证据支持该项结论。

- **工程取舍（3 分）：** 解释分辨率、细节和显存延迟权衡。要求提交物中有直接证据支持该项结论。

- **训练目标（3 分）：** 说明噪声预测 MSE 的变量。要求提交物中有直接证据支持该项结论。

- **采样取舍（4 分）：** 解释 CFG 对遵循度、多样性和伪影的影响。要求提交物中有直接证据支持该项结论。

- **架构完整（3 分）：** 音频/视频/文本管线及时间戳清楚。要求提交物中有直接证据支持该项结论。

- **评测体系（3 分）：** 定义模态级和端到端指标。要求提交物中有直接证据支持该项结论。

- **治理（4 分）：** 覆盖媒体权限、保留、删除和成本。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把模态拼接等同于对齐；忽略时间戳；把 patch 数线性误当注意力成本；不报告 WER/隐私；将理论带宽当实测。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 进阶概念辨析与课堂扩展

### 1. 对比式对齐与生成式跨模态学习

CLIP 类目标使用 batch 内图文配对构造双向对比损失；温度参数控制相似度分布，负样本策略决定训练信号。SigLIP 使用成对 sigmoid loss，避免对整个 batch 的 softmax 归一化。两者都依赖数据配对质量，重复 caption、错误配对、语义 false negative 和语言偏差会损害对齐。要求学生区分 embedding retrieval 与条件生成的训练目标，并按 image-to-text、text-to-image、语言和细粒度概念分层评测。

### 2. 动态视觉分辨率与输入预算

固定 resize、center crop、tiling、native aspect ratio 和 dynamic resolution 的信息损失不同。NaViT 的 Patch n' Pack 说明可在序列中打包不同尺寸/长宽比图像；高分辨率并非免费增益，token 数增加会扩大注意力、显存和延迟。对 OCR、图表、细小目标和密集场景，应采用任务驱动的区域采样，并同时报告任务质量、视觉 token 和成本。

### 3. Latent Diffusion 与采样器工程

Latent Diffusion 在压缩 latent 空间中去噪，减少空间维度但引入自编码器重建误差。采样器将反向过程离散化；NFE 比“步数”更能反映网络调用预算，guidance 实现可能在每步触发多次前向。DPM-Solver 通过扩散 ODE 求解加速采样，但论文数据集的 FID/速度不能直接外推到不同模型、分辨率和 prompt。课堂实验必须固定 checkpoint、seed、采样器和 CFG，只改变一个变量。

### 4. 流式 ASR、说话人分离与延迟

Streaming ASR 的 chunk、overlap 和 look-ahead 在边界准确率与响应延迟之间折中；partial transcript 可能被后续修订，需区分 provisional/stable/final。Diarization 输出说话人轮次，不等同于身份认证。WER/CER、DER、first-token latency、endpoint latency 和 real-time factor 衡量不同目标。统一多任务语音模型与 ASR→MT→TTS 级联系统也应按语言方向、噪声、口音和任务切片比较。

### 5. 视频时序覆盖与事件级 Grounding

固定抽帧容易漏掉短事件；提高帧率又增加 token 和推理成本。动态抽帧、场景切换检测和 coarse-to-fine 检索需要对事件 Recall 和采样偏差进行验证。视频回答应引用时间区间和原始帧/片段；没有被采样覆盖的时间段只能标记“未观察”，不能断言事件未发生。Video-MME 等基准有助于评估不同视频长度和模态组合，但仍需审查字幕泄漏、数据污染和长视频性能衰减。

### 6. 实验工作簿与代码

五项实验统一见 [M09 实验工作簿](./M09-lab-workbook.md)，可运行计算器见仓库的 `examples/m09/README.md`。这些程序仅做确定性预算、指标和时间轴计算，不加载视觉/音频模型，也不代表 GPU 或真实多模态推理性能。

## 跨模块衔接补充：从模型输入/推理到多模态系统

### 先修诊断（进入本模块前）
- 让学习者解释 Token ID、Embedding 和上下文预算，确认其不会把视觉 patch、音频帧或文本 token 混为同一计量单位。
- 复习 M02 的 Attention/QKV 和 M05 的 Prefill/Decode、内存/吞吐预算；只要求能读懂数据流和复杂度，不重复完整讲授。

### 过渡实验
给定一段 60 秒会议音频和每 2 秒抽取一帧的视频流，设计时间戳对齐表，列出采样策略、缺帧处理、模态级质量指标、token/带宽预算和隐私保留策略。所有预算必须注明是假设估算还是目标模型/设备实测。

### 进入后续课程的交付门
