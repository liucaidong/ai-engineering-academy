# M16 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** Workflow 控制状态推进和副作用；Agent 仅在边界清楚的节点提供开放式判断。重试必须有界，补偿失败必须可见。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。



## 标准基线与教学补充（0.35.0）

M16 以 durable workflow、事件驱动和分布式恢复为工程基线，注意区分各框架的具体语义：

- Temporal Workflow Definition：Workflow 命令序列必须与历史兼容；非确定性 API、LLM、网络和数据库交互应放入 Activities。Temporal 当前提供 Worker Versioning（Pinned/Auto-Upgrade）与 patching；具体能力依赖 SDK/部署模式。Activity 会按 Retry Policy 重试，外部副作用必须幂等。
- Temporal Worker Versioning：Pinned Workflow 固定在一个 Worker Deployment Version；Auto-Upgrade 需保持 replay-safe，必要时使用 patching。
- Azure Durable Task：orchestrator 使用事件历史和 replay 恢复状态，必须确定性；Activities 可能 at-least-once 执行，因此外部副作用应幂等。
- AWS Saga Patterns：局部事务与补偿用于长事务跨服务一致性；补偿不是物理回滚，补偿失败需要独立恢复。
- AWS Step Functions Error Handling：Retry/Catch、MaxAttempts、BackoffRate、MaxDelaySeconds 和 jitter 是具体平台语义，可用于比较通用策略。
- CloudEvents 1.0.2：必需上下文属性为 `specversion`、`id`、`source`、`type`；事件中的 `specversion` 值仍为 `"1.0"`。aggregate_id、aggregate_version、schema_version 属于应用字段。
- Transactional Outbox：业务写入与 outbox row 必须在同一数据库事务中提交；relay 至少一次投递，消费者需 Inbox/幂等去重。课程代码仅在进程内锁下模拟事务边界。
- OpenTelemetry Messaging Spans 当前为 Development：跨 producer/broker/consumer 传播 trace context；语义约定状态为 Development，不是 Stable，需 pin 版本并治理迁移。

**教学边界：** Temporal、Azure Durable Functions 和 Step Functions 的 API/执行保证不能混用；课程借用的是共同工程原则，具体重试、回放、版本和计费语义必须以目标引擎文档为准。Full Jitter 的窗口公式为 `Uniform(0, min(cap, base×factor^n))`；课程熔断器是连续失败/单探针示例，不等于 Resilience4j 滑动窗口实现。审批 HMAC 示例假设可信服务已认证审批人，nonce store 仅为进程内原子示例。

## 模块先修与教学准备

- **先修知识：** 状态机、消息队列、分布式事务、重试语义、熔断、审批和回放测试
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Workflow 与确定性编排 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Workflow 与 Agent 的边界

### 课前准备

- 复习：状态机、消息队列、分布式事务、重试语义、熔断、审批和回放测试
- 预读主题：Workflow 的确定性、Agent 的动态决策、混合编排模式、选择决策矩阵、Workflow Control Plane 与 Agent Decision Plane、复现练习：为理赔流程选择 Workflow/Agent 边界。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 Workflow 的确定性、Agent 的动态决策、混合编排模式，先定义对象、边界和数据流。
2. **工程深化：** 以 选择决策矩阵 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：为理赔流程选择 Workflow/Agent 边界。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「Workflow 的确定性」与「Agent 的动态决策」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「混合编排模式」与「选择决策矩阵」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：为理赔流程选择 Workflow/Agent 边界」和「Workflow Control Plane 与 Agent Decision Plane」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为保险理赔设计 workflow/Agent 混合架构，标出确定性状态、Agent 节点、人工审批和不可由模型决定的步骤。

**参考解答与推理：** 理赔的收件、保单有效性、额度计算、状态变更和付款由确定性 workflow 执行；Agent 可做材料分类、摘要和缺失信息建议。模型不能决定越过政策阈值或直接付款。输出经 schema、证据和业务规则验证；人工审批是持久状态节点。审批事件应绑定动作摘要、审批人身份、request/event ID、过期时间和一次性 nonce；签名由可信审批服务生成，消费 nonce 必须原子化。

**原始 Rubric 对照（满分 10 分）：**

- **边界（3 分）：** 正确区分确定流程和开放式决策。要求提交物中有直接证据支持该项结论。

- **控制（4 分）：** 权限、状态推进和审批由确定性组件控制。要求提交物中有直接证据支持该项结论。

- **验证（3 分）：** Agent 输出有 schema、证据和业务校验。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 timeout 当失败；无界重试；补偿被误认为回滚；审批只是 UI 弹窗；回放测试重复执行真实副作用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 为支付依赖设计 timeout、retry、backoff、circuit breaker 和 bulkhead 参数。重试计算沿用讲次基线：base=0.5s、factor=2、cap=5s、n=0..3、overall deadline=8s；列出各次 Full Jitter 窗口并将排队/执行/退避纳入总预算。另自行声明熔断阈值、半开探测和 bulkhead 并发假设及依据；说明哪些错误不重试，以及超时后如何查询状态、避免重复支付并转人工补偿。

**参考解答与推理：** 错误分不可重试参数/授权错误、可重试限流/暂时 5xx、结果未知 timeout。按 base=0.5s、factor=2、cap=5s，n=0..3 的 Full Jitter 窗口依次为 [0,0.5]、[0,1]、[0,2]、[0,4] 秒；这些是等待窗口上限，不代表必须执行四次重试。所有排队、请求执行和退避都受 8s overall deadline 约束，预算不足时停止而不是重置 deadline。熔断 closed/open/half-open 的阈值和探测策略、bulkhead 并发数由学习者声明负载假设并说明依据。timeout 后先用幂等键查询 operation status，状态未知时不得盲目重试支付，应转人工对账/补偿。

**原始 Rubric 对照（满分 10 分）：**

- **错误分类（3 分）：** 区分参数、授权、限流、超时和服务故障。要求提交物中有直接证据支持该项结论。

- **预算（3 分）：** 退避有界且共享总 deadline。要求提交物中有直接证据支持该项结论。

- **隔离恢复（4 分）：** 包含熔断、隔离、幂等查询和人工补偿。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 timeout 当失败；无界重试；补偿被误认为回滚；审批只是 UI 弹窗；回放测试重复执行真实副作用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。

## 第五讲：Workflow 测试、版本与生产治理

### 课前准备

- 复习：状态机、消息队列、分布式事务、重试语义、熔断、审批和回放测试
- 预读主题：状态与转移覆盖、时间与故障注入、版本兼容与回放、生产治理、Replay Determinism 与 Workflow Versioning、复现练习：建立 Workflow 状态覆盖与回放测试。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 状态与转移覆盖、时间与故障注入、版本兼容与回放，先定义对象、边界和数据流。
2. **工程深化：** 以 生产治理 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：建立 Workflow 状态覆盖与回放测试。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「状态与转移覆盖」与「时间与故障注入」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「版本兼容与回放」与「生产治理」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：建立 Workflow 状态覆盖与回放测试」和「Replay Determinism、Workflow Versioning 与历史兼容」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为付款工作流制定测试和上线计划，覆盖状态转移、重复事件、补偿失败、版本回放、SLO 和回滚。

**参考解答与推理：** 测试包括状态/转移覆盖、重复/乱序事件、并发竞争、超时未知、补偿成功/失败、审批过期、版本升级回放。回放必须 mock 或隔离外部副作用，禁止再次扣款。发布前定义 SLO、告警、owner、兼容迁移、canary 和回滚。

**原始 Rubric 对照（满分 10 分）：**

- **测试覆盖（3 分）：** 覆盖正常、异常、并发和副作用路径。要求提交物中有直接证据支持该项结论。

- **版本安全（3 分）：** 处理历史任务兼容和回放副作用。要求提交物中有直接证据支持该项结论。

- **运维（4 分）：** 定义指标、告警、owner 和回滚。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 timeout 当失败；无界重试；补偿被误认为回滚；审批只是 UI 弹窗；回放测试重复执行真实副作用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。
