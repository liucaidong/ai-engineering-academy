# M13 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** Skill 是可发现、可组合、有版本和资源边界的能力包；它不是权限授予机制，脚本/工具权限仍由 Runtime 强制执行。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。



## 标准基线与教学补充（0.32.0）

M13 以 Agent Skills 开放格式规范为基础，并区分格式标准、Host/Runtime 集成和实际任务效果。建议教师备课时使用以下一手材料：

- Agent Skills Specification：定义目录结构、SKILL.md frontmatter、name/description 约束、可选字段、渐进披露和 skills-ref 验证入口。
- Anthropic《Equipping agents for the real world with Agent Skills》：解释设计动机、三阶段上下文加载、脚本/资源和安全注意事项。
- Anthropic《Introducing advanced tool use》：用于区分 Skill 指导流程与 Tool Search、Programmatic Tool Calling 等工具调用机制。
- OWASP Top 10 for Agentic Applications 2026 与 SLSA v1.2：用于 Agentic 风险分类、依赖与发布来源证明；两者不是 Agent Skills 格式规范。

**规范事实：** name 和 description 是必需字段；license、compatibility、metadata 是可选字段；allowed-tools 是 experimental，运行时支持不一致；version、tags、skill_id、input_schema、required_scopes 等不是规范定义的顶层 frontmatter 字段。组织可以将版本和能力契约放入自定义 metadata 或独立 Registry schema，但必须标注为组织约定。

**教学边界：** skills-ref 明确标注为 demonstration-only、not for production；其 validate/read-properties/to-prompt 是参考实现，不是生产安全扫描器。符合开放格式也不保证所有 Host 具有相同触发、脚本执行、权限和沙箱行为。Claude Code 的 `allowed-tools` 是该 Runtime 的临时工具预批准语义，不能外推为跨平台授权协议；所有权限必须由可信 Runtime/Host 强制执行。

## 模块先修与教学准备

- **先修知识：** 接口契约、包管理、版本语义、文件系统安全、依赖供应链与测试金字塔
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Skills 与可复用能力 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Skill 概念、边界与能力契约

### 课前准备

- 复习：接口契约、包管理、版本语义、文件系统安全、依赖供应链与测试金字塔
- 预读主题：Skill 是能力包而非万能 Prompt、输入输出契约、能力边界与职责、完成标准与可组合性、开放格式与 Runtime 契约分离、复现练习：把代码审查能力定义为 Skill 契约。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 Skill 是能力包而非万能 Prompt、输入输出契约、能力边界与职责，先定义对象、边界和数据流。
2. **工程深化：** 以 完成标准与可组合性 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：把代码审查能力定义为 Skill 契约。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「Skill 是能力包而非万能 Prompt」与「输入输出契约」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「能力边界与职责」与「完成标准与可组合性」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：把代码审查能力定义为 Skill 契约」和「开放 Agent Skills 格式与 Runtime 契约分离」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为“代码仓库安全审查”Skill 定义输入/输出 schema、前置条件、权限、副作用、错误码和完成标准。

**参考解答与推理：** SKILL.md 只承载 Agent Skills 规范定义的 name/description 等 frontmatter；企业 Registry 可另行定义 purpose、input/output schema、preconditions、postconditions、required scopes、side effects、timeout、error codes 和 completion evidence。metadata.version 是组织约定，不是规范顶层字段。代码审查 Skill 只读指定仓库路径，输出 findings 与证据位置；不得自行 push/merge。完成标准是覆盖约定目录且报告带 commit SHA。

**原始 Rubric 对照（满分 10 分）：**

- **能力定位（2 分）：** 清楚区分 Skill 与 Tool/Prompt/Workflow。要求提交物中有直接证据支持该项结论。

- **契约（4 分）：** 输入输出、前置条件和终止条件明确。要求提交物中有直接证据支持该项结论。

- **边界（4 分）：** 声明权限、副作用和失败语义。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 Skill 当作 Prompt 或权限授予；包内脚本不审计；路径可逃逸；依赖不锁定；破坏契约却不升级 major 版本。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 教学路径与关键讲解

1. **概念建立：** 讲解 Skill 测试金字塔、触发与执行指标、发布与兼容策略，先定义对象、边界和数据流。
2. **工程深化：** 以 目录治理与生命周期 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：建立 Skill Registry 的准入与回滚门禁。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「Skill 测试金字塔」与「触发与执行指标」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「发布与兼容策略」与「目录治理与生命周期」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：建立 Skill Registry 的准入与回滚门禁」和「分层验证：格式通过不等于 Skill 有效或安全」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。

- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 制定企业 Skill Registry 的准入、测试、SemVer、灰度、弃用和撤销规则，并定义核心质量指标。

**参考解答与推理：** Registry 准入需静态扫描、契约测试、集成/行为测试、权限审查和 owner。若组织采用 SemVer（它不是 Agent Skills 强制规范），兼容增量 minor/patch，破坏性契约 major；灰度按租户/流量分批，监控成功率、权限拒绝、成本和回归。定义弃用窗口、迁移说明、回滚版本、紧急撤销和维护期限。

**原始 Rubric 对照（满分 10 分）：**

- **测试策略（3 分）：** 覆盖静态、契约、集成和任务行为。要求提交物中有直接证据支持该项结论。

- **发布治理（3 分）：** 定义版本兼容、灰度和回滚。要求提交物中有直接证据支持该项结论。

- **目录责任（4 分）：** 明确 owner、审核、撤销和维护期限。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 Skill 当作 Prompt 或权限授予；包内脚本不审计；路径可逃逸；依赖不锁定；破坏契约却不升级 major 版本。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。
