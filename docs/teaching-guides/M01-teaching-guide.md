# M01 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

> 本指南对应课程中的五讲与五项正式评分作业；答案是示范性解法，不限制其他满足 Rubric 的方案。

## 教学定位与先修准备

- **模块主题：** AI、机器学习与大语言模型
- **教学主线：** AI 的概念地图与系统边界 → 数据、规则与机器学习 → 神经网络、训练与自回归语言模型 → 模型能力、信息来源与失败模式 → 从问题定义到 AI 系统设计
- **先修要求：** 无硬性编程先修；具备基础数学、数据表格和系统思维即可。
- **教师准备：** 为每讲准备成功案例、失败案例和输入/假设明确的练习材料。

## 五讲教学安排

| 讲次 | 主题 | 课堂目标 |
|---|---|---|
| 1 | AI 的概念地图与系统边界 | 建立“任务—方法—模型—应用—系统”拆解，避免把产品名当架构事实。 |
| 2 | 数据、规则与机器学习 | 以垃圾邮件为案例，区分规则逻辑与数据学习信号。 |
| 3 | 神经网络、训练与自回归语言模型 | 用函数和下一 token 概率分解连接神经网络与 LLM。 |
| 4 | 模型能力、信息来源与失败模式 | 比较参数知识、当前上下文和外部证据，识别生成、检索、执行和验证失败。 |
| 5 | 从问题定义到 AI 系统设计 | 从用户任务、非目标、数据流、信任边界和验收指标构建设计包。 |

## 第一讲：AI 的概念地图与系统边界

### 课前准备

- 阅读课程原文：先从一个问题开始：什么样的机器行为可以称为智能；AI、ML、DL、生成式 AI 与 LLM：一张不容易混淆的关系图；不要把模型、应用和系统混成一个东西；把概念用于真实产品：地图导航与智能客服。
- 复习：无硬性编程先修；具备基础数学、数据表格和系统思维即可。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 建立“任务—方法—模型—应用—系统”拆解，避免把产品名当架构事实。
2. **机制拆解：** 讲解 先从一个问题开始：什么样的机器行为可以称为智能、AI、ML、DL、生成式 AI 与 LLM：一张不容易混淆的关系图、不要把模型、应用和系统混成一个东西，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“把概念用于真实产品：地图导航与智能客服”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？
- **证据：** 是否保留原始输入、来源、版本、计算过程或测试记录？

### 课后复习

- 不看讲义重画本讲数据流、公式或系统边界图。
- 写出一个失败案例、根因、可观测信号和回归测试。
- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答


**原始作业：** 选择一个智能客服或地图导航产品，提交一页系统分解图。必须分别标出任务、AI 方法、模型组件、应用流程、外部数据/工具，以及权限与验证控制；无法确认的实现必须标注为假设。

**课程原题：** 选择一个智能客服或地图导航产品，提交一页系统分解图。必须分别标出任务、AI 方法、模型组件、应用流程、外部数据/工具，以及权限与验证控制；无法确认的实现必须标注为假设。

**参考答案与推理：** 以智能客服为例：任务包括意图识别、知识问答、订单查询和人工升级；方法可能包括分类、检索排序与生成模型。模型层含 Embedding/LLM；应用层含会话、Prompt、RAG 编排和订单工具适配；系统层含身份、租户/文档 ACL、配额、审计、监控和人工队列。订单查询权限由后端按登录主体和订单归属验证。无法从外部界面确认的内部模型、索引和服务商必须标注为假设。

**原始 Rubric 对照（总分 10 分）：**
- **概念准确性（3 分）：** 正确区分 AI、ML、DL、生成式 AI 与 LLM，未把不同维度概念混为一谈。批改时检查提交物是否有可直接复核的证据。
- **架构分层（3 分）：** 清楚区分模型、应用和系统层，并说明各层职责。批改时检查提交物是否有可直接复核的证据。
- **证据与假设（2 分）：** 区分已知事实与推测，说明至少一个需要进一步验证的假设。批改时检查提交物是否有可直接复核的证据。
- **工程边界（2 分）：** 指出至少两个不能由模型单独保证的权限、质量或运行控制。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

**课程原题：** 某团队用邮件数据训练垃圾邮件分类器。请解释一条样本中的特征和标签、模型参数如何被调整、验证集与测试集的区别，并给出一种可能的数据泄漏方式。

**参考答案与推理：** 一条样本是一封邮件；特征可包括 token/ngram、发件域、链接数和时间等，标签为 spam/ham。模型计算 ŷ=fθ(x)，以交叉熵等损失比较预测与标签，优化器按梯度更新 θ。验证集用于模型/阈值/超参数选择；测试集在决策冻结后评估泛化。泄漏例子：同一邮件线程或近重复邮件跨训练/测试；使用发送后才产生的投诉字段作为特征；按行随机切分导致同一用户或时间事件泄漏。

## 第三讲：神经网络、训练与自回归语言模型

### 课前准备

- 阅读课程原文：神经网络不是一组手写知识，而是一类可训练函数；深度学习的关键：学习中间表示；LLM 为什么训练预测下一个 token；模型知识、上下文与外部证据；从语言模型到生成式 AI 产品。

### 正式作业参考解答


**原始作业：** 用一张流程图解释 LLM 从 token 序列训练到逐 token 生成的过程，并分别标注模型参数、当前上下文和外部检索证据的角色。

**课程原题：** 用一张流程图解释 LLM 从 token 序列训练到逐 token 生成的过程，并分别标注模型参数、当前上下文和外部检索证据的角色。

**参考答案与推理：** 训练链路：文本→Tokenizer→token IDs→Embedding/位置表示→因果 Transformer→对每个位置预测下一 token→交叉熵损失→反向传播更新参数。推理链路：输入上下文→模型计算下一 token 分布→解码选择 token→追加上下文并循环至停止条件。参数是训练得到的持久权重；上下文是当前请求的输入序列；外部检索证据是运行时取得、带来源/权限/时间的非参数化信息。三者不可混为一谈。

**原始 Rubric 对照（总分 10 分）：**
- **神经网络（2 分）：** 解释参数化变换、非线性和表示学习。批改时检查提交物是否有可直接复核的证据。
- **语言建模（3 分）：** 正确描述自回归条件概率和下一 token 训练目标。批改时检查提交物是否有可直接复核的证据。
- **信息来源（3 分）：** 区分参数化知识、上下文和外部证据。批改时检查提交物是否有可直接复核的证据。
- **产品转化（2 分）：** 指出模型之外的至少两个应用/系统组件。批改时检查提交物是否有可直接复核的证据。

- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。

## 第四讲：模型能力、信息来源与失败模式

### 课前准备

- 阅读课程原文：流畅不等于真实：生成机制与事实验证是两回事；五种能力必须分开评估；幻觉与其他常见失败模式；按风险设计验证：低风险与高风险不能用同一把尺；设计一个可靠的“不确定时怎么办”流程。
- 复习：无硬性编程先修；具备基础数学、数据表格和系统思维即可。

**课程原题：** 为“查询订单并在用户确认后申请退款”设计一个可靠性与安全流程。必须覆盖信息来源、订单权限、退款规则、用户确认、幂等、错误处理和审计。

## 第五讲：从问题定义到 AI 系统设计

### 课前准备

- 阅读课程原文：先定义问题，而不是先选模型；绘制系统数据流与信任边界；把“效果好”变成可测量的质量目标；从设计进入交付：测试、监控、回滚与人工介入；毕业设计：提交一份可评审的 AI 系统方案。
- 复习：无硬性编程先修；具备基础数学、数据表格和系统思维即可。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 从用户任务、非目标、数据流、信任边界和验收指标构建设计包。
2. **机制拆解：** 讲解 先定义问题，而不是先选模型、绘制系统数据流与信任边界、把“效果好”变成可测量的质量目标，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“毕业设计：提交一份可评审的 AI 系统方案”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？
- **证据：** 是否保留原始输入、来源、版本、计算过程或测试记录？

### 课后复习

- 不看讲义重画本讲数据流、公式或系统边界图。
- 写出一个失败案例、根因、可观测信号和回归测试。
- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答


**原始作业：** 完成一个 AI 系统设计包。选择课程知识助手、代码审查助手、文件整理助手或客服工单分类系统之一，提交需求、架构、数据流、信任边界、指标、评测计划、威胁分析和运维方案。

**课程原题：** 完成一个 AI 系统设计包。选择课程知识助手、代码审查助手、文件整理助手或客服工单分类系统之一，提交需求、架构、数据流、信任边界、指标、评测计划、威胁分析和运维方案。

**参考答案与推理：** 以课程知识助手为例：章程定义目标用户、支持问题、非目标和成功指标；数据流为认证→ACL 过滤→文档解析/索引→检索→证据引用→生成→引用校验→答复/升级。架构区分 UI、应用编排、模型网关、检索服务、身份/策略服务、审计与监控。指标至少包括检索 Recall@k、引用支持率、任务成功率、拒答正确率、P95 和成本/任务；威胁覆盖越权检索、Prompt Injection、敏感数据泄露和供应商故障。交付写明回滚、数据删除、日志保留、成本预算和未验证事项。

**原始 Rubric 对照（总分 10 分）：**
- **需求与范围（2 分）：** 目标用户、任务、非目标和验收标准明确。批改时检查提交物是否有可直接复核的证据。
- **架构与数据流（3 分）：** 模型、应用、数据、检索和工具职责清晰，信任边界正确。批改时检查提交物是否有可直接复核的证据。
- **质量与评测（2 分）：** 定义可测量指标、测试数据和失败案例。批改时检查提交物是否有可直接复核的证据。
- **安全与治理（2 分）：** 覆盖身份、权限、隐私、人工介入和审计。批改时检查提交物是否有可直接复核的证据。
- **交付可行性（1 分）：** 说明运行约束、成本假设、监控、回滚和已知限制。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

## 教师批改与反馈总则

- 逐条按原始 Rubric 评分，不改变权重；每项反馈指出证据所在位置。
- 数值题检查公式、代入、单位、舍入和数量级。
- 架构题审查职责边界、信任边界、失败路径、可观测性和运维闭环。
- 开放题接受等价方案，但要求说明假设、替代方案和权衡。
- 所有实验按课程 Lab Registry 声明的执行模式理解；不得暗示真实模型推理或 GPU 性能测试。
