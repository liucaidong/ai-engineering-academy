> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

## 教学定位与先修准备

- **模块主题：** Transformer 与 Attention
- **教学主线：** Scaled Dot-Product Attention → Multi-Head Attention 与 Mask → 位置编码与 RoPE → Transformer Block 内部结构 → Attention 复杂度与推理优化
- **先修要求：** M01 概念基础；线性代数、矩阵乘法、Softmax 和基本概率。
- **教师准备：** 为每讲准备成功案例、失败案例和输入/假设明确的练习材料。

## 五讲教学安排

| 讲次 | 主题 | 课堂目标 |

## 第一讲：Scaled Dot-Product Attention

### 课前准备

- 阅读课程原文：先看一个序列问题：当前位置需要哪些上下文信息；从隐藏状态生成 Q、K、V；手算一次 Scaled Dot-Product Attention；为什么要缩放，以及 Softmax 权重代表什么。
- 复习：M01 概念基础；线性代数、矩阵乘法、Softmax 和基本概率。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 先用 2×2 矩阵手算，再映射到 batch/head/sequence/head-dim 张量。
2. **机制拆解：** 讲解 先看一个序列问题：当前位置需要哪些上下文信息、从隐藏状态生成 Q、K、V、手算一次 Scaled Dot-Product Attention，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“为什么要缩放，以及 Softmax 权重代表什么”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？
- **证据：** 是否保留原始输入、来源、版本、计算过程或测试记录？

### 课后复习

- 不看讲义重画本讲数据流、公式或系统边界图。
- 写出一个失败案例、根因、可观测信号和回归测试。
- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答


**原始作业：** 给定 Q=K=[[1,0],[0,1]]、V=[[1,0],[0,2]]，逐步计算 QKᵀ、按 √dₖ 缩放后的分数、逐行 Softmax 权重和最终输出。提交每一步矩阵，并解释为什么 Softmax 沿键位置维度执行。

**课程原题：** 给定 Q=K=[[1,0],[0,1]]、V=[[1,0],[0,2]]，逐步计算 QKᵀ、按 √dₖ 缩放后的分数、逐行 Softmax 权重和最终输出。提交每一步矩阵，并解释为什么 Softmax 沿键位置维度执行。

**参考答案与推理：** 为使数值示例明确，教师可采用 Q=K=I₂、V=[[1,0],[0,2]]。QKᵀ=I₂；dₖ=2，缩放后 S=[[1/√2,0],[0,1/√2]]。逐行 Softmax 得 A≈[[0.6698,0.3302],[0.3302,0.6698]]。输出 AV≈[[0.6698,0.6604],[0.3302,1.3396]]。Softmax 沿键位置维度归一化：每个 query 对所有可见 key 形成一组权重，总和为1，再对对应 V 聚合。题目若未在作业附件提供矩阵，需由教师统一发放矩阵，不能要求学生猜题目输入。

**原始 Rubric 对照（总分 10 分）：**
- **分数矩阵（3 分）：** 正确计算 QKᵀ，行列含义与矩阵方向正确。批改时检查提交物是否有可直接复核的证据。
- **缩放与归一化（3 分）：** 正确使用 √d_k 缩放并对每行执行 Softmax。批改时检查提交物是否有可直接复核的证据。
- **Value 聚合（2 分）：** 正确计算权重乘 V 并解释输出含义。批改时检查提交物是否有可直接复核的证据。
- **概念边界（2 分）：** 说明权重是计算系数而非自动成立的因果解释。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

## 第三讲：位置编码与 RoPE

## 第五讲：Attention 复杂度与推理优化

### 课前准备

- 阅读课程原文：先把所有维度放到同一张图里；为什么标准全注意力会出现 T² 项；KV Cache：避免每个生成步骤重复计算历史 K/V；FlashAttention：优化数据搬运，而不是改写注意力定义；实验报告：从矩阵观察走向工程判断。
- 复习：M01 概念基础；线性代数、矩阵乘法、Softmax 和基本概率。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 从 BHT² 估算分数规模，区分算术复杂度、显存物化和 IO。
2. **机制拆解：** 讲解 先把所有维度放到同一张图里、为什么标准全注意力会出现 T² 项、KV Cache：避免每个生成步骤重复计算历史 K/V，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“实验报告：从矩阵观察走向工程判断”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？
- **证据：** 是否保留原始输入、来源、版本、计算过程或测试记录？

### 课后复习

- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答


**原始作业：** 提交一份 Transformer Attention 工程分析报告。对 B=4、H=8、T=2048、d_k=64 推导张量形状和分数元素数；解释标准注意力的 T² 项、KV Cache 容量变量、FlashAttention 的 IO 优化目标；最后说明 Transformer Lab 能验证什么、不能验证什么。

**课程原题：** 提交一份 Transformer Attention 工程分析报告。对 B=4、H=8、T=2048、d_k=64 推导张量形状和分数元素数；解释标准注意力的 T² 项、KV Cache 容量变量、FlashAttention 的 IO 优化目标；最后说明 Transformer Lab 能验证什么、不能验证什么。

**参考答案与推理：** Q/K/V 为 [4,8,2048,64]，分数矩阵为 [4,8,2048,2048]，元素数 BHT²=4×8×2048²=134,217,728；若完整物化为 FP16，单份分数张量约 268,435,456 bytes=256 MiB（未计梯度/临时工作区）。KV Cache 主要由层数 L、batch/并发 B、缓存长度 T、KV head 数 Hkv、head dim d 和每元素字节数决定，常用估算 2×L×B×T×Hkv×d×bytes。FlashAttention 通过分块与在线 Softmax 减少中间矩阵物化和 HBM↔片上存储数据搬运，不消除标准精确全注意力的 T² 算术关系。Transformer Lab 只能验证固定小矩阵、Mask 与权重；不能验证真实模型权重、CUDA 内核或 GPU 性能。

**原始 Rubric 对照（总分 10 分）：**
- **形状与规模（2 分）：** 正确推导 Q/K/V、分数矩阵形状和元素数量。批改时检查提交物是否有可直接复核的证据。
- **复杂度（2 分）：** 解释标准全注意力计算和显式分数存储中的 T² 项。批改时检查提交物是否有可直接复核的证据。
- **KV Cache（2 分）：** 正确说明缓存内容、主要容量变量和收益/成本权衡。批改时检查提交物是否有可直接复核的证据。
- **FlashAttention（2 分）：** 准确说明 IO 优化目标，不误称为消除标准注意力 T² 计算。批改时检查提交物是否有可直接复核的证据。
- **实验边界（2 分）：** 区分浏览器固定矩阵实验与真实模型/GPU 性能评估。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

## 教师批改与反馈总则

- 逐条按原始 Rubric 评分，不改变权重；每项反馈指出证据所在位置。
- 数值题检查公式、代入、单位、舍入和数量级。
- 架构题审查职责边界、信任边界、失败路径、可观测性和运维闭环。
- 开放题接受等价方案，但要求说明假设、替代方案和权衡。
- 所有实验按课程 Lab Registry 声明的执行模式理解；不得暗示真实模型推理或 GPU 性能测试。
