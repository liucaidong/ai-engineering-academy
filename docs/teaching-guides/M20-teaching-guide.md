# M20 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** Capstone 以需求—实现—测试—证据追踪为主线，必须区分设计、静态审阅、模拟、真实测试和生产验证。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 工程参考基线（0.40.9）

- **ISO/IEC/IEEE 29148 Requirements Engineering：** 需求工程过程、需求信息项和可追踪性。2018 Edition 2 经 2024 复审仍为现行版；2026-02-16 标记待修订，DIS Edition 3 已进入 enquiry 阶段，不能把草案当成已发布标准；ISO 页面未给出固定发布日期。
- **arc42：** 用结构化视图、运行时视图、质量要求、风险和架构决策组织架构文档。
- **Practical Test Pyramid：** 以快速底层测试提供反馈，结合契约/集成测试和少量 E2E 验证用户旅程。
- **OWASP ASVS 5.0.0：** 将 Web 应用/服务安全要求转成可验证控制；与 OWASP GenAI LLM Top 10 2026 配合使用，二者覆盖范围不同。
- **SLSA v1.2：** 当前 Approved 规范包含 Build 与 Source tracks；provenance/attestation 描述来源、构建过程和依赖，验证时必须检查 signer-builder identity 与声明内容。

**协议与框架版本：** 本教材核验基准包括 MCP Specification `2026-07-28`、SLSA `v1.2`、OWASP ASVS `5.0.0`、OWASP GenAI LLM Top 10 `2026`。引用规范时固定版本，不以无版本 `latest` 作为可复现基线。

**Capstone 证据等级：** design-only、static-reviewed、simulated、tested-in-local、tested-in-target-environment、production-observed。不同等级不能互相冒充。Mock 成功不等于真实 provider 可用；本地测试不等于目标环境验收；答辩演示不等于生产批准。

## 模块先修与教学准备

- **先修知识：** 需求工程、架构图、ADR、接口契约、测试、威胁建模、SLO 和技术答辩
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Capstone 综合项目 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Capstone 立项——需求、范围与验收

### 课前准备

- 复习：需求工程、架构图、ADR、接口契约、测试、威胁建模、SLO 和技术答辩
- 预读主题：问题陈述与用户画像、需求与非目标、验收指标、风险和可行性、Definition of Ready/Done 与需求追踪、复现练习：编写 Capstone 项目章程与验收追踪矩阵。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 问题陈述与用户画像、需求与非目标、验收指标，先定义对象、边界和数据流。
2. **工程深化：** 以 风险和可行性 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：编写 Capstone 项目章程与验收追踪矩阵。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「问题陈述与用户画像」与「需求与非目标」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「验收指标」与「风险和可行性」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：编写 Capstone 项目章程与验收追踪矩阵」和「Definition of Ready/Done、需求追踪与治理节奏」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 提交 Capstone 项目章程：用户问题、范围/非目标、验收指标、风险登记和外部依赖清单。

**参考解答与推理：** 章程包含用户/任务/情境/痛点、当前 baseline、范围与非目标、验收指标（分子分母/阈值/窗口）、风险 owner、数据许可、模型凭证、环境和预算依赖。每条需求分配 ID，关联测试方法、证据位置和状态；外部依赖缺失标记 blocked/not tested。

**原始 Rubric 对照（满分 10 分）：**

- **问题与范围（3 分）：** 用户任务、痛点和非目标清楚。要求提交物中有直接证据支持该项结论。

- **验收标准（4 分）：** 指标、分母、阈值和证据来源明确。要求提交物中有直接证据支持该项结论。

- **风险可行性（3 分）：** 记录数据、凭证、模型和环境依赖。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把设计文档当实现证据；Mock 当真实集成；验收指标无分母；缺少失败/拒绝路径；把演示成功等同生产可用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 正式作业参考解答

**原始作业：** 提交 Capstone 架构包：组件图、数据流、关键时序、模型/RAG/Agent 选型表、权限边界和至少三份 ADR。

**参考解答与推理：** 架构包包含 context/container/component、数据流、关键时序、信任边界、故障域和部署视图。比较托管/本地模型、RAG/微调、Agent/workflow、向量/混合检索；至少三份 ADR 记录背景、选项、决定、后果、验证计划和复审触发。Prompt 不承担授权。

**原始 Rubric 对照（满分 10 分）：**

- **架构表达（3 分）：** 组件、数据流和故障边界完整。要求提交物中有直接证据支持该项结论。

- **技术决策（3 分）：** 比较替代方案并说明约束。要求提交物中有直接证据支持该项结论。

- **安全 ADR（4 分）：** 记录身份、工具权限和验证证据。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把设计文档当实现证据；Mock 当真实集成；验收指标无分母；缺少失败/拒绝路径；把演示成功等同生产可用。

### 正式作业参考解答

**原始作业：** 在本地隔离仓库中实现一条最小核心垂直切片，并提交代码审查包：代码/commit、README 与复现命令、模型请求与 RAG 引用、工具 schema、服务端授权、幂等处理、正常/失败/安全拒绝测试及日志。默认可用确定性 mock，无需付费 API；若接入真实服务，单独标明 provider、模型/索引版本、凭证前提和实际执行证据。明确依赖版本、执行环境、未运行项及 mock/真实服务边界，不得把 mock 结果标记为真实集成。

**参考解答与推理：** 垂直切片实现一条用户旅程：认证→检索 ACL→模型调用→schema 校验→工具授权/幂等→业务状态→审计。提供正常、失败和安全拒绝轨迹；记录 model/prompt/index/tool versions。Mock 与真实 provider 明确分开，未运行部分标记 not tested。

**原始 Rubric 对照（满分 10 分）：**

- **核心流程（3 分）：** 端到端最小路径可追踪。要求提交物中有直接证据支持该项结论。

- **集成契约（3 分）：** 模型/检索/工具 schema 和错误语义明确。要求提交物中有直接证据支持该项结论。

- **安全质量（4 分）：** 授权、幂等、审计和模拟边界清楚。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 教学路径与关键讲解

1. **概念建立：** 讲解 交付物清单、演示脚本与证据、技术答辩，先定义对象、边界和数据流。
2. **工程深化：** 以 成熟度与后续路线图 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：组织最终演示与技术答辩。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「交付物清单」与「演示脚本与证据」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「技术答辩」与「成熟度与后续路线图」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：组织最终演示与技术答辩」和「Reproducible Defense、证据来源与评审问责」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 完成 Capstone 答辩包，演示正常/失败/安全拒绝三条路径，并说明实现状态、测试证据、架构取舍和残余风险。

**参考解答与推理：** 交付包包含代码 commit、架构/ADR、API schema、数据/模型/Prompt 版本、测试、benchmark、trace、成本、部署和已知限制。演示冻结版本和输入，展示正常、失败、安全拒绝/人工接管；答辩解释替代方案、指标、失败模式和残余风险。Implemented、reviewed、tested、not tested、blocked 分开标记。

**原始 Rubric 对照（满分 10 分）：**

- **交付完整性（3 分）：** 代码、架构、评测和运维文档齐全。要求提交物中有直接证据支持该项结论。

- **演示证据（3 分）：** 三类流程可复现且引用真实日志。要求提交物中有直接证据支持该项结论。

- **技术答辩（4 分）：** 清楚区分实现、测试和未验证事项。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把设计文档当实现证据；Mock 当真实集成；验收指标无分母；缺少失败/拒绝路径；把演示成功等同生产可用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 评分与教学一致性要求

- 评分项和分值逐条取自课程模块正式 Rubric；不改变原题、分值或课程内评分标准。
- 数学题写明单位、假设和舍入规则；架构题展示替代方案与故障边界；安全题将控制映射到执行组件和测试证据。
- 外部服务使用 mock/sandbox 时明确标注范围，不得将模拟通过描述为真实 provider 或生产验收。
- 允许其他等价方案，只要满足原始 Rubric 且证据充分。


## Capstone 最终评审补充：证据等级与硬门槛

教师在 Gate 2–4 评审时必须逐条核对 M20 实验工作簿中的 E0–E5 证据等级。重点检查：
- 是否至少有一条冻结版本的端到端用户旅程达到 E3 Local-tested；
- 是否演示正常、失败恢复和安全拒绝/人工接管路径；
- 是否将设计、静态审阅、模拟、真实 Sandbox 和生产观测分开标记；
- 是否有需求—实现—测试—证据的双向追踪；
- 是否披露外部凭证缺失、环境阻塞、真实 Provider 未验证和残余风险。

关键越权、跨租户泄漏、未经授权的写操作、证据造假或未披露重大风险均为不可补偿失败项。不得因总分达到建议阈值或演示顺利而放行。课程建议总分门槛为 75/100，且 Gate 0–4 全部通过；该门槛是教学规则，不是生产认证。
