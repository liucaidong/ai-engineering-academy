# M17 教师教学指南与作业参考解答

> 版本：0.20.0 · 适用模块：M17 Evaluation 与 Observability  
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 评测必须有样本单位、分母、成功定义、分层和版本；LLM Judge 需人工校准，Trace/Metric/Log 需隐私与基数治理。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** 统计学、分类指标、抽样、实验设计、遥测数据模型和隐私保护
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Evaluation 与 Observability 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：AI Evaluation 体系与指标设计

### 课前准备

- 复习：统计学、分类指标、抽样、实验设计、遥测数据模型和隐私保护
- 预读主题：为什么单一 benchmark 不够、指标与分母、多目标质量模型、评测分层与分布、复现练习：为知识 Agent 定义端到端 Evaluation 指标。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 为什么单一 benchmark 不够、指标与分母、多目标质量模型，先定义对象、边界和数据流。
2. **工程深化：** 以 评测分层与分布 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：为知识 Agent 定义端到端 Evaluation 指标。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **对象与边界：** 能否说明参与方、状态、数据和责任归属？若把模型建议写成已执行状态，要求重画控制流。
- **机制与权衡：** 能否解释核心算法/协议及其成本？要求给出至少一个替代方案。
- **验证与失败：** 是否定义异常、权限拒绝、超时、恢复或人工接管？没有负向测试的设计不完整。

### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为企业知识 Agent 定义组件级和端到端指标，明确分母、统计窗口、分层维度和上线约束。

**参考解答与推理：** 分层定义 retrieval recall@k、generation faithfulness/correctness、tool schema/authorization pass、端到端 task success。每指标写 numerator/denominator、样本单位、时间窗和风险分层；同时报告成本、P95 和安全硬约束，不能用加权平均掩盖越权。

**原始 Rubric 对照（满分 10 分）：**

- **层次（3 分）：** 区分模型、检索、工具和任务层评测。要求提交物中有直接证据支持该项结论。

- **指标定义（3 分）：** 指标分母、成功标准和窗口明确。要求提交物中有直接证据支持该项结论。

- **多目标（4 分）：** 覆盖质量、成本、延迟和安全硬约束。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 指标没有分母/窗口；benchmark 污染；Judge 未校准；Trace 泄露敏感数据；高基数标签导致成本和存储失控。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 设计 500 条企业问答 benchmark 的字段和切分，计算 80% 成功率时标准误，并说明防污染与盲测策略。

**参考解答与推理：** 500条样本、成功率 p=0.8，SE≈√(0.8×0.2/500)=0.0179，即约1.79个百分点；粗略95%区间约±3.5个百分点（正态近似，边界/分层可用 Wilson 或 bootstrap）。按用户/文档实体分组去重，冻结盲测集并记录 hash、标注、模型和脚本版本。

**原始 Rubric 对照（满分 10 分）：**

- **数据结构（3 分）：** 字段覆盖答案、证据、来源、风险和版本。要求提交物中有直接证据支持该项结论。

- **统计计算（3 分）：** 正确使用比例标准误并说明近似限制。要求提交物中有直接证据支持该项结论。

- **可信度（4 分）：** 覆盖分层、去重、盲测和评分器版本。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 指标没有分母/窗口；benchmark 污染；Judge 未校准；Trace 泄露敏感数据；高基数标签导致成本和存储失控。

**原始作业：** 为 RAG Agent 设计 trace/span、metrics 和 logs 字段，标出高基数标签、敏感字段和采样/保留策略。

**参考解答与推理：** Trace 以 trace_id/span_id 关联 request→retrieval→rerank→model→tool→business outcome；span 记录耗时、模型/索引版本、token usage、错误类别和证据引用。Metric 用低基数维度，不把 user_id/document_id/prompt 当 label。日志脱敏，采样和保留按风险/同意策略执行。

- **指标设计（3 分）：** 包含延迟、token、成本、质量和错误。要求提交物中有直接证据支持该项结论。

- **隐私治理（4 分）：** 避免高基数和敏感内容泄露。要求提交物中有直接证据支持该项结论。
