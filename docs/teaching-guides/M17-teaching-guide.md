# M17 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 评测必须有样本单位、分母、成功定义、分层和版本；LLM Judge 需人工校准，Trace/Metric/Log 需隐私与基数治理。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。



## 标准基线与教学补充（0.40.8）

M17 以 Agent Evaluation 与 OpenTelemetry 为工程基线，强调“评测对象、评分器、观测信号和线上目标”四者一致。

- Anthropic《Demystifying evals for AI agents》：Task、Trial、Grader、Transcript、Outcome 和 Evaluation Harness 定义；Code/Model/Human graders；Capability vs Regression eval。
- HumanEval 原始论文：有限样本无偏 pass@k 估计 `1−C(n−c,k)/C(n,k)`；需与 IID 理论式 `1−(1−p)^k` 区分。
- Prometheus evaluator 论文（非 Prometheus 监控系统）：细粒度 rubric、LLM Judge 与人类评审对齐。
- OpenTelemetry GenAI Semantic Conventions：模型调用、Agent、工具、Token、检索与错误属性；相关约定当前为 Development，需锁定语义约定/仪表化版本并治理迁移。Prometheus label 的 key allowlist 不能单独保证 value cardinality，模型名/租户等值域也需要受控。
- Google SRE Workbook《Alerting on SLOs》：error budget、burn rate 和 multi-window alerting。

**统计边界：** IID 模型的 `pass@k=1−(1−p)^k` 是独立尝试近似；HumanEval 使用 `1−C(n−c,k)/C(n,k)` 有限样本估计。二者不可混用。同一 task 的多次 trial 通常存在任务级相关性；统计分析应按任务聚类或采用配对设计，不能简单把所有 trial 当作独立样本。置信区间不消除数据集泄漏、评分器错误或抽样偏差。

**Judge 边界：** LLM Judge 是待校准测量仪器，不是客观真值。必须用人工 gold set 评估误判、位置/长度偏差和版本漂移；高风险安全判断要保留确定性控制和人工审查。

**遥测边界：** GenAI spans 可能含输入消息、系统指令、检索文本和工具参数等敏感数据。相关 GenAI semantic conventions 当前为 Development，不是 Stable。默认最小化内容采集，使用低基数 metrics、受控 trace/log、脱敏、访问控制和保留期限。

## 模块先修与教学准备

- **先修知识：** 统计学、分类指标、抽样、实验设计、遥测数据模型和隐私保护
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Evaluation 与 Observability 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：AI Evaluation 体系与指标设计

### 课前准备

- 复习：统计学、分类指标、抽样、实验设计、遥测数据模型和隐私保护
- 预读主题：为什么单一 benchmark 不够、指标与分母、多目标质量模型、评测分层与分布、Eval Harness 对象模型与 Outcome Grading、复现练习：为知识 Agent 定义端到端 Evaluation 指标。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 为什么单一 benchmark 不够、指标与分母、多目标质量模型，先定义对象、边界和数据流。
2. **工程深化：** 以 评测分层与分布 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：为知识 Agent 定义端到端 Evaluation 指标。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「为什么单一 benchmark 不够」与「指标与分母」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「多目标质量模型」与「评测分层与分布」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：为知识 Agent 定义端到端 Evaluation 指标」和「Eval Harness 对象模型、Outcome Grading 与回归套件」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为企业知识 Agent 定义组件级和端到端指标，明确分母、统计窗口、分层维度和上线约束。

**参考解答与推理：** 分层定义 retrieval recall@k、generation faithfulness/correctness、tool schema/authorization pass、端到端 task success。每指标写 numerator/denominator、样本单位、时间窗和风险分层；同时报告成本、P95 和安全硬约束，不能用加权平均掩盖越权。

**原始 Rubric 对照（满分 10 分）：**

- **层次（3 分）：** 区分模型、检索、工具和任务层评测。要求提交物中有直接证据支持该项结论。

- **指标定义（3 分）：** 指标分母、成功标准和窗口明确。要求提交物中有直接证据支持该项结论。

- **多目标（4 分）：** 覆盖质量、成本、延迟和安全硬约束。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 指标没有分母/窗口；benchmark 污染；Judge 未校准；Trace 泄露敏感数据；高基数标签导致成本和存储失控。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 设计 500 条企业问答 benchmark 的字段和切分，计算 80% 成功率时标准误，并说明防污染与盲测策略。

- **数据结构（3 分）：** 字段覆盖答案、证据、来源、风险和版本。要求提交物中有直接证据支持该项结论。

- **统计计算（3 分）：** 正确使用比例标准误并说明近似限制。要求提交物中有直接证据支持该项结论。

- **可信度（4 分）：** 覆盖分层、去重、盲测和评分器版本。要求提交物中有直接证据支持该项结论。

- **核心机制：** 围绕「离线与线上一致性」与「漂移检测」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「质量 SLI/SLO」与「反馈闭环与回归」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：将线上质量反馈转成发布 SLO」和「Quality SLO、Error Budget Burn Rate 与持续评测」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为企业知识 Agent 定义线上质量 SLI/SLO、漂移告警、人工采样、错误预算和回归发布流程。

**参考解答与推理：** SLI 包括任务成功、citation support、tool correctness、P95、成本和安全事件；SLO 按任务类型分层，安全硬门槛不进入错误预算。漂移监控输入分布、检索命中、模型版本和人工纠错。反馈经标注、归因、回归集更新、canary 后发布。

**原始 Rubric 对照（满分 10 分）：**

- **SLI/SLO（3 分）：** 定义任务质量、延迟、成本和安全目标。要求提交物中有直接证据支持该项结论。

- **漂移（3 分）：** 覆盖输入、检索和行为分布变化。要求提交物中有直接证据支持该项结论。

- **反馈闭环（4 分）：** 标注、归因、回归和 canary 完整。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 指标没有分母/窗口；benchmark 污染；Judge 未校准；Trace 泄露敏感数据；高基数标签导致成本和存储失控。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。
