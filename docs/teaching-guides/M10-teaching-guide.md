# M10 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** Agent 是受 Runtime 约束的状态化控制循环；模型决策与确定性状态推进、权限执行、预算和停止条件必须分离。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** 状态机、事件循环、API 调用、权限模型、持久化和分布式任务基础
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Agent 基础与 Runtime 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Agent 基本模型与自主性边界

### 课前准备

- 复习：状态机、事件循环、API 调用、权限模型、持久化和分布式任务基础
- 预读主题：Agent 的工程定义、Agent、Workflow 与普通应用、自主性等级与权限边界、目标、约束和停止条件、复现练习：把自然语言目标转成可验证 Agent 契约。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 Agent 的工程定义、Agent、Workflow 与普通应用、自主性等级与权限边界，先定义对象、边界和数据流。
2. **工程深化：** 以 目标、约束和停止条件 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：把自然语言目标转成可验证 Agent 契约。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「Agent 的工程定义」与「Agent、Workflow 与普通应用」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「自主性等级与权限边界」与「目标、约束和停止条件」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：把自然语言目标转成可验证 Agent 契约」和「Agent Runtime：把自主决策约束在可审计执行包络内」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 将一个差旅报销助手拆分为 workflow 与 Agent 决策部分，定义状态、动作、观察、权限等级和停止条件。

**参考解答与推理：** 报销流程中，身份、票据字段、额度、政策版本、状态变更由 workflow 执行；Agent 处理票据解释、缺失信息澄清和异常分类。状态含 applicant、expense、policy_version、evidence、approval；动作分只读、草稿、提交、付款。付款不可由模型自主决定；预算、超时、拒绝条件和人工审批是停止边界。

**原始 Rubric 对照（满分 10 分）：**

- **系统抽象（3 分）：** 明确状态、观察、动作和环境反馈。要求提交物中有直接证据支持该项结论。

- **控制流取舍（3 分）：** 区分确定性步骤和模型决策步骤。要求提交物中有直接证据支持该项结论。

- **权限终止（4 分）：** 定义动作分级、预算和停止条件。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 Agent 当成无限循环；模型输出“完成”就更新业务状态；恢复时盲目重放副作用；只隔离 Prompt 不隔离缓存/凭证/执行资源。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 第二讲：Planning、Execution 与 Observation 循环

### 课前准备

- 复习：状态机、事件循环、API 调用、权限模型、持久化和分布式任务基础
- 预读主题：循环的最小结构、ReAct 与显式计划、观察与状态压缩、循环检测与预算、复现练习：实现带循环检测的 Plan/Act/Observe 轨迹。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 循环的最小结构、ReAct 与显式计划、观察与状态压缩，先定义对象、边界和数据流。
2. **工程深化：** 以 循环检测与预算 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：实现带循环检测的 Plan/Act/Observe 轨迹。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「循环的最小结构」与「ReAct 与显式计划」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「观察与状态压缩」与「循环检测与预算」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：实现带循环检测的 Plan/Act/Observe 轨迹」和「Observation 可信度、后置条件与循环停止」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为“查找订单并判断是否符合退款条件”设计 Agent loop 伪代码，包含状态更新、重复动作检测、超时和停止条件。

**参考解答与推理：** 循环：读取 state→模型提出 action→schema 校验→policy/ownership 授权→执行器带 deadline/idempotency_key 调用→记录 observation→更新 state/version→检测重复 action/循环→检查完成条件。超时后查询 operation status；达到步数、token、成本或总 deadline 即停止并交接，不能把模型的“完成”当作业务事实。

**原始 Rubric 对照（满分 10 分）：**

- **循环结构（4 分）：** 包含决策、校验、执行、观察和状态更新。要求提交物中有直接证据支持该项结论。

- **计划状态（2 分）：** 计划节点具有依赖和完成条件。要求提交物中有直接证据支持该项结论。

- **资源控制（4 分）：** 实现步数、调用次数、超时和循环检测。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 Agent 当成无限循环；模型输出“完成”就更新业务状态；恢复时盲目重放副作用；只隔离 Prompt 不隔离缓存/凭证/执行资源。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 为一个多步骤采购 Agent 绘制状态机和事件表，定义 checkpoint 字段、恢复规则和并行依赖。

- **状态转移（3 分）：** 状态、事件、守卫和终止状态完整。要求提交物中有直接证据支持该项结论。

- **恢复设计（4 分）：** checkpoint 包含版本、步骤、预算和调用引用。要求提交物中有直接证据支持该项结论。

- **一致性（3 分）：** 处理副作用幂等和恢复前权限复核。要求提交物中有直接证据支持该项结论。

### 正式作业参考解答

**原始作业：** 为采购 Agent 制定验收方案，包含任务成功定义、执行轨迹字段、五类故障注入和人工接管门槛。

**参考解答与推理：** 指标包括任务成功率、人工接管率、越权率（硬门槛）、副作用重复率、每任务成本、P95 和恢复时间。故障注入含模型超时、工具超时但实际成功、重复事件、权限撤销、非法参数、预算耗尽。证据包包含 trace、状态快照、policy decision、工具结果引用；上线需通过安全门槛和接管演练。

**原始 Rubric 对照（满分 10 分）：**

- **指标（3 分）：** 任务成功、效率、安全、成本和延迟定义清楚。要求提交物中有直接证据支持该项结论。

- **故障覆盖（4 分）：** 包含超时副作用、撤权、非法动作和预算耗尽。要求提交物中有直接证据支持该项结论。

- **接管治理（3 分）：** 定义证据包、审批和上线门槛。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 Agent 当成无限循环；模型输出“完成”就更新业务状态；恢复时盲目重放副作用；只隔离 Prompt 不隔离缓存/凭证/执行资源。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 进阶概念辨析与课堂扩展

### 1. Agent Runtime 与自主性包络

Agent 不是单独的 LLM，而是由模型、Runtime、工具适配器、策略、状态存储和外部环境组成的系统。自主性应拆成计划生成、只读观察、可逆写入、不可逆副作用、跨系统执行和长期运行等维度。每个任务都要定义 autonomy envelope：允许目标、禁止目标、可读/可写资源、最大轮次、费用/时间预算、审批点和终止条件。最终成功必须由环境状态或业务后置条件验证。

### 2. 观察结果、后置条件与循环停止

ReAct 说明推理、动作和观察可以交替进行，但生产审计应记录结构化事件，而不是把内部思维文本当作事实。Action 记录 action_id、工具、参数摘要、授权决策、deadline 和预期后置条件；Observation 记录状态、来源版本、时间戳、错误类型和关联 ID。执行后重新读取目标状态，区分请求已接受、执行中、已完成和结果未知。重复 action signature、无进展状态、连续错误和预算耗尽都应触发停止或升级。

### 3. Durable Execution、Replay 与副作用恢复

Durable execution 将可重放的确定性决策与外部 I/O 分开。事件历史保存输入、命令、结果和状态迁移；恢复时 replay 历史重建状态，而不是重做已提交副作用。Replay 不等于 Retry；Activity/Tool 重试仍可能重复执行外部动作。写操作必须使用 idempotency key、业务唯一约束或 operation ledger；结果未知时先 reconcile，再决定是否重试。模型调用结果和工具结果应持久化，避免恢复时无意重复收费或重复副作用。

### 4. Capability Security 与 Agent-Computer Interface

Agent-Computer Interface 的命令粒度、输出格式和错误反馈会改变 Agent 行为。Runtime 应按任务签发短期、资源范围明确的 capability，而不是继承用户全部权限。工具注册表只暴露必要能力；参数/路径由服务端校验；文件、网络和进程在 sandbox 中隔离；secret 经 broker 注入且不可回显。网页、文件、OCR、工具输出和终端日志都是不可信观察，不能因其包含“系统指令”而提升权限。高风险副作用应在 policy engine 或 HITL 处拦截。

### 5. Agent 评测与多次运行可靠性

Agent 成功应通过环境最终状态与目标状态的差异验证。AgentBench 覆盖多种交互环境；τ-bench 将用户、工具和领域策略放入动态对话，并提出 pass^k 衡量多次运行的一致性。在独立同分布的简化假设下，单次成功率 p 连续 k 次都成功的概率为 p^k；真实任务并不保证独立，必须报告样本量和置信区间。还应报告 policy violation、recovery rate、human intervention、latency、token/tool cost 和 cost per successful task。

### 6. 实验工作簿与代码

五项实验统一见 [M10 实验工作簿](./M10-lab-workbook.md)，可运行计算器见仓库的 `examples/m10/README.md`。示例只模拟状态、预算、幂等和评测指标，不启动真实 Agent Runtime、外部工具或模型。

## 评分与教学一致性要求

- 评分项和分值逐条取自课程模块正式 Rubric；不改变原题、分值或课程内评分标准。
- 数学题写明单位、假设和舍入规则；架构题展示替代方案与故障边界；安全题将控制映射到执行组件和测试证据。
- 外部服务使用 mock/sandbox 时明确标注范围，不得将模拟通过描述为真实 provider 或生产验收。
- 允许其他等价方案，只要满足原始 Rubric 且证据充分。


### Runtime 与可观测性版本核验（2026-11-10）

- ReAct 论文展示 reasoning/action/observation 交替轨迹；生产审计应记录结构化动作、授权决策、工具结果和状态变化，不应把模型内部思维文本当作事实日志。
- Temporal Workflow replay 要求 Workflow 决策确定性；外部 I/O 放入 Activity，Activity 可能重试，必须幂等或先 reconcile。Replay 不等于重新执行外部副作用。
- LangGraph 当前文档区分 thread-scoped checkpointer 与跨 thread store，二者不是同一种持久化。
- OpenTelemetry GenAI Semantic Conventions 目前为 Development maturity，不能作为 Stable 字段契约；固定版本并管理 schema migration。
- AgentBench 当前 arXiv v3 于 2025-10 修订；τ-bench 用终态数据库与标注目标比较，并定义 pass^k 衡量多次试验一致性。
