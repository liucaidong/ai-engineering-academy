# M10 教师教学指南与作业参考解答

> 版本：0.20.0 · 适用模块：M10 Agent 基础与 Runtime  
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** Agent 是受 Runtime 约束的状态化控制循环；模型决策与确定性状态推进、权限执行、预算和停止条件必须分离。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** 状态机、事件循环、API 调用、权限模型、持久化和分布式任务基础
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Agent 基础与 Runtime 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Agent 基本模型与自主性边界

### 课前准备

- 复习：状态机、事件循环、API 调用、权限模型、持久化和分布式任务基础
- 预读主题：Agent 的工程定义、Agent、Workflow 与普通应用、自主性等级与权限边界、目标、约束和停止条件、复现练习：把自然语言目标转成可验证 Agent 契约。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 Agent 的工程定义、Agent、Workflow 与普通应用、自主性等级与权限边界，先定义对象、边界和数据流。
2. **工程深化：** 以 目标、约束和停止条件 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：把自然语言目标转成可验证 Agent 契约。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **对象与边界：** 能否说明参与方、状态、数据和责任归属？若把模型建议写成已执行状态，要求重画控制流。
- **机制与权衡：** 能否解释核心算法/协议及其成本？要求给出至少一个替代方案。
- **验证与失败：** 是否定义异常、权限拒绝、超时、恢复或人工接管？没有负向测试的设计不完整。

### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 将一个差旅报销助手拆分为 workflow 与 Agent 决策部分，定义状态、动作、观察、权限等级和停止条件。

**参考解答与推理：** 报销流程中，身份、票据字段、额度、政策版本、状态变更由 workflow 执行；Agent 处理票据解释、缺失信息澄清和异常分类。状态含 applicant、expense、policy_version、evidence、approval；动作分只读、草稿、提交、付款。付款不可由模型自主决定；预算、超时、拒绝条件和人工审批是停止边界。

**原始 Rubric 对照（满分 10 分）：**

- **系统抽象（3 分）：** 明确状态、观察、动作和环境反馈。要求提交物中有直接证据支持该项结论。

- **控制流取舍（3 分）：** 区分确定性步骤和模型决策步骤。要求提交物中有直接证据支持该项结论。

- **权限终止（4 分）：** 定义动作分级、预算和停止条件。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把 Agent 当成无限循环；模型输出“完成”就更新业务状态；恢复时盲目重放副作用；只隔离 Prompt 不隔离缓存/凭证/执行资源。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 为“查找订单并判断是否符合退款条件”设计 Agent loop 伪代码，包含状态更新、重复动作检测、超时和停止条件。

**参考解答与推理：** 循环：读取 state→模型提出 action→schema 校验→policy/ownership 授权→执行器带 deadline/idempotency_key 调用→记录 observation→更新 state/version→检测重复 action/循环→检查完成条件。超时后查询 operation status；达到步数、token、成本或总 deadline 即停止并交接，不能把模型的“完成”当作业务事实。

**原始 Rubric 对照（满分 10 分）：**

- **循环结构（4 分）：** 包含决策、校验、执行、观察和状态更新。要求提交物中有直接证据支持该项结论。

- **计划状态（2 分）：** 计划节点具有依赖和完成条件。要求提交物中有直接证据支持该项结论。

- **资源控制（4 分）：** 实现步数、调用次数、超时和循环检测。要求提交物中有直接证据支持该项结论。

### 正式作业参考解答

**原始作业：** 为一个多步骤采购 Agent 绘制状态机和事件表，定义 checkpoint 字段、恢复规则和并行依赖。

- **状态转移（3 分）：** 状态、事件、守卫和终止状态完整。要求提交物中有直接证据支持该项结论。

- **恢复设计（4 分）：** checkpoint 包含版本、步骤、预算和调用引用。要求提交物中有直接证据支持该项结论。

- **一致性（3 分）：** 处理副作用幂等和恢复前权限复核。要求提交物中有直接证据支持该项结论。
