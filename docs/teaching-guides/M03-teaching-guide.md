# M03 教师教学指南与作业参考解答

> 课程版本：0.21.0  
> 本指南对应课程中的五讲与五项正式评分作业；答案是示范性解法，不限制其他满足 Rubric 的方案。

## 教学定位与先修准备

- **模块主题：** Token、Embedding 与 Context
- **教学主线：** Tokenizer 与文本离散化 → Embedding 与向量表示 → Context Window 与 Token Budget → Context Engineering 与信息组织 → Tokenizer Lab 与综合审计
- **先修要求：** M01–M02；基本向量、矩阵、存储单位和消息/API 概念。
- **教师准备：** 为每讲准备成功案例、失败案例和输入/假设明确的练习材料。

## 五讲教学安排

| 讲次 | 主题 | 课堂目标 |
|---|---|---|
| 1 | Tokenizer 与文本离散化 | 建立 Unicode→UTF-8→token→token ID→embedding 的层次图。 |
| 2 | Embedding 与向量表示 | 比较 tokenizer 的训练/编码机制，强调模型与 tokenizer 必须匹配。 |
| 3 | Context Window 与 Token Budget | 推导 V×d 参数与 BF16 payload，画出 embedding 到 logits 的链路。 |
| 4 | Context Engineering 与信息组织 | 核算上下文预算，讨论截断、摘要、滑窗和 RAG 的信息损失。 |
| 5 | Tokenizer Lab 与综合审计 | 完成可复现的 token/context 审计，记录模板、来源、权限和质量回归。 |

## 第一讲：Tokenizer 与文本离散化

### 课前准备

- 阅读课程原文：一段文本经过了哪些表示层；词级、字符级与子词：三种切分策略的取舍；BPE：通过高频相邻片段合并构建词表；WordPiece、Unigram 与 Byte-level 设计；特殊 Token、Chat Template 与序列边界。
- 复习：M01–M02；基本向量、矩阵、存储单位和消息/API 概念。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 建立 Unicode→UTF-8→token→token ID→embedding 的层次图。
2. **机制拆解：** 讲解 一段文本经过了哪些表示层、词级、字符级与子词：三种切分策略的取舍、BPE：通过高频相邻片段合并构建词表，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“特殊 Token、Chat Template 与序列边界”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？
- **证据：** 是否保留原始输入、来源、版本、计算过程或测试记录？

### 课后复习

- 不看讲义重画本讲数据流、公式或系统边界图。
- 写出一个失败案例、根因、可观测信号和回归测试。
- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答

**课程原题：** 为一组中英混合、含代码、空白和 emoji 的输入设计 tokenizer 审计记录。说明从字符串到 token ID 的处理层次，比较至少两种子词算法，并列出复现切分结果所需的配置。

**参考答案与推理：** 记录原始输入字节/Unicode、规范化、预分词、算法/词表、特殊 token、输出 token 字符片段与 ID、解码回文本。比较 BPE 的迭代相邻符号对合并、WordPiece 的词片段评分/选择机制，或 Unigram 的子词概率模型；注明 byte-level 覆盖策略。复现必须固定模型/tokenizer 名称与版本、词表/merges 文件、normalizer、pre-tokenizer、特殊 token、add_prefix_space/截断/填充参数、Chat Template 版本和输入字节。字符数不能代替 token 数，emoji/代码/中英混合尤其如此。

**原始 Rubric 对照（总分 10 分）：**
- **表示层次（3 分）：** 正确区分 Unicode、UTF-8 字节、token 与 token ID。批改时检查提交物是否有可直接复核的证据。
- **算法比较（3 分）：** 准确比较 BPE 与 WordPiece 或 Unigram 的基本思想。批改时检查提交物是否有可直接复核的证据。
- **复现条件（2 分）：** 记录预处理、词表、版本、特殊 token 和模板。批改时检查提交物是否有可直接复核的证据。
- **语言覆盖（2 分）：** 解释多语言、代码和 emoji 切分不能按字符数推断。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

## 第二讲：Embedding 与向量表示

### 课前准备

- 阅读课程原文：Token ID 是索引，不是语义向量；Embedding 参数量与内存估算；Embedding 如何在训练中学习；输入 Embedding、输出投影与 Weight Tying；位置表示与上下文表示不是同一件事。
- 复习：M01–M02；基本向量、矩阵、存储单位和消息/API 概念。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 比较 tokenizer 的训练/编码机制，强调模型与 tokenizer 必须匹配。
2. **机制拆解：** 讲解 Token ID 是索引，不是语义向量、Embedding 参数量与内存估算、Embedding 如何在训练中学习，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“位置表示与上下文表示不是同一件事”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？
- **证据：** 是否保留原始输入、来源、版本、计算过程或测试记录？

### 课后复习

- 不看讲义重画本讲数据流、公式或系统边界图。
- 写出一个失败案例、根因、可观测信号和回归测试。
- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答

**课程原题：** 给定词表 V=48,000、embedding 维度 d=3,072、BF16 权重，计算 embedding 参数量和原始权重存储量；再画出 token ID、embedding lookup、Transformer hidden state 和输出 logits 的数据流，并解释 weight tying。

**参考答案与推理：** 参数量 V×d=48,000×3,072=147,456,000。BF16 每参数2 bytes，原始权重 payload=294,912,000 bytes=294.912 MB（十进制）≈281.25 MiB。实际加载还可能有对齐/运行时开销；训练还需梯度、优化器状态和激活。数据流：token ID→embedding lookup 得 [B,T,d]→位置处理/Transformer contextual hidden states→LM head 得 [B,T,V] logits→softmax/解码。Weight tying 让输入 embedding 矩阵与输出投影权重共享，减少独立参数并形成输入/输出词表空间联系，但不是所有架构都必须采用。

**原始 Rubric 对照（总分 10 分）：**
- **离散与连续表示（2 分）：** 明确区分 token ID 与 embedding vector。批改时检查提交物是否有可直接复核的证据。
- **参数计算（3 分）：** 正确计算 V×d 参数量和 BF16 存储量。批改时检查提交物是否有可直接复核的证据。
- **数据流（3 分）：** 正确表达输入 lookup、隐藏状态和输出投影。批改时检查提交物是否有可直接复核的证据。
- **权重共享（2 分）：** 说明 weight tying 的机制及其并非普遍必选。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

## 第三讲：Context Window 与 Token Budget

### 课前准备

- 阅读课程原文：Context Window 是一次模型调用可处理的序列范围；建立可复算的 Token Budget；一个逐步计算的超限案例；截断、滑动窗口、摘要与检索；上下文窗口不等于有效记忆。
- 复习：M01–M02；基本向量、矩阵、存储单位和消息/API 概念。
- 统一公式符号、张量维度、单位和示例输入。

### 教学路径与核心讲解

1. **问题引入：** 推导 V×d 参数与 BF16 payload，画出 embedding 到 logits 的链路。
2. **机制拆解：** 讲解 Context Window 是一次模型调用可处理的序列范围、建立可复算的 Token Budget、一个逐步计算的超限案例，要求学生说明每个对象的输入、输出和作用。
3. **工程连接：** 以“上下文窗口不等于有效记忆”为落点，讨论理论对系统设计、性能、可靠性或安全的影响。
4. **迁移练习：** 改变一个输入条件，让学生预测输出、形状、预算或风险，再用计算/证据验证。

### 学习检查点与教师提示

- **概念：** 能否解释关键对象并指出一个常见误解？
- **推导：** 是否写出中间步骤、单位和假设，而非只报最终数字？
- **边界：** 是否区分理论定义、具体实现、教学模拟和生产行为？

### 课后复习

- 不看讲义重画本讲数据流、公式或系统边界图。
- 写出一个失败案例、根因、可观测信号和回归测试。
- 将结论改写为至少一条可判定通过/失败的验收条件。

### 正式作业参考解答

**课程原题：** 为一个标称上下文上限 32,000 tokens 的模型请求设计预算表。必须纳入 system/developer、工具契约、用户消息、历史、RAG、工具返回、输出预留和安全余量；提供一次超限计算及压缩方案，并说明如何验证摘要/检索没有破坏关键约束。

**参考答案与推理：** 32,000-token 上限示例：system 1,000；developer 800；tool schema 2,000；user 1,200；history 10,000；RAG 12,000；tool return 4,000；output reserve 2,000；safety margin 1,000，总计34,000，超出2,000。先按任务重要性压缩历史1,500、RAG 1,000，再校验 tool contract 和用户约束，得到31,500，保留500额外余量。不能先删除系统/开发约束或授权信息。摘要质量用关键事实/实体/数字/约束覆盖测试；RAG 用证据 Recall@k、引用支持率和权限过滤回归验证。

**原始 Rubric 对照（总分 10 分）：**
- **预算完整性（3 分）：** 覆盖所有主要输入来源与输出预留。批改时检查提交物是否有可直接复核的证据。
- **计算准确性（3 分）：** 总量、超限值和调整后预算计算正确。批改时检查提交物是否有可直接复核的证据。
- **压缩策略（2 分）：** 选择合理的截断、摘要或检索策略并说明代价。批改时检查提交物是否有可直接复核的证据。
- **质量验证（2 分）：** 检查约束保留、证据召回和来源可追溯性。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

### 正式作业参考解答

**课程原题：** 为企业知识助手设计 Context Assembly Pipeline。必须包含消息序列化、来源标注、权限过滤、RAG、token 预算、模板版本、冲突处理和审计字段；说明哪些内容属于不可信数据。

**参考答案与推理：** Pipeline：可信身份→消息规范化/模板版本→来源登记→租户/对象 ACL 过滤→查询改写→稀疏/向量召回→融合/重排→去重和冲突标注→token 预算→按信任等级序列化→模型生成→引用/格式校验→审计。每个片段保留 source_ref、document/version、page/offset、timestamp、ACL、trust_level。用户上传文件、网页、检索片段和工具结果默认是不可信数据，其中的指令不能覆盖 system/developer policy；ACL 必须在服务端执行，不能让模型决定。

### 正式作业参考解答

**课程原题：** 提交一份 Token 与 Context 综合审计报告：记录 Tokenizer 实验、真实 tokenizer 核验计划、embedding 参数估算、24,000-token 请求预算、超限调整和压缩前后质量验证。

**参考答案与推理：** 24,000-token 审计例：system 1,000、developer 1,000、tool schema 2,000、user 1,000、history 7,000、RAG 8,000、tool return 3,000、output reserve 3,000、margin 1,000，总计27,000，超限3,000。压缩 history 1,500、RAG 1,500，得到24,000；若服务实际把模板/特殊 token 计入额外开销，则需再留余量而非贴边。报告附 tokenizer 与模板版本、分项计数、裁剪前后内容摘要、保留约束清单、证据引用、质量回归结果和实际接口计量对照。

**原始 Rubric 对照（总分 10 分）：**
- **实验记录与边界（2 分）：** 完整记录 toy BPE 合并，并明确不等同于真实厂商 tokenizer。批改时检查提交物是否有可直接复核的证据。
- **表示链路（2 分）：** 正确区分文本、token、ID、embedding 和上下文隐藏状态。批改时检查提交物是否有可直接复核的证据。
- **参数估算（2 分）：** 参数量、字节数和单位换算正确。批改时检查提交物是否有可直接复核的证据。
- **预算与超限处理（2 分）：** 预算分项完整，超限计算和压缩顺序合理。批改时检查提交物是否有可直接复核的证据。
- **验证与可追溯性（2 分）：** 定义事实保持检查并记录模型、tokenizer、模板和数据版本。批改时检查提交物是否有可直接复核的证据。

**常见错误与纠正：**
- 只给结论，不展示输入、假设、单位和中间步骤；要求补全推导。
- 把概念类比当作严格机制；要求指出类比适用范围和失效条件。
- 把模拟、推测或设计意图写成真实系统事实；要求标注证据等级。
- 只覆盖正常路径，忽略异常、权限拒绝、边界值和恢复路径。

## 教师批改与反馈总则

- 逐条按原始 Rubric 评分，不改变权重；每项反馈指出证据所在位置。
- 数值题检查公式、代入、单位、舍入和数量级。
- 架构题审查职责边界、信任边界、失败路径、可观测性和运维闭环。
- 开放题接受等价方案，但要求说明假设、替代方案和权衡。
- 所有实验按课程 Lab Registry 声明的执行模式理解；不得暗示真实模型推理或 GPU 性能测试。
