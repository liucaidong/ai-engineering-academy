# M14 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 多 Agent 只有在任务可分解、并行收益或独立验证价值超过协调成本时才成立；多数投票不能替代证据。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。



## 标准基线与教学补充（0.33.0）

M14 的多 Agent 架构不绑定单一框架。建议使用官方材料对照不同实现的概念与边界：

- Anthropic《Building Effective Agents》：routing、parallelization、orchestrator-worker、evaluator-optimizer 的适用条件。
- Anthropic《How we built our multi-agent research system》：并行 subagents、任务边界、artifact handoff、上下文管理和观测。
- OpenAI Agents SDK：Agents as tools 与 handoffs 的控制权差异；内建 trace/task/turn/agent/generation/function/guardrail/handoff spans，以及敏感数据采集、脱敏和 ZDR 限制。Artifact 生命周期需要自定义 span。
- A2A Protocol v1.0.1：`supportedInterfaces`、三种核心 binding、TaskState、Message/Part/Artifact 和 `A2A-Version`。
- Microsoft AutoGen SelectorGroupChat：动态 speaker selection、共享会话上下文和显式 termination conditions。
- Dynamo 论文：最终一致性、版本向量和冲突协调的分布式系统基础。

**协议边界：** 内部 Multi-Agent Runtime 的 Task/Result 消息属于应用内部合同；A2A 用于不同 Agent Runtime 之间的远程互操作；MCP 主要连接模型与工具/资源/提示上下文。三者可以组合，但不能互相替代。

**评测边界：** 多个 Agent 的输出不自动构成独立样本。若模型、提示、工具或数据源相同，错误可能高度相关。多数票、共识或自评不能代替独立证据、确定性检查和真实任务对照实验。Chandy–Lamport 支持分布式全局状态快照概念，Dynamo 支持版本向量/冲突协调；不要把快照算法直接等同于数据库 CAS 或 CRDT。

## 模块先修与教学准备

- **先修知识：** 分布式系统、消息队列、并发控制、证据评估、成本模型和实验设计
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Multi-Agent 协作系统 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：Multi-Agent 协作模型与适用边界

### 课前准备

- 复习：分布式系统、消息队列、并发控制、证据评估、成本模型和实验设计
- 预读主题：多 Agent 不等于更聪明、Manager/Worker 拓扑、Peer 与流水线拓扑、采用多 Agent 的判据、Topology Decision Matrix 与协调税模型、复现练习：用单 Agent Baseline 决定是否采用 Multi-Agent。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 多 Agent 不等于更聪明、Manager/Worker 拓扑、Peer 与流水线拓扑，先定义对象、边界和数据流。
2. **工程深化：** 以 采用多 Agent 的判据 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：用单 Agent Baseline 决定是否采用 Multi-Agent。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「多 Agent 不等于更聪明」与「Manager/Worker 拓扑」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「Peer 与流水线拓扑」与「采用多 Agent 的判据」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：用单 Agent Baseline 决定是否采用 Multi-Agent」和「Topology Decision Matrix 与协调税模型」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 对市场研究、代码审查和订单退款三个任务分别选择单 Agent、Manager/Worker、Peer 或流水线，并解释成本与风险。

**参考解答与推理：** 市场研究适合 Manager/Worker 或并行研究后综合；代码审查可由独立 reviewer 并行，但需统一 diff/commit 基线；订单退款优先确定性 workflow+单 Agent 辅助解释，不应让多个 Agent 讨论后决定付款。比较依赖、并行性、可验证性、通信成本和副作用风险。

**原始 Rubric 对照（满分 10 分）：**

- **拓扑理解（3 分）：** 正确比较至少三种拓扑。要求提交物中有直接证据支持该项结论。

- **任务匹配（4 分）：** 基于依赖、并行性和独立验证做选择。要求提交物中有直接证据支持该项结论。

- **成本风险（3 分）：** 考虑通信、延迟、冲突和终止。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 默认 Agent 越多越好；只比较回答质量不比较成本；共享状态 last-write-wins；多数票替代独立证据；重派任务导致重复副作用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

- **核心机制：** 围绕「单 Agent Baseline」与「成本与延迟模型」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「协作可靠性指标」与「上线门槛」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：计算多 Agent 的单位成功成本」和「实验设计与可观测性：Cost per Successful Task」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 设计单 Agent 与 4-Agent 研究团队的对照 benchmark，计算成本/成功任务并定义延迟、冲突和安全门槛。

**参考解答与推理：** 单 Agent 与4-Agent 对照需固定任务集、模型版本、工具权限、总 token/时间预算和成功标准。单位成功成本=全部模型/工具/重试成本÷成功任务数；同时报告 p50/p95、重复工作率、冲突率、人工接管和越权率。增益不足以覆盖成本/延迟则回退单 Agent。

**原始 Rubric 对照（满分 10 分）：**

- **对照公平（3 分）：** 任务集、模型/工具和预算基线明确。要求提交物中有直接证据支持该项结论。

- **成本分析（3 分）：** 计入所有 Agent、重试和工具成本。要求提交物中有直接证据支持该项结论。

- **可靠性（4 分）：** 包含冲突、死锁、权限和人工接管指标。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 默认 Agent 越多越好；只比较回答质量不比较成本；共享状态 last-write-wins；多数票替代独立证据；重派任务导致重复副作用。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 跨模块衔接补充：从单 Agent 状态到多 Agent 协作

### 先修诊断（进入本模块前）
- 让学习者重画 M10 的 Agent 状态机和 M11 的任务 DAG/Memory 边界。
- 要求先定义单 Agent baseline 的任务成功条件、失败分类、token/延迟成本和人工接管率。

### 过渡实验
将一个供应商尽调任务分别实现为单 Agent 与 Manager/Worker 两种设计。先固定任务集和成功判定，再测量调用数、重复工作、端到端延迟、证据独立性和人工复核成本。无法执行真实模型时可用确定性模拟，但必须标记 E2，不得推断真实模型表现。

### 进入后续课程的交付门
只有当多 Agent 方案相对单 Agent baseline 的质量/成本净收益可说明，且共享状态具有版本冲突处理、写入所有权和证据来源时，才建议采用多 Agent。否则推荐保留单 Agent 或确定性 Workflow。
