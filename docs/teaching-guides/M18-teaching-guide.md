# M18 教师教学指南与作业参考解答

> 版本：0.20.0 · 适用模块：M18 AI Platform 架构  
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 平台需划分控制平面与数据平面；身份、租户、配额、密钥和策略由服务端权威执行。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** 多租户架构、网关、限流算法、密钥管理、队列、SLO 与灾备
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** AI Platform 架构 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：AI 平台边界与分层架构

### 课前准备

- 复习：多租户架构、网关、限流算法、密钥管理、队列、SLO 与灾备
- 预读主题：平台与单个 AI 应用、控制平面与数据平面、多租户层级、平台 API 与契约、复现练习：绘制多租户 AI 平台控制/数据平面边界。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 平台与单个 AI 应用、控制平面与数据平面、多租户层级，先定义对象、边界和数据流。
2. **工程深化：** 以 平台 API 与契约 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：绘制多租户 AI 平台控制/数据平面边界。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **对象与边界：** 能否说明参与方、状态、数据和责任归属？若把模型建议写成已执行状态，要求重画控制流。
- **机制与权衡：** 能否解释核心算法/协议及其成本？要求给出至少一个替代方案。
- **验证与失败：** 是否定义异常、权限拒绝、超时、恢复或人工接管？没有负向测试的设计不完整。

### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 绘制多租户 AI 平台控制平面/数据平面架构，标出身份、模型网关、配额、密钥、观测和应用责任边界。

**参考解答与推理：** 控制平面负责租户/用户/策略/模型目录/配额配置/密钥生命周期；数据平面处理认证、策略决策、路由、推理、计量和审计。租户身份从可信认证上下文派生，不信任客户端 tenant_id。应用负责业务语义，平台负责共享能力和隔离。

**原始 Rubric 对照（满分 10 分）：**

- **平面划分（3 分）：** 控制与数据平面职责清晰。要求提交物中有直接证据支持该项结论。

- **租户边界（4 分）：** 身份派生和资源隔离明确。要求提交物中有直接证据支持该项结论。

- **契约治理（3 分）：** 接口版本、幂等、限流和密钥保护完整。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 信任客户端 tenant_id；fallback 忽略能力/数据区域；把 token 估算当供应商账单；策略服务故障时 fail open；没有故障域与恢复演练。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 设计租户 RPM/TPM/并发/日预算策略，并计算 10k 输入、2k 输出在给定单价下的费用，说明重试与缓存如何计量。

- **成本计算（3 分）：** 正确算出 0.036 并标注价目版本。要求提交物中有直接证据支持该项结论。

- **计量对账（4 分）：** 区分估算、供应商 usage 和其他资源费用。要求提交物中有直接证据支持该项结论。
