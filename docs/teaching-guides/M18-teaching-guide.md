# M18 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 平台需划分控制平面与数据平面；身份、租户、配额、密钥和策略由服务端权威执行。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。



## 标准基线与教学补充（0.40.8）

M18 以云原生控制平面、AI Gateway、多租户 SaaS 隔离、用量事件和 SRE 过载治理为工程基线：

- Kubernetes Cluster Architecture：控制平面、API Server、Scheduler、Controller Manager 和 Node 的职责边界；平台配置/控制不应与请求热路径耦合。
- Envoy Gateway Rate Limiting：Local 与 Global 限流的差异、共享配额和路由级限流策略。
- AWS Well-Architected SaaS Lens：Silo、Pool、Bridge 模型可按服务层和风险等级组合。
- OpenMeter Usage Events：基于 CloudEvents 的 usage ingestion、source/id 去重和用量聚合；同一 source/id 的 payload 冲突必须拒绝。
- NIST SP 800-57 Part 1 Rev.5：当前最终版；Rev.6 仍是 IPD，不能当成最终标准。
- Google SRE《Handling Overload》：准入控制、降级、负载均衡和过载保护。

**平台架构原则：** tenant context 必须由可信身份派生并贯穿请求、队列、缓存、向量检索、对象存储、日志和计量；客户端 header 不是租户身份凭证。控制平面发布版本化策略快照，数据平面在请求路径强制执行。

**计量原则：** quota reservation、provider usage settlement、ledger、price version 和账单对账是不同步骤。事件去重键使用 source+id；同一 key 的不同 payload 是冲突。金额用 Decimal（禁止先转 float），价格绑定 provider/model/region/price_version/currency；按版本化 ISO 4217 minor unit 和明确 rounding policy 量化，不可假定所有币种都是两位小数。内部 Tokenizer 估算应明确标注，不得冒充供应商账单。

**教学边界：** Local/Global rate limit 的具体实现和路由粒度依赖网关版本；Silo/Pool/Bridge 是部署模型而非安全等级的自动排序。Kubernetes namespace 不是强安全边界；私有缓存 key 必须绑定 tenant、principal、resource version 和 policy version，并对每个分隔符组件做无歧义编码。最终选择需结合数据敏感性、合规、成本和运维能力。

## 第一讲：AI 平台边界与分层架构

### 课前准备

- 复习：多租户架构、网关、限流算法、密钥管理、队列、SLO 与灾备
- 预读主题：平台与单个 AI 应用、控制平面与数据平面、多租户层级、平台 API 与契约、Desired State Reconciliation 与配置快照、复现练习：绘制多租户 AI 平台控制/数据平面边界。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 平台与单个 AI 应用、控制平面与数据平面、多租户层级，先定义对象、边界和数据流。
2. **工程深化：** 以 平台 API 与契约 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：绘制多租户 AI 平台控制/数据平面边界。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「平台与单个 AI 应用」与「控制平面与数据平面」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「多租户层级」与「平台 API 与契约」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：绘制多租户 AI 平台控制/数据平面边界」和「Desired State Reconciliation、配置快照与平面隔离」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 绘制多租户 AI 平台控制平面/数据平面架构，标出身份、模型网关、配额、密钥、观测和应用责任边界。

**参考解答与推理：** 控制平面负责租户/用户/策略/模型目录/配额配置/密钥生命周期；数据平面处理认证、策略决策、路由、推理、计量和审计。租户身份从可信认证上下文派生，不信任客户端 tenant_id。应用负责业务语义，平台负责共享能力和隔离。

**原始 Rubric 对照（满分 10 分）：**

- **平面划分（3 分）：** 控制与数据平面职责清晰。要求提交物中有直接证据支持该项结论。

- **租户边界（4 分）：** 身份派生和资源隔离明确。要求提交物中有直接证据支持该项结论。

- **契约治理（3 分）：** 接口版本、幂等、限流和密钥保护完整。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 信任客户端 tenant_id；fallback 忽略能力/数据区域；把 token 估算当供应商账单；策略服务故障时 fail open；没有故障域与恢复演练。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

3. **实践复现：** 复现练习：进行一次 Model Gateway 故障域与 SLO 评审。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「故障域与依赖图」与「队列、弹性和隔离」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「灾备与恢复目标」与「平台 SLO 与架构验收」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：进行一次 Model Gateway 故障域与 SLO 评审」和「Fair Scheduling、Overload Control 与 Capacity Headroom」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为多租户 Model Gateway 制定故障域图、队列/熔断策略、RTO/RPO 和平台 SLO 验收表。

**参考解答与推理：** 故障域覆盖 DNS/网络、身份、策略、队列、provider、计量和数据库；队列实施背压、优先级、隔离池和熔断。定义 RTO/RPO 并演练区域故障、provider 故障和密钥泄露。SLO 覆盖可用性、P95、路由正确、租户隔离、计量差异和安全事件。

**原始 Rubric 对照（满分 10 分）：**

- **故障分析（3 分）：** 识别关键依赖和级联路径。要求提交物中有直接证据支持该项结论。

- **弹性灾备（3 分）：** 定义背压、熔断、RTO/RPO 和演练。要求提交物中有直接证据支持该项结论。

- **SLO（4 分）：** 覆盖可用性、延迟、隔离、计量和路由。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 信任客户端 tenant_id；fallback 忽略能力/数据区域；把 token 估算当供应商账单；策略服务故障时 fail open；没有故障域与恢复演练。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 跨模块衔接补充：从推理服务和评测走向平台工程

### 先修诊断（进入本模块前）
- 复习 M05 的 KV/并发/队列/容量预算，确认学习者能区分请求数、输入 token、输出 token、并发和实际 GPU 内存。
- 复习 M17 的 SLI/SLO、指标分母、质量回归和 Trace/Metric/Log 隐私边界。

### 过渡实验
为两个租户设计 Model Gateway：定义能力路由、RPM/TPM/并发配额、请求优先级、成本归因、usage reservation/settlement 和过载拒绝。用同一组请求模拟突发流量，检查公平性、配额超限、重复 usage event 和模型 fallback 是否破坏质量/数据政策约束。

### 进入后续课程的交付门
平台设计必须明确控制平面与数据平面、租户身份来源、计量事件幂等、容量故障域和 SLO。不能将客户端声明的 tenant ID 当作可信授权，也不能把 provider usage、内部 tokenizer 估算和账单结算混为同一数字。
