# M11 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 计划、运行状态、上下文、长期记忆与知识库是不同对象；记忆必须有来源、时效、权限、纠错和删除传播。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** DAG、数据库事务、检索排序、数据生命周期、审批状态和隐私删除
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Planning、Memory 与状态 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：任务分解与计划表示

### 课前准备

- 复习：DAG、数据库事务、检索排序、数据生命周期、审批状态和隐私删除
- 预读主题：目标规格化、线性计划与 DAG、计划生成与验证、动态重规划、复现练习：将供应商尽调目标编译成任务 DAG。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 目标规格化、线性计划与 DAG、计划生成与验证，先定义对象、边界和数据流。
2. **工程深化：** 以 动态重规划 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：将供应商尽调目标编译成任务 DAG。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「目标规格化」与「线性计划与 DAG」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「计划生成与验证」与「动态重规划」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：将供应商尽调目标编译成任务 DAG」和「从自然语言计划到可验证的形式化问题」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 把供应商尽调任务建模为 DAG，至少 8 个节点，标出并行路径、依赖、完成条件和重规划规则。

**参考解答与推理：** 供应商尽调 DAG：定义范围→识别供应商→收集公司资料/制裁信息/财务资料（并行）→来源核验→交叉比对→风险评分→人工复核→报告发布。每节点有输入输出、owner、完成条件和失败策略；新证据推翻假设时只重算受影响下游节点，保留旧计划版本。

**原始 Rubric 对照（满分 10 分）：**

- **分解质量（3 分）：** 目标拆分完整且每步有输入输出。要求提交物中有直接证据支持该项结论。

- **依赖建模（3 分）：** DAG 无环且并行关系正确。要求提交物中有直接证据支持该项结论。

- **验证恢复（4 分）：** 包含权限、前置条件和重规划策略。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把上下文、状态、记忆和知识库混为一谈；无来源写入长期记忆；冲突时覆盖；删除只删主表不删派生索引；审批不绑定参数。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 第二讲：Memory 类型与存储边界

### 课前准备

- 复习：DAG、数据库事务、检索排序、数据生命周期、审批状态和隐私删除
- 预读主题：四种不同的记忆对象、短期与长期记忆、读写策略、遗忘、修正与删除、复现练习：制定 Agent Memory 写入与读取策略。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 四种不同的记忆对象、短期与长期记忆、读写策略，先定义对象、边界和数据流。
2. **工程深化：** 以 遗忘、修正与删除 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：制定 Agent Memory 写入与读取策略。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「四种不同的记忆对象」与「短期与长期记忆」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。

- **验证与失效：** 围绕「复现练习：制定 Agent Memory 写入与读取策略」和「Memory Record Schema：来源、时间、范围与可撤销性」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为个人研究 Agent 设计短期状态与长期记忆策略，定义写入门槛、来源、TTL、冲突解决和删除传播。

**参考解答与推理：** 短期 state 存放当前任务进度、临时变量和 checkpoint，任务结束按策略清理；长期 memory 只保存经过验证、可复用且获准持久化的信息。记录 source、owner、created_at、expires_at、confidence、sensitivity、consent、version。冲突不简单覆盖，比较来源/时间并标记待确认；删除传播到索引、摘要、缓存和派生副本。

**原始 Rubric 对照（满分 10 分）：**

- **类型边界（3 分）：** 区分上下文、状态、记忆和知识库。要求提交物中有直接证据支持该项结论。

- **生命周期（4 分）：** 定义写入、读取、验证、TTL 和冲突。要求提交物中有直接证据支持该项结论。

- **隐私删除（3 分）：** 覆盖敏感信息、删除和派生索引。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把上下文、状态、记忆和知识库混为一谈；无来源写入长期记忆；冲突时覆盖；删除只删主表不删派生索引；审批不绑定参数。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 设计一个采购审批 Agent 的等待/批准/拒绝状态机，定义审批参数绑定、过期、恢复复核和反馈记忆规则。

**参考解答与推理：** 审批状态 waiting→approved/rejected/expired/revoked；绑定 approver、主体、资源 ID、动作、金额/参数摘要 hash、policy version 和过期时间。恢复时重新认证并检查权限、参数 hash 和业务状态；任何参数变化需重新审批。反馈仅在用户明确授权且非敏感、可长期复用时进入记忆。

**原始 Rubric 对照（满分 10 分）：**

- **HITL 状态（3 分）：** 定义触发条件和审批状态转移。要求提交物中有直接证据支持该项结论。

- **防篡改（4 分）：** 审批绑定主体、资源和参数摘要。要求提交物中有直接证据支持该项结论。

- **恢复与记忆（3 分）：** 恢复时复核权限且不擅自持久化敏感信息。要求提交物中有直接证据支持该项结论。

### 正式作业参考解答

**原始作业：** 为长期运行的研究 Agent 设计规划/记忆评测基准，提交数据集结构、指标、四类故障注入和发布门槛。

**参考解答与推理：** 规划评测与记忆评测分开：计划看依赖正确率、完成率、重规划代价、无效节点；记忆看 precision/recall、时效性、冲突检测、删除传播和租户隔离。故障注入覆盖撤权、来源过期、矛盾事实、删除请求、checkpoint 恢复。

**原始 Rubric 对照（满分 10 分）：**

- **基准任务（3 分）：** 覆盖计划执行、记忆读写和更正。要求提交物中有直接证据支持该项结论。

- **指标体系（3 分）：** 计划质量和记忆质量指标分离。要求提交物中有直接证据支持该项结论。

- **安全恢复（4 分）：** 覆盖撤权、冲突、删除和恢复。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把上下文、状态、记忆和知识库混为一谈；无来源写入长期记忆；冲突时覆盖；删除只删主表不删派生索引；审批不绑定参数。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 进阶概念辨析与课堂扩展

### 1. 从自然语言目标到形式化计划

计划应表示为动作、前置条件、效果、成本和资源约束，而不只是自然语言步骤列表。LLM+P 展示了自然语言到 PDDL、再由经典规划器求解的协同方式；其正确性取决于输入问题模型是否完整。课堂要求学生检查初始条件、动作参数、依赖 DAG、资源/时间约束和目标可达性，并区分模型翻译错误与规划器搜索错误。

### 2. Memory Record 的来源与时间语义

长期记忆必须保留 source_event_ids、主体/租户范围、类型、confidence、sensitivity、consent basis、valid_from/valid_until、recorded_at、version、supersedes 和 deletion status。区分“用户曾经说过”“现在仍然成立”和“模型推断”三种证据。用户偏好、项目状态和事实会变化，必须支持更新、过期、纠正、撤销和派生记录删除。

### 3. 检索、反思与记忆巩固

记忆检索可综合 relevance、recency、salience、frequency、confidence 和 task utility，但要说明排序权重和任务适用范围。Generative Agents 展示 memory stream、reflection 和动态 retrieval；MemGPT 展示上下文与外部记忆层之间的虚拟分页。摘要和反思必须保留原始事件引用、时间范围和冲突标记，避免将模型生成的摘要当成独立事实来源。

### 4. Human Approval 与 Memory Governance

审批记录应绑定 actor、tenant、task_id、action_digest、resource scope、state_version、policy_version 和 expires_at。执行前必须重算 digest 并验证状态未变化；审批不是永久 capability。记忆写入需要用途和来源审查；纠错应形成 superseding record；删除应传播到摘要、向量索引、缓存和派生记忆。

### 5. Planning/Memory 的分离评测

Planning 评测关注 goal completion、plan feasibility、precondition violation、dependency correctness、replan frequency 和 execution deviation。Memory 评测关注 write precision、retrieval recall/precision、temporal accuracy、knowledge-update accuracy、stale-memory rate、abstention 和 deletion compliance。LongMemEval 与 LoCoMo 可作为长时记忆基准参考，但需要加入目标用户群、领域和隐私策略相关的自有回归集。

### 6. 实验工作簿与代码

五项实验统一见 [M11 实验工作簿](./M11-lab-workbook.md)，可运行计算器见仓库的 `examples/m11/README.md`。示例仅模拟 DAG、记忆记录、检索排序、审批摘要和评测指标，不连接真实向量数据库或长期记忆服务。

## 评分与教学一致性要求

- 评分项和分值逐条取自课程模块正式 Rubric；不改变原题、分值或课程内评分标准。
- 数学题写明单位、假设和舍入规则；架构题展示替代方案与故障边界；安全题将控制映射到执行组件和测试证据。
- 外部服务使用 mock/sandbox 时明确标注范围，不得将模拟通过描述为真实 provider 或生产验收。
- 允许其他等价方案，只要满足原始 Rubric 且证据充分。


### Planning/Memory 来源与基准边界（2026-11-10）

- Tree of Thoughts v2（2023-12）在 Game of 24、创意写作和迷你填字等特定任务验证搜索式思考；不能外推为任意任务都提升。Plan-and-Solve 是“先规划、再执行子任务”的 prompting 方法，不是形式化最优规划器。LLM+P 才是把自然语言转换为 PDDL 并调用经典 planner；翻译错误会导致“对错误世界模型的最优计划”。
- MemGPT 的 virtual context management 通过内外存储层之间的数据迁移扩展有效上下文；它不意味着无限记忆或无损摘要。Mem0 的 arXiv 论文由 Mem0 团队作者撰写，26% judge 提升、91% p95 latency 降低和 90% token 节省是作者 benchmark 结果，不能当作独立第三方结论，教学中应要求在自有 workload 复现。
- LongMemEval v2（2025-03）有 500 个问题，覆盖信息抽取、多会话推理、时间推理、知识更新和拒答五项能力。LoCoMo 对话平均约 300 turns/9K tokens、最多 35 sessions，并包含图像/多模态任务；两套 benchmark 不可互换。
- NIST AI RMF 1.0（2023-01）仍是已发布框架，但 NIST 当前正在修订；2026-04 发布了关键基础设施 Trustworthy AI Profile concept note。引用时区分 AI RMF 1.0 与后续 profile/revision。
- AgentBench 当前 arXiv v3（2025-10）；τ-bench 的 pass^k 受 retail/airline policy、用户模拟器和运行次数影响，不能直接当作生产环境成功率。
