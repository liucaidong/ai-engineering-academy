# M11 教师教学指南与作业参考解答

> 版本：0.20.0 · 适用模块：M11 Planning、Memory 与状态  
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 计划、运行状态、上下文、长期记忆与知识库是不同对象；记忆必须有来源、时效、权限、纠错和删除传播。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。

## 模块先修与教学准备

- **先修知识：** DAG、数据库事务、检索排序、数据生命周期、审批状态和隐私删除
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** Planning、Memory 与状态 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：任务分解与计划表示

### 课前准备

- 复习：DAG、数据库事务、检索排序、数据生命周期、审批状态和隐私删除
- 预读主题：目标规格化、线性计划与 DAG、计划生成与验证、动态重规划、复现练习：将供应商尽调目标编译成任务 DAG。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 目标规格化、线性计划与 DAG、计划生成与验证，先定义对象、边界和数据流。
2. **工程深化：** 以 动态重规划 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：将供应商尽调目标编译成任务 DAG。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **对象与边界：** 能否说明参与方、状态、数据和责任归属？若把模型建议写成已执行状态，要求重画控制流。
- **机制与权衡：** 能否解释核心算法/协议及其成本？要求给出至少一个替代方案。
- **验证与失败：** 是否定义异常、权限拒绝、超时、恢复或人工接管？没有负向测试的设计不完整。

### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 把供应商尽调任务建模为 DAG，至少 8 个节点，标出并行路径、依赖、完成条件和重规划规则。

**参考解答与推理：** 供应商尽调 DAG：定义范围→识别供应商→收集公司资料/制裁信息/财务资料（并行）→来源核验→交叉比对→风险评分→人工复核→报告发布。每节点有输入输出、owner、完成条件和失败策略；新证据推翻假设时只重算受影响下游节点，保留旧计划版本。

**原始 Rubric 对照（满分 10 分）：**

- **分解质量（3 分）：** 目标拆分完整且每步有输入输出。要求提交物中有直接证据支持该项结论。

- **依赖建模（3 分）：** DAG 无环且并行关系正确。要求提交物中有直接证据支持该项结论。

- **验证恢复（4 分）：** 包含权限、前置条件和重规划策略。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把上下文、状态、记忆和知识库混为一谈；无来源写入长期记忆；冲突时覆盖；删除只删主表不删派生索引；审批不绑定参数。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 第二讲：Memory 类型与存储边界

### 课前准备

- 复习：DAG、数据库事务、检索排序、数据生命周期、审批状态和隐私删除

- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

2. **工程深化：** 以 遗忘、修正与删除 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：制定 Agent Memory 写入与读取策略。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为个人研究 Agent 设计短期状态与长期记忆策略，定义写入门槛、来源、TTL、冲突解决和删除传播。

**参考解答与推理：** 短期 state 存放当前任务进度、临时变量和 checkpoint，任务结束按策略清理；长期 memory 只保存经过验证、可复用且获准持久化的信息。记录 source、owner、created_at、expires_at、confidence、sensitivity、consent、version。冲突不简单覆盖，比较来源/时间并标记待确认；删除传播到索引、摘要、缓存和派生副本。

**原始 Rubric 对照（满分 10 分）：**

- **类型边界（3 分）：** 区分上下文、状态、记忆和知识库。要求提交物中有直接证据支持该项结论。

- **生命周期（4 分）：** 定义写入、读取、验证、TTL 和冲突。要求提交物中有直接证据支持该项结论。

- **隐私删除（3 分）：** 覆盖敏感信息、删除和派生索引。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 把上下文、状态、记忆和知识库混为一谈；无来源写入长期记忆；冲突时覆盖；删除只删主表不删派生索引；审批不绑定参数。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 设计一个采购审批 Agent 的等待/批准/拒绝状态机，定义审批参数绑定、过期、恢复复核和反馈记忆规则。

**参考解答与推理：** 审批状态 waiting→approved/rejected/expired/revoked；绑定 approver、主体、资源 ID、动作、金额/参数摘要 hash、policy version 和过期时间。恢复时重新认证并检查权限、参数 hash 和业务状态；任何参数变化需重新审批。反馈仅在用户明确授权且非敏感、可长期复用时进入记忆。

**原始 Rubric 对照（满分 10 分）：**

- **HITL 状态（3 分）：** 定义触发条件和审批状态转移。要求提交物中有直接证据支持该项结论。

- **防篡改（4 分）：** 审批绑定主体、资源和参数摘要。要求提交物中有直接证据支持该项结论。

- **恢复与记忆（3 分）：** 恢复时复核权限且不擅自持久化敏感信息。要求提交物中有直接证据支持该项结论。
