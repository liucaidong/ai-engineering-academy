# M15 教师教学指南与作业参考解答

> 课程版本：0.40.9

> **证据评阅：** 教师应按[全课程证据等级](../CURRICULUM_EVIDENCE_LEVELS.md)区分设计、静态审阅、模拟/Mock、本地测试、目标环境测试和生产观测；只为实际覆盖范围授予等级。

>
> 用于教师备课、助教批改和学生复习；参考解答不是唯一可接受答案。

## 使用方式

- 建议每讲 75–90 分钟；先从真实案例提出问题，再推导机制，最后审阅工程证据。
- 课前让学生写下假设；课堂结束前提交公式、架构图、状态图、测试记录或决策日志。
- **教学主线：** 安全工作从资产与信任边界出发，把威胁映射到服务端控制、可执行测试、责任人和事件闭环。
- 评分先检查边界、假设、单位、失败路径和证据，再检查表达完整性。



## 标准基线与教学补充（0.34.0）

M15 的安全体系应采用 threat-informed 与 risk-based 方法，避免将“安全 Prompt”当作唯一控制。

- MITRE ATLAS：动态的 AI 对抗战术/技术知识库，特别关注 Agent Tool Invocation、Context Poisoning、Prompt Injection、Credential Access 和 Exfiltration。
- OWASP Top 10 for Agentic Applications 2026：Agent 目标劫持、工具滥用、身份/权限滥用、记忆/上下文污染、级联失效等风险。
- NIST SP 800-162 Update 2：ABAC 的主体、对象、操作和环境属性决策模型；与 RBAC 角色基线互补。
- NIST SP 800-207：零信任架构，使用 PE/PA/PEP 组件，不因网络位置或资产所有权隐式信任主体。
- NIST AI 600-1：生成式 AI 风险管理、信息完整性、人工监督和可信性；AI RMF 1.0 仍在修订，Playbook 是自愿建议而非 checklist。
- NIST Privacy Framework 1.0 是当前发布版；1.1 仍为 Initial Public Draft。
- NIST SP 800-53 Release 5.2.0（2025-08-27）已发布；该次更新未改变 SP 800-53B control baselines。
- EU AI Act 应按 2026-07-27 合并文本判断招聘/筛选等 Annex III 高风险用途；一般适用日期 2026-08-02、Annex III 适用日期 2027-12-02、Annex I 产品相关高风险适用日期 2028-08-02。
- MITRE ATLAS OpenClaw Investigation：Agent 配置、凭证、工具调用、间接注入和攻击链分析的真实案例研究。

**授权设计原则：** 通用 PDP/PEP 模型用于解释决策/执行分离；NIST SP 800-207 具体使用 PE/PA/PEP，PE 决策、PA 管理通信路径、PEP 执行。RBAC/ABAC/ReBAC 可组合，但所有授权必须绑定 principal、tenant、resource、action、environment 和 policy version。人工审批必须绑定具体参数和资源版本，且不能代替服务端授权。

**教学边界：** STRIDE、ATLAS、OWASP、NIST 是不同层次的框架/知识库，不能相互替代；课程中的 STRIDE↔ATLAS 映射和 1–5 风险阈值是教学启发式/组织自定义规则，不是官方 crosswalk 或客观概率。NIST AI RMF 1.0 正在修订，Privacy Framework 1.1 仍是 IPD；真实部署需结合行业规则和法务/隐私审查。

## 模块先修与教学准备

- **先修知识：** STRIDE、数据流图、身份认证、RBAC/ABAC、隐私工程、事件响应和公平性评测
- **教师准备：** 准备一个最小正例、一个失败案例和一份可审计输出；区分模型推断、宿主控制、业务规则与外部系统状态。
- **贯穿案例：** AI 安全、权限与人工审批 的作业均要求说明输入、状态、权限、输出、成本和异常处理。

## 第一讲：AI 系统威胁建模与风险分类

### 课前准备

- 复习：STRIDE、数据流图、身份认证、RBAC/ABAC、隐私工程、事件响应和公平性评测
- 预读主题：资产与攻击面、STRIDE 与 AI 特有风险、风险评估、安全目标与边界、MITRE ATLAS 攻击链与 AI Agent 威胁映射、复现练习：为企业知识 Agent 建立 STRIDE 威胁模型。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 资产与攻击面、STRIDE 与 AI 特有风险、风险评估，先定义对象、边界和数据流。
2. **工程深化：** 以 安全目标与边界 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：为企业知识 Agent 建立 STRIDE 威胁模型。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「资产与攻击面」与「STRIDE 与 AI 特有风险」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「风险评估」与「安全目标与边界」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：为企业知识 Agent 建立 STRIDE 威胁模型」和「MITRE ATLAS 攻击链与 AI Agent 威胁映射」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为企业知识 Agent 绘制数据流和信任边界，使用 STRIDE 分类至少八项威胁并排序风险。

**参考解答与推理：** 资产包括身份、租户数据、Prompt、模型上下文、工具凭证、检索索引、审计日志和外部 API。用 STRIDE 分类 spoofing/tampering/repudiation/information disclosure/DoS/elevation，并补充 indirect injection、model extraction、unsafe tool use。按可利用性、影响、暴露面排序并映射控制。

**原始 Rubric 对照（满分 10 分）：**

- **资产边界（3 分）：** 覆盖模型、Prompt、数据、工具和凭证。要求提交物中有直接证据支持该项结论。

- **威胁分析（4 分）：** 分类并解释威胁路径与影响。要求提交物中有直接证据支持该项结论。

- **控制验收（3 分）：** 为高风险项定义可验证控制。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 只列风险不映射控制；只靠 Prompt 防注入；认证和授权混淆；审批不绑定参数；高影响决策没有人工责任/申诉路径。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

### 正式作业参考解答

**原始作业：** 为多租户 RAG Agent 制定数据分级、Prompt Injection 防护、日志脱敏、缓存隔离和删除传播方案。

**参考解答与推理：** 对文档/网页等不可信内容标记来源并隔离指令；模型不得自行提升权限。检索前做 tenant/object ACL，输出前做敏感信息检查；日志只记录必要元数据并脱敏，设保留期；缓存 key 包含 tenant、principal/ACL version。删除传播到原文、chunk、embedding、摘要、缓存。

- **授权隔离（4 分）：** 检索前授权、租户隔离和缓存键策略。要求提交物中有直接证据支持该项结论。

## 第五讲：安全测试、审计与事件响应

### 课前准备

- 复习：STRIDE、数据流图、身份认证、RBAC/ABAC、隐私工程、事件响应和公平性评测
- 预读主题：红队测试范围、安全指标与门槛、事件响应与取证、风险接受与持续治理、Agentic 红队/控制验证/事件响应闭环、复现练习：组织一次 Agent 红队与事件响应演练。
- 准备一个成功路径和一个失败路径，要求学生比较其状态、权限和恢复差异。

### 教学路径与关键讲解

1. **概念建立：** 讲解 红队测试范围、安全指标与门槛、事件响应与取证，先定义对象、边界和数据流。
2. **工程深化：** 以 风险接受与持续治理 为切入点讨论异常、权限、成本或可维护性，并指出由哪个可信组件执行控制。
3. **实践复现：** 复现练习：组织一次 Agent 红队与事件响应演练。先独立推导，再对照参考解答检查假设与边界。
4. **证据要求：** 提交物包含输入/假设、处理步骤、结果、失败路径、版本和未验证项。

### 学习检查点（含教师提示）

- **核心机制：** 围绕「红队测试范围」与「安全指标与门槛」，能否解释本讲的关键机制并写出必要公式、状态或数据流？要求说明变量/参与方及适用假设。
- **工程权衡：** 针对「事件响应与取证」与「风险接受与持续治理」，能否比较不同实现的质量、成本、延迟或安全取舍，并说明何时不应采用？
- **验证与失效：** 围绕「复现练习：组织一次 Agent 红队与事件响应演练」和「Agentic 红队、控制验证与事件响应闭环」，能否设计一个边界/故障/对抗测试，明确预期结果、证据和通过标准？
### 课后复习

- 不看讲义重画本讲数据流/状态图，并逐项标记可信边界。
- 为一个失败案例写出根因、检测信号、恢复动作和防复发测试。
- 将结论转化为一条可自动检查的验收条件。

### 正式作业参考解答

**原始作业：** 为可执行外部写操作的 Agent 建立安全发布门槛和事件响应手册，包含红队案例、指标、证据保全和风险接受流程。

**参考解答与推理：** 发布门槛含 prompt injection 成功率、越权动作率、敏感泄露率、工具滥用率和恢复时间；越权/泄露硬门槛为零容忍。响应：检测→隔离/撤销凭证→保全日志与 hash→评估影响→通知责任人→修复与回归→复盘。风险接受须有 owner、期限、补偿控制和审批。

**原始 Rubric 对照（满分 10 分）：**

- **红队覆盖（3 分）：** 攻击场景覆盖注入、越权、泄露和滥用。要求提交物中有直接证据支持该项结论。

- **门槛指标（3 分）：** 定义可量化安全指标和发布阈值。要求提交物中有直接证据支持该项结论。

- **事件闭环（4 分）：** 包含遏制、取证、恢复和责任审批。要求提交物中有直接证据支持该项结论。

**常见错误与纠正：**

- 只列风险不映射控制；只靠 Prompt 防注入；认证和授权混淆；审批不绑定参数；高影响决策没有人工责任/申诉路径。
- 只写术语、不展示推导或数据来源；要求补充中间步骤和可复核依据。
- 把设计、模拟和真实执行混为一谈；要求显式标注验证等级。

## 评分与教学一致性要求

- 评分项和分值逐条取自课程模块正式 Rubric；不改变原题、分值或课程内评分标准。
- 数学题写明单位、假设和舍入规则；架构题展示替代方案与故障边界；安全题将控制映射到执行组件和测试证据。
- 外部服务使用 mock/sandbox 时明确标注范围，不得将模拟通过描述为真实 provider 或生产验收。
- 允许其他等价方案，只要满足原始 Rubric 且证据充分。
