# M01–M20 跨模块知识体系审计

> 审计范围：当前工作区 M01–M20 课程源文件、目录目标、教师指南、实验工作簿、示例代码与现有来源审计。此报告是课程体系与教材内容审计，不宣称外部同行评审或生产环境认证。

## 1. 总体判断

当前 20 个模块形成从 AI/ML 基础、Transformer 与输入表示、训练/推理、应用组件、Agent 协议与治理、评测平台到产品交付的连贯主线。课程不是 20 个互不相关的技术专题：课程目录声明模块先修关系，M20 对 M01–M19 全量映射。

体系的主要风险不是缺少更多热门框架，而是：
1. 基础模块 M01–M03 缺少与 M04–M20 同等级的独立实验工作簿和可提交实验步骤；
2. 个别先修关系未表达真实内容依赖（M04 使用 token-level loss mask 却只声明 M02）；
3. 安全、评测、成本等横切能力在多模块出现，必须区分首次系统讲授与领域内强化；
4. 课程作业多为设计评审和知识检查，部分关键工程能力还需要可执行负向测试、故障注入、指标计算和证据复现；
5. Capstone Gate 有交付物清单，但必须明确真实集成的最低证据和硬性安全门槛，不能让文档替代工程证明。

## 3. 关键知识衔接审计

### P1 — 先修关系修正
- **M04 ← M03**：M04 的训练样本、Token ID 和 token-level loss mask 依赖 M03 的离散化与消息序列化概念。课程目录已将 M03 加入 M04 prerequisites。
- M05/M06 已显式依赖 M03；M08 依赖 M03/M07；M09 依赖 M03/M05，因此不需再向这些模块重复添加 M02 直接边（M05 已传递 M02）。
- M12/M13 的先修链区分工具调用、Runtime、协议与能力包；不得把 MCP 作为所有工具调用的同义词，也不得把 Skill package conformance 视为执行权限。

### P2 — 领域边界和重复控制
- **Transformer**：M02 负责完整机制；M04 的模型家族、M05 的 KV/推理、M09 的 ViT 只引用所需概念。
- **Token/Context**：M03 负责 tokenizer/embedding/context budget；M04 讨论训练 target mask，M05 讨论 KV 与请求上下文，M06 讨论 Prompt token 预算，M10 讨论 Agent 上下文装配。
- **工具与协议**：M06 负责输出契约；M07 负责 provider tool call 和 host runtime；M12 负责 MCP 协议；M13 负责 Skill 格式与组合；M15 负责授权和安全控制。
- **Planning 与 Workflow**：M10/M11 负责 Agent 动态计划；M16 负责确定性业务流程、持久化状态和补偿。不能把 Agent 计划当作业务事务控制。
- **Security**：M06/M07/M10/M12/M13/M16/M18 讲领域内威胁和控制；M15 汇总系统威胁模型、控制映射、红队和事件响应。
- **Evaluation**：各组件课定义组件级指标；M17 统一数据集、统计、Judge 校准、观测和线上质量门禁。
- **Cost**：M05 是模型推理成本，M14 是协作协调税，M18 是平台计量和资源分配，M19 是产品单位经济。相同术语不代表相同分母。

## 5. 教学事实和版本治理

- MCP 协议行为引用对应发布日期的官方规范，明确 legacy 与当前版本差异；不能把某个 SDK 的实现行为提升为协议保证。
- Agent Skills 文件格式规范、Host/Runtime 能力和任务效果是三个独立评价对象；Skill 文件本身不授予权限。
- OpenTelemetry GenAI Semantic Conventions 的 maturity 必须在课程发布日期重新核对；Development 状态不得表述为稳定承诺。
- NIST AI RMF 是自愿风险管理框架，不是法规或认证；NIST SP 800 系列出版物与 OWASP/MITRE 指南也要分别标注其规范/指南性质。
- 论文结果是特定模型、数据、任务和实验环境下的研究证据，不是生产性能保证。
- 厂商产品文档描述产品接口和限制，不自动成为开放协议规范。

## 6. 不应新增的内容

本轮没有证据支持再增加一门数学课程、另开框架教程、加入更多 Agent 框架比较或把更多热门协议堆进课程。数学深度应以 M01–M05 的公式解释、变量/单位和可复算任务为边界；超出范围时明确标注先修阅读。技术覆盖的价值取决于工程判断与可验证产出，而不是名词数量。

## 7. 结论

课程体系具备完整主干，整改重点为基础实验资源一致性、先修边、Capstone 证据门槛和跨模块横切能力去重。完成上述整改后，课程在教学设计层面可描述为完整的 AI Engineering 培养路径；仍不能声称经过外部同行评审、真实生产部署认证或所有第三方来源永久有效。
