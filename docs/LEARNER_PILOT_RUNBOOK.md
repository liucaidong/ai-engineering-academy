# M01–M20 学习者试测执行手册

> 状态：执行准备就绪；尚未招募参与者，未开展真实学习者试测。
> 适用：首轮形成性试测（6–8 人），用于发现阻塞和课程说明问题，不用于统计推断或资格认证。

## 1. 试测目标

收集真实学习者独立使用课程时的行为证据，验证：
- 入门诊断是否能识别真实先修缺口；
- 学习者是否理解模块先修和任务要求；
- 课程讲解、实验和作业能否在声明环境下完成；
- 作业 Rubric 是否对应可观察的学习产出；
- 讲次、作业、调试和 Capstone 的真实耗时；
- 课程是否把模拟、mock、本地真实服务和生产验证边界说明清楚。

本轮不是完整 24 周课程认证。静态审查、内部软件验收和参与者试测必须分开报告。

## 2. 招募与样本分层

招募文案、筛选问题、分层规则、数据最小化和招募完成定义见 [`LEARNER_PILOT_RECRUITMENT_KIT.md`](./LEARNER_PILOT_RECRUITMENT_KIT.md)。

首轮目标 6–8 人，建议优先 8 人：
- A 组（2 人）：基本计算机使用能力，无系统 AI/ML 工程经验；
- B 组（3 人）：有软件/API/数据库/测试经验，LLM/Agent 实战有限；
- C 组（3 人）：做过 LLM 应用、RAG 或 Agent 项目，缺少系统生产工程经验。

招募时只记录匿名参与者 ID、经验分层、相关经历区间和可用时间。不要收集身份证、雇主机密、客户数据、API Key、真实账号或无关个人信息。

参与者自愿参加，可随时退出。不得把首轮结果用于招聘、升学、绩效或资格认证。

## 3. 试测前准备

负责人逐项完成：
- [ ] 固定试测版本：记录 Git commit、课程版本、浏览器和操作系统。
- [ ] 阅读《学习者质量验证协议》《入门诊断题》《先修能力地图》。
- [ ] 将参与者匿名 ID 写入参与者登记表和时间日志，不写真实姓名；登记表模板见 [`LEARNER_PILOT_PARTICIPANT_REGISTER_TEMPLATE.csv`](./LEARNER_PILOT_PARTICIPANT_REGISTER_TEMPLATE.csv)。
- [ ] 取得知情同意；明确记录范围、用途、保留期限和退出方式。
- [ ] 准备干净浏览器配置，确认无教师答案或预先完成的作业内容。
- [ ] 记录参与者是否使用自己的设备、是否有 GPU/API Key/付费服务；不得要求参与者购买服务。
- [ ] 准备观察员记录表、屏幕/录音记录许可（默认不录制；需单独同意）。
- [ ] 预先冻结任务、提示语和求助规则，避免不同参与者接受不同程度的指导。

## 4. 任务分配策略

### 核心任务（所有参与者）

1. 阅读学习者手册并独立完成入门诊断。
2. 完成 M01、M02、M03 的学习任务；至少完整记录每个模块的一个代表性讲次和正式作业。若无法完成整个模块，明确标注实际覆盖，不得将抽样结果描述为完整模块通过。
3. 在开始 M04–M20 抽样任务前，使用《先修能力地图》自查；记录是否知道应该复习什么。
4. 选取一项课程 Lab 或作业，明确标记执行模式和证据等级。
5. 完成任务后填写时间日志和摩擦记录。

### M04–M19 分层抽样

第一轮按能力层级覆盖不同模块，不要求每位参与者完成全部模块。建议任务组合如下；实际分配按参与者经验和可用时间调整：

| 经验组 | 抽样模块 | 重点观察 |
|---|---|---|
| A | M04/M05 或 M06/M07 | 数学先修、模型训练/推理术语、结构化输出说明 |
| B | M08/M09 或 M10/M12 | RAG、多模态、Agent/MCP 任务契约和实验边界 |
| C | M13/M14 或 M15/M16 | Skill 包、安全、Multi-Agent、Workflow 工程交付 |
| B/C | M17/M18/M19 | 评测统计、平台成本/隔离、产品工程交付 |

第一轮结束后根据缺口安排补测，确保 M04–M19 的每个模块至少有一次学习者观察；覆盖不足的模块必须标记为未测，不得用相邻模块结果代替。

### Capstone

至少两位 B/C 组参与者完成 M20 Gate 0–4 演练。记录项目章程、ADR、垂直切片、正常/失败/安全拒绝轨迹、评测、安全、SLO、成本、回滚和答辩准备。若参与者无法在试测周期内完成真实项目，使用受限演练并明确标注，不得伪装成完整项目交付。

具体到 Lesson ID / Assessment ID 的 8 人任务分配、M01–M03 共同任务和 M20 Gate 0–4 覆盖表，见 [`LEARNER_PILOT_TASK_MATRIX.md`](./LEARNER_PILOT_TASK_MATRIX.md)。该矩阵中的 P01–P08 是排程占位符，不代表已招募或已参与的真实学习者。

## 5. 观察员标准操作

- 先给出课程已有材料和任务，不先讲解答案。
- 参与者连续停滞时，先记录停滞时间和行为，再按统一求助规则提供最小提示。
- 每次提示记录提示原文、发生时间、原因、提示等级和是否恢复。
- 区分学习困难、说明不清、先修缺失、环境阻塞、外部服务不可用和个人时间不足。
- 不因参与者失败立即判断课程失败；先检查任务、环境和参与者经验层级。
- 不代替参与者操作，不修改任务输入，不补充课程未声明的依赖。
- 观察员不得在参与者提交前展示教师参考答案。

## 6. 必须采集的数据

每个任务记录：
- participant_id、experience_group、module_id、lesson_id、assessment_id；
- started_at、ended_at、active_minutes、blocked_minutes；
- help_requests、hint_level、environment、execution_mode；
- evidence_level、completed、result；
- friction_code、friction_description、artifact_ref、observer_notes。

摩擦代码建议：
- PREREQ：先修知识缺失；
- INSTRUCTION：说明或步骤不清；
- INPUT：输入、样例或参数不足；
- ENV：环境、安装、权限或凭证阻塞；
- FORMAT：交付格式不明确；
- RUBRIC：评分标准无法操作；
- EVIDENCE：证据或复现要求不明确；
- TIME：工作量超出预期；
- CONTENT：概念错误、过时或前后矛盾；
- ACCESS：导航、可访问性或界面障碍。

## 7. 判定与升级

每个任务按以下维度记录 PASS / PARTIAL / FAIL：
1. 无教师口头补充能否开始；
2. 先修能力是否足够或能否通过课程桥接补足；
3. 输入和执行环境是否可获得；
4. 交付物是否明确；
5. Rubric 是否能映射到实际产出；
6. 任务是否在声明的执行模式下可复现；
7. 是否能区分模拟与真实环境证据。

问题升级：
- P0：造成危险学习、安全错误、隐私泄露或证据造假；
- P1：阻断核心任务或导致关键学习目标无法达成；
- P2：明显摩擦、评分歧义、重复或较大时间偏差；
- P3：低影响措辞、排版和导航问题。

所有 FAIL 必须绑定具体模块/讲次/assessment ID、参与者证据、影响、修复责任和复测结果。

## 8. 结束报告模板

报告必须包含：
- 参与者人数、经验分层、退出人数和样本覆盖；
- 完成任务清单、未测模块和未完成原因；
- 诊断各领域表现及桥接前后差异；
- 各任务 active time / blocked time 的 P50、P75、P90；
- 求助次数、提示等级和阻塞原因；
- PASS / PARTIAL / FAIL 分布及 P0/P1/P2/P3 清单；
- Rubric 评分者一致性观察（若有双评）；
- Capstone Gate 结果和证据等级；
- 修复项、复测结果和仍未验证事项；
- 样本量、经验偏差和不可外推的限制。

## 9. 停止条件与当前阻塞

当至少 6 人完成核心任务、M04–M19 抽样覆盖有记录、至少两位 B/C 参与者完成 Capstone 演练，且所有 P0/P1 均有处置结论后，首轮形成性试测才可结束。

**当前真实阻塞**：需要由项目负责人招募 6–8 位符合画像的自愿参与者，并安排观察时段。AI 助手可以整理记录、分析结果和提出整改，但不能代替真实学习者完成课程，也不能伪造参与者行为数据。
